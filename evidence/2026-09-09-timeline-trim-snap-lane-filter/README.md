# evidence: timeline-trim-snap-lane-filter

同じ動画を 2 レーンに重ねた状態で右端トリムすると「⚠ 重なるためトリムできません」が
**離すピクセルによって出たり出なかったりする**（実機報告 2026-09-09）件の L1 実測記録。

## 根因（main 系統・`akari-annotations-widget.ts`）

- cut-trim の吸着候補 `outputSnapCandidates` は**レーンで絞り込まない**。同レーンの隣接境界と、
  別レーンにある同尺クリップの端が数 px 差で並ぶと、`resolveSnapTime` の「閾値内の最寄り 1 件」で
  勝者が中点で入れ替わる
- 吸着後の値がそのまま `cutWouldOverlap`（**同レーンのみ**・許容 1e-4 秒）へ渡るため、
  別レーン端へ吸着して同レーン境界を 1 フレーム越えただけで拒否になる
- 確定は pointerup 座標で preview を組み直すので、**離した位置の 1px 差が合否を決めていた**

## 直し

`resolveSnapTime` に任意の重なり判定（`wouldOverlap`）を渡せるようにし、cut-trim だけがそれを渡す。
吸着先が同レーンで重なるときは (1) 吸着前の生の値が合法ならそれを採り、(2) 生の値も重なるなら
閾値内の**合法な候補**へ吸着する。どちらも無ければ従来どおり拒否する（= 本当の重なりは拒否のまま）。
移動（cut-move / layer）と字幕の吸着経路は引数を渡さないので挙動不変。

## 検証環境

- production ビルドの Electron を隔離 `--user-data-dir` / `THEIA_CONFIG_DIR` / `AKARI_HOME` +
  `--remote-debugging-port` で起動し、生 CDP（`scripts/cdp-lib.mjs`）で実マウスイベントを投げる
- ワークスペースは一時ディレクトリに `fixture/edit.json` を複製して生成（実素材は ffmpeg lavfi で
  30 秒の mp4 を都度生成し、検証後に破棄。バイナリはコミットしない）
- 帯の分解能を上げるため `Emulation.setDeviceMetricsOverride` で 1920x1200 にしてから計測

再現コマンド:

```sh
node evidence/2026-09-09-timeline-trim-snap-lane-filter/scripts/run-l1.mjs --port 9536 --releases 20
```

## fixture の幾何（fps 30・`at` / `duration` はフレーム）

| レーン | クリップ | 出力秒 |
|---|---|---|
| V1 | a / b / c / d | 0–2 / 3–6 / 8–11 / 11.0333–14.0333 |
| V2 | e / f / g / h | 0.0333–3.0333 / 3.0333–6.0333 / 8–10 / 11–14 |

- V1 の測定対象 = `a` の右端。同レーン境界は `b` の頭 **3.000**、競合する別レーン端は
  `e.end` / `f.start` = **3.0333**（+1 フレーム）
- V2 の測定対象 = `g` の右端。同レーン境界は `h` の頭 **11.000**、競合する別レーン端は
  `d.start` = **11.0333**（+1 フレーム）
- 実測 35.04 px/秒 → 1 フレーム = 1.17px。吸着閾値 6px の内側で 2 候補が競合する
  （= オーナーの言う「気まぐれ」が起きる幾何そのもの）
