# contract — 断片書体の部分化と字形検査 v0

- 決定日: 2026-10-02
- 対象: HTML 断片の `@font-face`
- 状態: 段 1 の字形検査を実装。段 2 の書き出し時の自動部分化と段 3 のキャッシュ掃除は予定

## 1. 目的と順序

断片の文言を直すたびに手で部分フォントを作り直す負担と、追加した字だけが別書体に切り替わる見落としを減らす。段 1 は `edit-lint` の字形検査、段 2 は書き出し時の自動部分化、段 3 は不要になったキャッシュの掃除とする。プレビューは原本の書体をそのまま読む。3D テキストと字幕の書体は対象外。

## 2. 使う字の集合

lint は断片から**描画される字**を集める。テキストノード（コメント・`<style>`・通常の `<script>` を除く）、文字参照を解いた字、CSS `content:` の文字列と CSS エスケープを解いた字、`content: attr(x)` の属性値、`params` / `vars` の文字列値、`type="application/json"` の宣言内の文字列値、`data-akari-font-chars`、`text-transform` の変換後の字を含む。数値文字参照と HTML 4.01 の名前付き文字参照 252 個を解く。`text-transform` は `uppercase`・`lowercase`・`capitalize`・`full-width` の対応する字を足し、`none` では足さない。空白・制御文字・既定で描画されない字は数えない。通常の `alt`・`title` などの属性値や、CSS のカスタムプロパティに置いた文字列は描画集合に直接は入れない。

段 2 の部分化は**ソース全体の字**を使う予定である。書体の `data:` URI の中身を除くソース、文字参照と CSS エスケープを解いた字、`params` / `vars`、`data-akari-font-chars` に、ASCII 印字可能文字・和文約物・省略記号などの安全余白を足す。**部分化用の広い集合 ⊇ lint 用の狭い集合**を保つ。

実行時の script が字を生成する断片は、ルート要素に `data-akari-font-chars="追加され得る字"` を置く。この値は lint の描画集合にも入る。宣言のない通常の `<script>` について lint は静的収集が不完全であることを info で知らせ、段 2 では書体を絞らない予定である。

```html
<div data-akari-font-chars="晴雨雪">
  <style>@font-face { font-family: MyFont; src: url("../assets/font/my-font.ttf"); }</style>
  <span>今日の天気</span>
</div>
```

## 3. 字形検査

`overlays.fragment-font-glyphs` は `@font-face` を持つファイル参照の断片を対象とする。プロジェクト内の断片と共有ライブラリ参照の断片を同じように扱い、相対パスと `data:` URI の書体を読む。断片が読む書体の cmap の**和集合**に描画集合の字が無ければ、欠けた字の先頭 20 字と件数、コードポイント、断片と書体のパスを含む warning を 1 件出す。通常の `<script>` があり宣言のない断片には静的に集めきれない旨の info を出す。書体を読めない場合やプロジェクト外への参照には info を出し、その断片で 1 本でも書体を読めなければ欠けた字の warning は出さない。`@font-face` のない断片は対象外。

読める書体の器は TTF / OTF / TTC（先頭の書体）/ WOFF / WOFF2 で、Unicode cmap の format 4 / 12 を読み、異体字セレクタ用の format 14 は見ない。Unicode cmap がない書体（記号用の符号化だけの書体など）、壊れた書体、WOFF2 コレクションは読めない旨を info で知らせる。`@font-face` の `src` が `local()` や `https:` だけの場合も、読める参照が無いため info になる。

和集合の検査は、ある要素に指定された書体に字が無くても、別の参照書体にその字があれば見逃す。体験版など字数を制限した書体で起こり得る。CSS の `font-family`、変数、代替書体を静的に確定しないため、warning は表示上の欠けを断定せず、書き出しを止めない。

## 4. 自動部分化とキャッシュ（予定）

段 2 では書き出し時に断片と書体ごとに部分化し、プレビューでは原本を読む。部分化器は版を固定した hb-subset の WASM を同梱する予定である。TTF / OTF は元と同じ sfnt 形式で、レイアウト機能、ヒンティング、可変軸、`.notdef` を保持する。通常の `<script>` があり `data-akari-font-chars` のない断片、WOFF2 の書体、部分化に失敗した書体は絞らず、理由を報告する。既存の手作業の部分フォントはそのまま利用できる。`AKARI_FONT_SUBSET=off` で部分化を外せるようにする。16MiB の埋め込み上限は部分化**後**の大きさに適用する。

一時ファイルはプロジェクトの `.akari/cache/font-subset/` に置く。鍵は書体内容の SHA-256、使う字、部分化器の版と設定から作る。段 3 では書き出し後に今回使わなかった期限切れの鍵だけを掃除する。`akari clean` の既存の `.akari/cache/**` 規則を使い、`assets/` の原本は削除しない。未参照の原本書体の一覧化は別途検討する。

出力プレビューで同じ書体が断片ごとに別 URL になる可能性は、実測してから別途扱う。この契約ではプレビューの配信方法を変えない。

## 5. 利用許諾

書き出し時の一時的な部分化は、書体の種類を問わずプロジェクト内のキャッシュだけに置き、部分フォントを頒布しない運用として扱う。字形自体は変更しない。利用者が部分化を外す手段を設ける。
