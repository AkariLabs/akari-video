# vocabulary-v0（画面の語の正本 — 素材・テンプレート・作例・作り方）契約

  `contract-2026-10-16-recipes-and-connectors-v0.md`（道具の手順と接続）/ `contract-2026-09-13-extension-kit-v0.md`（配布の箱）/

- 発端: 「まとまり」を指す語が画面で絡まっていた（テンプレートに 4 つの意味・作り方に 3 つ・レシピに 3 つ・同じ物に 3 つの名前）。
  参考にした他製品は「テンプレートかどうか」で分けず、**選んだあとに何ができるか**と**始め方**で分けている。それに合わせて画面の語を決め直す

## 0. 原則

1. **名前は「選んだあとに何ができるか」で決める。** 大きさ・尺・文書の詳しさから種類を推定しない（10 秒の音にも尺はある。1 本まるごと差し替えるだけの物はテンプレート）
2. **画面の語と内部語を切り離す。** 内部語（`kind`・ファイル名・CLI・スキル名）は安定させ、画面の語は本契約で決める。画面の語を変えても id・キー・URL は変えない
3. **1 つの語に 2 つの約束を背負わせない。** 同じ語で別の物を呼ばない。同じ物を 2 つの語で呼ばない
4. **省略形を画面に出さない**（「テンプレ」「プレイブック」のカタカナ単独は使わない）
5. 日本語の画面は日本語の語だけ。英語の併記は、英語の画面と CLI の usage に任せる

## 1. 語

| 画面の語 | 英語 | 選んだあとに何ができるか | 例 | 内部 id | 置き場 |
|---|---|---|---|---|---|
| **素材** | Asset | **足す**（タイムラインに置く / 何かに当てる）。ツマミで変えられる | 映像・画像・音・3D・動く部品（旧オーバーレイ）・フォント・自分で撮った映像 | `asset`（category は現状の語彙） | `~/.akari/assets/<category>/<id>`・`<project>/assets/` |
| **スタイル** | Style | **当てる**。素材のうち時間を持たず、文字 / カット / 画面に当てて効く | 文字の見た目・字幕の見た目・LUT・つなぎ・動き | `style`（`presets/*` は同梱の表） | `<library>/styles/<id>/`・`presets/` |
| **テンプレート** | Template | **枠を埋めて使う**。尺・文字・枠・音が決まったまとまり 1 つ。空き枠に素材を落とすと入れ替わる | 「手元の寄り 15 秒」「商品カット 3 連」 | `template`（当面は playbook の depth 3。§9） | `~/.akari/playbooks/<id>/template/` → 次の版で `~/.akari/templates/<id>/` |
| **作例** | Showcase | **見て、参考にして作る**。完成した 1 本。誰が作ったかを問わない。元データが付き素材がそろえば**編集データを開く**こともできる | 「朝の Vlog 60 秒」「商品紹介 30 秒」 | `showcase` | `~/.akari/showcases/<id>/`・`channels/<ch>/showcases/<id>/`・キット `showcases/<id>/` |
| **作り方** | Playbook | **読む**。1 本ぶんの手順・確認点・設定・仮枠。作例に付くことが多いが単独でもよい。全部書かれていなくてよい | `planning/playbook.md` | `playbook` | playbook-v0 のまま |

補助の語（単独の種類ではない）:

| 語 | 意味 |
|---|---|
| 空き枠 | テンプレートや作り方の中で、使う人が埋める枠。映像なら「映像を入れる枠」、文字なら「入力する項目」と中身で言う。内部 `placeholder` |
| 印 | ★ お気に入り / 無料・Pro / 出どころ（同梱・Lab・自分の）/ 尺・空き枠の数 / **開けるか**（説明だけ・元データ付き・素材もそろう）。種類ではなく、どの種類にも付く |
| チャンネルの設定 | 旧ブランドキット（色・ロゴ・定番の文字スタイル・定番の音）。チャンネルの持ち物として設定の画面に置く。内部 `channel` |
| 型 | 企画書の下書き（旧「テンプレから」）。チャンネルの画面で既に使っている語 |
| 3D の設定 | 旧「3D レシピ」。素材を 3D で作り直すときの設定 |
| 同じ設定で作り直す | 旧「この作り方で作り直す」（AI で作った素材の生成設定の再利用）。作り方とは別物 |

画面に出さない語（内部語として残す）: 雛形 / ひな形 / 器（`scaffold`）・レシピ（`tool-recipe` = 道具の手順。AI 向け。`recipes` = 好みの記憶は読み取り互換のみ）・
拡張キット（`kit` = 配布の箱。画面では出どころの印）・パック（Lab の売り方だけ）・マイスタイル / プリセット（→ 自分のスタイル）・オーバーレイ（→ 動く部品）。

## 2. 関係

- 多対多で参照する。作例 → 使ったテンプレート / 素材 / スタイル。作例 ⇄ 作り方（1 つの作り方から複数の作例、1 つの作例に字幕 / 構成 / 音の複数の作り方もあり得る）。テンプレート → 素材
- **種類は宣言（`kind`）で決まる。** 尺・文書の詳しさ・空き枠の有無から推定しない
- **同じ物を 2 つの種類として重複表示しない。** 作例にテンプレート版が付いているなら、作例の詳細から「参考にして作る」「テンプレートを使う」を選ぶ
- 置く場所は 2 つ: **ライブラリ = タイムラインへ落とす物**（素材・スタイル・テンプレート。1 つの棚。分類は「何か」、種類と性質は絞り込み）/
  **ホーム「作り始める」= 1 本を始める入口**（作例・作り方・白紙）。**作例は編集中にも開ける**（「この 3 秒の演出を取り入れて」の参照先。場所は §11）
- ライブラリに作り方は並べない（深さ 1・2 の作り方は文書。棚に並ぶのはテンプレートだけ。template-v0 §3 を本契約で改める）

## 3. 作例が持つもの

| 情報 | 内容 |
|---|---|
| 識別 | 安定 id・版（整数）・作者（id）・完成動画の参照とハッシュ・尺・fps・画面比 |
| 区間 | 安定した区間 id・対象の動画の版・開始と終了・見出し・代表フレーム・注目してほしい特徴（「文字が音に合わせて現れる」） |
| 元データ | `edit.json`（とシーン）・関係するクリップ id・生成の設定 / コード・依存する素材とスタイルの参照と版（参照台帳の語彙） |
| 作り方 | `playbook.md` / `playbook.json` への参照（id@版）・該当する節・適用する区間 |
| 利用条件 | 各素材のライセンス・取得できるか（Lab / 同梱 / 外部）・要る道具・足りない物・作者への帰属 |
| 表紙 | 表紙とコマ（playbook-v0 の `preview` と同じ規則） |

**開けるかの印は 3 段**で、依存を解決した結果から決める（推測で付けない）:

| 印 | 条件 | できること |
|---|---|---|
| 説明だけ | 動画（または表紙）+ 作り方のメモ | 見る・参考にして作る |
| 元データ付き | + `edit.json` と参照一覧 | + 区間から部品と手順を辿る |
| 素材もそろう | + 依存する素材・スタイル・フォントが手元にあるか取得できる | + 編集データを開く・ここから始める |

## 4. 区間の指し方

- 完成動画の時間で指す。単位は秒（小数可）と fps を併記。**開始を含み、終了を含まない**
- 区間は 2 種類: **登録済み**（作例が持つ区間 id。作り方の `beats` と同じ粒度）と **任意**（`start-end`。使う人が選んだ範囲）
- 区間は**動画の版**を伴う。動画を差し替えても既存の参照を黙ってずらさない（版が違えば「古い版の区間」と出す）
- 書き出した動画の時刻と `edit.json` のタイムラインが一致しないとき（速度・トリム）は、作例が対応表を持つ
- 区間から辿る依存は、区間に重なる項目だけでなく、**区間の外にある音源・フォント・共通のスタイル**も含める

## 5. 制作の根拠 — 最低条件

- 作例は**動画だけでも登録できる**。作り方は**メモだけでもよい**（工程の一部・箇条書き）。「完全に再現できる」を一律に約束しない
- エージェントに渡すのは次の 4 つを分けた形: 辿れた物 / 足りない物 / **作者の説明と、エージェントの推測の区別** / 依頼者の注目点
- **注目点**（文字の動き・色・テンポ・構図・音 など）は依頼の側に残す。同じ区間でも何を参考にするかで結果が変わる
- 作例を参考に作ったプロジェクトは、出典（作例 id@版・区間・作り方）を `.akari/manifest.json` の `uses` と参照台帳に残す（§7）

## 6. 操作・CLI・スキル

操作は 5 つに分け、画面のボタンもこの語で書く: **足す** / **枠を埋める** / **参考にして作る** / **編集データを開く** / **公開する**（門。automation-gates v0）。

| 何 | 名前 | 状態 |
|---|---|---|
| CLI | `akari showcase list \| inspect <id> [--segment <id> \| --range <s>-<e>] [--json] \| capture <project> --id <id>` | **新設**（inspect = 区間の依存と手順を解決して出す。capture = 完成した 1 本を手元の作例にする） |
| CLI | `akari new --from <id>`（作例 / 作り方 / テンプレートを `kind` で見分ける唯一の入口）。作例は `--from showcase:<id>@<版> [--segment <id>]` | 既存に足す |
| CLI | `akari template export \| list \| place`（template-v0 §6 の `akari playbook template` は別名として残す） | **改名** |
| CLI | `akari new --template <path>`（器を選ぶ）→ `akari new --scaffold <path>`。旧名は 2 マイナー版のあいだ別名 + 1 行の案内 | **改名** |
| CLI | `akari playbook list \| apply`・`akari recipe list \| plan`（AI 向け） | 維持 |
| スキル | `capture-showcase`（完成した 1 本 + 元データ + 区間 + メモを手元の作例に登録する） | **新設** |
| スキル | `create-from-showcase`（作例の区間から根拠を辿り、新規または既存のプロジェクトで作る） | **新設** |
| スキル | `record-playbook`（手順を記録する。完成作品の登録は背負わせない） | 維持 |
| スキル | `harvest-asset --as template`（template-v0） | 既存に足す |

- 登録（capture）と公開（publish）は別の操作。公開の CLI / スキルは Lab へ出す手順が決まってから（非スコープ）
- 旧 id（`example-*`）は変えない。旧フラグ・旧サブコマンドは**読み取りは永続・書き込みは警告つき別名**

## 7. 出典と利用実績

- イベントは 3 種に分ける: **閲覧**（開いた）/ **参照**（区間や依存を辿った）/ **適用**（置いた・枠を埋めた・編集データを開いた・ここから始めた）
- 記録の形: `{ event, kind, id, version, segment?, playbook?, at, by }`。置き場は作業場の記憶（`.akari/memory/` の既存の規律）とプロジェクトの manifest
- **作者への還元の計算に使うのは「適用」だけ。** 参照を辿っただけで課金や還元を重複計上しない
- 作者・ライセンス・tier は各物の `meta.json` / `playbook.json` / `showcase.json` に持つ（asset-tier v1・asset-license-axes v0 の語彙）

## 8. 今の語の行き先

| 今の語（使われ方） | 行き先 |
|---|---|
| テンプレート（今日の深さ 3） | **テンプレート**（この意味だけ） |
| テンプレート（`templates/` の器・kaisetsu-short） | 器は内部語 `scaffold`。kaisetsu-short は作例へ |
| テンプレから（企画書の下書き） | 型 |
| 字幕テンプレ | 字幕スタイル |
| 雛形 / ひな形（タイル・CLI・インスペクタ） | 画面から消す。タイルはテンプレート。「ひな形から始める」（動きのプリセット）→ スタイル |
| 作り方（Playbook） | 作り方のまま。「作り方（Playbook）から」→「作り方から」 |
| 作り方（「この作り方で作り直す」） | 同じ設定で作り直す |
| 作例（サイトの利用者の作品）・`example: true` の「例」 | **作例**に統一。`example: true` は中身を見て `starter`（始める用の見本）か作例かに振り分ける（一括変換しない） |
| マイスタイル / 保存したプリセット / `mystyle` | 自分のスタイル（出どころの印） |
| オーバーレイ | 素材（動く部品） |
| レシピ（道具 / 好み / 3D） | 画面に出さない。好みは「好みの記憶」。3D は「3D の設定」 |
| ブランドキット | チャンネルの設定 |
| 拡張キット | 画面では出どころの印（内部語 `kit`） |
| パック（Lab の束 / 記憶パック） | Lab の売り方だけ。記憶パックは別の語へ（チャンネルの契約で決める） |
| 素材（部品 / 自分で撮った映像） | どちらも素材。出どころの印（自分の / Lab / 同梱）と場所（ライブラリ / プロジェクト）で分ける |

## 9. データと置き場

- **作例**: `showcase.json`（`version: 0`・`kind: "akari-showcase"`・`id`・`showcaseVersion`・`title`・`author`・`video`・`segments[]`・`sources`（edit.json と参照）・`playbook`（id@版）・`parts[]`・`license`・`provenance`・`preview`）。
  形は別票の `contract-…-showcase-v0.md` で切る（本契約は語と関係まで）。置き場は §1
- **テンプレート**: 今は template-v0 のとおり `akari-playbook` の depth 3 で実装中。**次の版で `kind: akari-template`・`~/.akari/templates/<id>/template.json` に分ける**（読み手は depth 3 の playbook を「作り方 + 内包するテンプレート」として読み続ける）。depth 3 では `steps` を省略可にする
- **作り方**: playbook-v0 のまま。`example: true` は §8 のとおり中身を見て移行
- **器**: `templates/project-default` は内部語 `scaffold`
- **Lab**: カタログの `genre` は残し、`kind`（asset / style / template / showcase / playbook）の列を足す。URL・id は変えない。英語の表示は Playbooks → そのまま、作り方の例 → Showcases（作例）

## 10. 移行の段取り

1. **用語の正本 = 本契約**。代表 20 件（アプリと Lab）を §1 の 5 語に振り分けた表を `docs/` に添える（紙上の試行）
2. **画面の文言だけ**（i18n のキーとデータは変えない）: §8 の行き先のうち、データを伴わないもの
3. **ライブラリ**: 漏斗に「種類（素材 / スタイル / テンプレート）・尺あり・空き枠あり」、テンプレートの印。作り方の棚は作らない
4. **ホーム**: 作り始める = 作例 + 作り方 + 白紙。作例の詳細に区間・開けるかの印・作り方
5. **データとコマンド**: showcase-v0 契約 → `akari showcase`・2 つのスキル → `akari-template` の分離 → `--scaffold` → Lab の `kind` の列

規律: id・キー・URL は変えない / 旧名は別名の表（`docs/` に 1 枚）に載せ、読み取りは永続 / CLI の旧フラグは警告だけ / Lab の分類は足すだけ / 画面の語の変更を理由に物を移動しない。

5. 記憶パックの新しい語
