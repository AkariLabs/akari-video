# Shared video tracks

`timeline.tracks[]` accepts `kind: "video"` with a required non-negative `ref`. One video row owns both `cuts[]` and `layers[]` whose `track` equals that reference. Existing `cuts`, `layers`, `overlays`, `captions`, and `audio` declarations remain supported. Track declaration order remains bottom to top.

Moving a clip across legacy cut/layer rows normalizes visual media rows to distinct video references while preserving row IDs and labels. Native items remain in their original arrays: source references, trim, speed, visual effects, audio semantics, and unknown item properties are retained. Implicit cut start times are resolved before remapping references. Empty source rows are removed in the same transaction; they are not displayed as destinations. Rows exist only while they contain material. Row heights are preserved when the storage kind changes. The guarded write is atomic and a full before/after snapshot provides undo/redo.

A video track is one horizontal band. Multiple cuts/layers can occupy it at non-overlapping times; touching endpoints are allowed. Dropping inside a row places the clip at the next free interval without moving its existing clips, matching the legacy Akari OS timeline. Dropping on a boundary inserts the moved clip there: a row containing only that clip is reused and reordered, while moving one of several clips creates a new occupied row. The source row is removed if it becomes empty. There is no pairwise clip swap and no empty-track creation menu. The ghost and commit share the same placement plan; boundary drops show an insertion line, not a fictitious empty row. Locks and media-domain boundaries remain enforced.

Shared-row overlaps are rejected by edit-lint, including direct snapshot writes. Source in/out ranges may be reused or appear out of source order: occupancy and duration are measured on the output timeline, including gaps and visual layer ends. Legacy sequential v0 source-order checks remain unchanged.

The initial time window is fitted once and then remains fixed across drag/drop, insertions, pruning, undo and redo. Content changes update the scrollable extent, not seconds-per-screen or the zoom percentage. A stable scrollbar gutter prevents row removal from changing the plotting width. Zoom is changed by explicit zoom gestures; double-clicking the zoom percentage explicitly fits the current content.

Preview and export expand each video row into its native cut and layer streams in the declared order. The preview places the main video and layer videos in one scaled output-coordinate stacking context, so their z-indices can actually cross; cut transforms are applied in output coordinates before the shared display scale. Within a valid row, native cut and layer intervals do not overlap. Active shared rows select the gap-aware export path, including multi-source video and delayed source audio. This prevents a moved multi-source clip from being concatenated at the wrong time. Empty shared rows alone do not alter export routing.

Current limitations: cross-domain conversion of rows containing freeze holds or `transition_out` is rejected without writing. Their nonlinear timing is not supported by the shared row export path. Existing legacy workflows remain available. Caption `display_policy` retains its existing guard against declared cut winner-order overrides.

Header reordering listens on the document, defers timeline reconstruction during the gesture, and writes stable row IDs. Escape and pointer cancellation never commit; pending media redraws resume after cancellation. Only the audio group remains pinned at the bottom.
