# Shared video tracks

`timeline.tracks[]` accepts `kind: "video"` with a required non-negative `ref`. One video row owns both `cuts[]` and `layers[]` whose `track` equals that reference. Existing `cuts`, `layers`, `overlays`, `captions`, and `audio` declarations remain supported. Track declaration order remains bottom to top.

Moving a clip across legacy cut/layer rows normalizes visual media rows to distinct video references while preserving row IDs and labels. Native items remain in their original arrays: source references, trim, speed, visual effects, audio semantics, and unknown item properties are retained. Implicit cut start times are resolved before remapping references. Empty source rows remain available as destinations. Row heights are preserved when the storage kind changes. The guarded write is atomic and a full before/after snapshot provides undo/redo.

A video track is one horizontal band. Multiple cuts/layers can occupy it at non-overlapping times; touching endpoints are allowed. The renderer does not create subrows or grow the row when clips move. A drop over exactly one clip swaps their row assignments if both receiving intervals are free after the swap. Across rows the displaced clip keeps its start time; within one row it takes the dragged clip's former start. Drops involving multiple collisions, or a swap that would collide with a third clip, are rejected. The ghost and commit use the same placement plan, and an additional ghost marks the displaced clip's destination. Shared-row overlaps are rejected by edit-lint, including direct snapshot writes. Source in/out ranges may be reused or appear out of source order: occupancy and duration are measured on the output timeline, including gaps and visual layer ends. Legacy sequential v0 source-order checks remain unchanged. Locked rows reject movement; audio and HTML overlay rows remain separate media domains. A video imported from the material bin into a shared video row becomes a cut, retaining its source audio; still images use layers. New material has no originating row to swap into, so it is placed in the next free interval using the same half-open collision rule as the legacy AKARI timeline.

Preview and export expand each video row into its native cut and layer streams in the declared order. The preview places the main video and layer videos in one scaled output-coordinate stacking context, so their z-indices can actually cross; cut transforms are applied in output coordinates before the shared display scale. Within a valid row, native cut and layer intervals do not overlap. Active shared rows select the gap-aware export path, including multi-source video and delayed source audio. This prevents a moved multi-source clip from being concatenated at the wrong time. Empty shared rows alone do not alter export routing.

Current limitations: cross-domain conversion of rows containing freeze holds or `transition_out` is rejected without writing. Their nonlinear timing is not supported by the shared row export path. Existing legacy workflows remain available. Caption `display_policy` retains its existing guard against declared cut winner-order overrides.

Header reordering listens on the document, defers timeline reconstruction during the gesture, and writes stable row IDs. Escape and pointer cancellation never commit; pending media redraws resume after cancellation. Only the audio group remains pinned at the bottom.
