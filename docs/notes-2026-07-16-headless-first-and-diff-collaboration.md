# ヘッドレス CLI 完結と差分協調の方向性メモ

- 日付: 2026-07-16
- 状態: 方向性メモ（オーナーとの設計会話の記録。契約への昇格は各項の実装着手時）
- 経緯: セーブデータ（edit.json）を中心に据えた協調モデルの再確認と、そこから導かれる
  3 つの新規決定 —「アプリ不要の完結経路を不変条件化」「人間の変更はリアルタイム監視
  ではなく状態差分で AI に伝える」「リモート・ヘッドレスパイプライン構想」— を記録する

## 0. 前提の再確認 — セーブデータが中心

- 全ての経路（AKARI Video アプリ / Claude Code CLI / VS Code 直接編集 / 自然言語指示）は
  **同一のセーブデータ（edit.json + サイドカー群）に合流する**。合流点はツール API ではなく
  データ（notes-2026-07-16-qa-lint §0 の不採用記録と同一結論）
- セーブデータを作り上げる主体は AI。人間は基本的に作らず、
  (a) 絶妙なニュアンスの微調整（文字位置の調整等）と (b) QA での最終確認だけを担う。
  目標水準は **80〜90% 自動化を確信した状態で開始し、人間が欲しいのは結果だけ**という状態
- 人間が edit.json を VS Code 等で直接いじる経路も正当な操作として扱う。
  その安全網は edit-lint（notes-2026-07-16-qa-lint §1）が兼ねる

## 1. アプリ不要の完結経路（headless-first）を不変条件に昇格

**AKARI Video アプリを一切インストールしなくても、Claude Code（または Codex）CLI の中で
編集が完結する経路を常に保つ。**

- アプリは「人間が確認して直すための場所」（design-2026-07-13 §1）であり、
  パイプラインの必須コンポーネントではない
- ファイル契約が結合の全て（shell CLAUDE.md）である以上、アプリ抜き経路は原理的に成立する。
  本項はそれを「**成立し続けることを要件にする**」という昇格。コア操作
  （分析・編集・lint・プレビュー用レンダ・書き出し）に、アプリでしか実行できないものを作らない

### レポートが HTML である理由（本項の帰結）

1. **AI が最も得意に書ける表現形式**。表現プレーンを HTML にした理由
   （design-2026-07-13 §4）と同一の根拠
2. **アプリ無しでどこでも表示できる**。ブラウザがあれば足りるため、スマホでの確認・
   Cloudflare Pages 等への一時公開・通知経由の共有がそのまま成立する

→「**AI が HTML を書き、人間はどこでも見る**」を表現プレーンとレポートの共通原則とする。

## 2. 差分協調 — リアルタイム監視ではなく、チェックポイント間の状態差分

問題: 人間がセーブデータを（アプリ経由でも直接でも）変更したことを、AI にどう伝えるか。

### 不採用の記録（再検討しない）

| 提案 | 不採用理由 |
|---|---|
| リアルタイム監視（ファイルウォッチ / 操作イベントログを AI に流す） | イベント列は「何をしたか」であり「何が変わったか」ではない。大量の字幕を誤削除 → undo で巻き戻し、のような操作の嵐をそのまま流すと差し引きゼロの変更にコンテキストを浪費する |

### 採用: 状態差分（net diff）

- AI が読むのは**チェックポイント間の正味の差分**だけ。undo で元に戻った変更は
  差分ゼロ = コストゼロに自然に潰れる
- 応答 3 チャネルの git diff（shell CLAUDE.md）を **human→AI 方向にも対称に使う**。
  操作ログという新チャネルは作らない
- QA ステージスキルの手順に「前回チェックポイントからの edit.json 差分を読み、
  人間の変更意図を解釈する」を組み込む（「ここを変更したんだね」を差分から判断し、
  同種の修正への展開可否などを提案できる）

### git コミット粒度

- **微調整ごとのコミットは要求しない**。作業ツリーの未コミット変更が「ライブ層」
- コミット = 意味のあるチェックポイントのみ:
  - ステージ遷移（分析完了・編集案適用・QA PASS）
  - 人間 → AI のハンドオフ（「あとはお願い」）時点
- AI は必要時に `git diff`（前回チェックポイント比）で人間の変更を把握する。
  ウォッチャーも操作ログも不要

## 3. リモート・ヘッドレスパイプライン構想（将来像 + 遠隔 MVP）

§1 の不変条件が保たれている限り、以下は**既存部品の合成のみ**で成立する
（新アーキテクチャを要さない）:

```
スマホで撮影 → Google Drive 等へ投入
  → 定期実行（cron / scheduled agent）が新着を検出
  → Claude Code が起動し分析（analyze-footage）
  → 編集判断レポートを HTML で生成 → Cloudflare Pages 等へ一時公開
  → Discord / Slack へ通知
  → 人間はスマホで確認し、修正指示を自然言語で返信
  → 編集確定 → 書き出し → SNS 投稿
```

- **スマホでは一切編集しない**。編集は自宅のサーバー（ちょっとした本体）が行う
- テンプレ駆動: プロジェクト雛形（templates/）に従えば全工程が自動で流れることを理想とする

### 遠隔 MVP スコープ

1. 日本語字幕を入れる
2. その下に英語訳を入れる
3. 必要に応じて B-roll を入れる（AI 生成。生成手段は選択肢を残す）
4. QA チェック（人間は動画を確認し、自然言語で修正を往復する）

## 4. 優先度メモ

- QA 指示出し専用の iPhone アプリ: いずれ欲しいが**優先度は低い**。
  当面は HTML レポート + 通知 + 自然言語返信で代替する
