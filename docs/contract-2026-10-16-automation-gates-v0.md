# automation-gates-v0（自動化の門と「やったこと」）契約

- 日付: 2026-10-16
- 状態: **accepted**
- 前提: `skills/edit-plan/autonomy.md`（おまかせ度 3 つと止まる条件 3 つ）/ `.akari/intake.json` の `autonomy`
  （`full-auto` そのまま / `checkpoint` 提案つき・既定 / `collaborative` 一緒に作る）/
  `contract-2026-08-12-chat-approval-v0.md`（チャットは配管・閉じた語彙の承認）/
  `contract-2026-07-25-project-structure-v0.md`（`.akari/events/` = 作業の節目の記録。追記のみ）/
  `contract-2026-09-13-generation-v0.md` §8（費用承認）
- 発端: エージェントに任せて見ていないあいだも作業を止めたくない。一方で、戻せないことは人が決めたい。
  線を「見ているか」ではなく **「戻せるか」** で引き直し、止まる場所（門）を 1 つの表にまとめる。
  止まらずに進んだことは、あとで一覧から見て戻せるようにする
- スコープ: 門の語彙と判定 / 門の依頼と返事の出来事 / エージェントの「やったこと」の出来事 / やったこと一覧と戻し方。
  **新しいおまかせ度は作らない**（既存の 3 つを使う）

## 1. 原則 — 戻せることは止めない、戻せないことだけ止める

- プロジェクトの中で閉じていて戻せる変更（edit.json・captions.json・planning/・生成した素材の追加）は、
  見ていなくても**そのまま書いてよい**。書いたら §3 の `agent-action` を 1 件残す。アプリはそれを節目として git に撮るので、
  あとで一覧から戻せる
- 戻せないこと・外に出ること・お金と権利に触ることは **門**（§2）で止まり、人の返事を待つ
- おまかせ度は「門以外でどれだけ確認を挟むか」だけを変える。門は**どのおまかせ度でも止まる**

| おまかせ度 | 門 | 門以外の確認 |
|---|---|---|
| `full-auto` そのまま | 止まる | 挟まない（進めて後で見る） |
| `checkpoint` 提案つき（既定） | 止まる | 書き出しの前に 1 回 + 作り方が宣言した確認点 |
| `collaborative` 一緒に作る | 止まる | 方針・素材・実行の要所ごと（edit-plan の承認手順） |

## 2. 門の語彙（閉じた表）

| `gate` | 何のとき | 戻せない理由 |
|---|---|---|
| `publish` | 公開・投稿（YouTube 等へのアップロード、共有リンクの発行） | 外に出る |
| `lab-submit` | Lab・ストアへの提出 | 外に出る |
| `paid` | 有償の生成・購入（費用承認と同じ。見積を添える） | お金 |
| `external-send` | 素材や文書を外部のサービスへ送る（生成 API に人物の写真を送る等） | 外に出る |
| `delete-original` | 元素材（`assets/` の取り込んだ実体）の削除・上書き | 戻せない |
| `license` | ライセンスの疑義（出どころ不明・商用不可の疑い・規約に触れる道具の使用） | 権利 |
| `playbook-checkpoint` | 作り方（`playbook.json` の steps の `checkpoint`）が宣言した確認点 | 作った人が止めたい所 |
| `human-asked` | 人が「確認して」と頼んだ所 | 人の指定 |

- 表に無いものは門にしない（書き出しは上書きしない限り戻せるので門ではない）。新しい門は**この表に追記してから**使う
- lint の FAIL が直せないときは門ではなく報告（autonomy.md §4 の 3 のまま）

## 3. 出来事（`.akari/events/` に 1 件 1 ファイル・追記のみ）

ファイル名は `<ISO 時刻の数字>-<id>.json`。既存の出来事（`report-generated` 等）と同じ置き場・同じ規律（既存の記録は変更しない）。

```json
{ "version": 1, "id": "act-01J…", "type": "agent-action", "occurredAt": "2026-10-16T01:23:45+09:00",
  "actor": "partner", "summary": "無音を 12 か所カット", "files": ["edit.json"], "skill": "silence-cut" }
```

| `type` | 書く人 | 必須の項目 | アプリの振る舞い |
|---|---|---|---|
| `agent-action` | エージェント | `actor`（`partner` 中の相棒 / `external` 外のエージェント / `unattended` 無人）・`summary`（1 行）・`files` | 節目として git に撮る（コミットの本文に summary） |
| `gate-requested` | エージェント | `gate`（§2）・`summary`・`detail`（任意。見積・送り先・対象ファイル）・`requestId` | 門の帯を出す（承認 / やめる） |
| `gate-resolved` | アプリ（人の操作）か人 | `requestId`・`decision`（`approved` / `declined`）・`by`（`human`） | 帯を消す。エージェントはこれを読んで進むかやめる |

- エージェントは `gate-requested` を書いたら、その `requestId` の `gate-resolved` が来るまで、その門の向こうの操作をしない
  （門と関係の無い戻せる作業は続けてよい）
- `gate-resolved` を書けるのは人の操作だけ（アプリの帯のボタン・チャットの承認の語彙）。エージェントは書かない
- 読み手は tolerant reader（未知の type は無視・未知のフィールドは保持）

## 4. やったこと一覧と戻し方

- 一覧はプロジェクトの節目（git のコミット）を新しい順に並べたもの。行 = 時刻・誰が（あなた / 相棒 / 外のエージェント / 無人）・
  1 行の要約・変わったファイル数。`agent-action` から撮った節目は summary と actor を出す
- 行の操作: **変更を見る**（既存の差分表示）/ **ここまで戻す**（その節目の直前の状態にファイルを戻し、それを新しい節目として撮る。
  履歴は消さない = 戻したこと自体も戻せる）
- 入口: プロジェクトのホームの「履歴」と、門の帯の「やったこと」。プロジェクトが git を持たないときは一覧を出さず理由を 1 行
- 素材の実体（`assets/` の取り込んだファイル）と書き出し（`exports/`）は履歴に入らない（`history-policy.mjs`）。
  戻すのは編集データと文書だけで、元素材は戻らない（だから削除・上書きは門）

## 5. 非スコープ

- 通知（OS の通知・メール）。v0 はアプリを開いたときの帯と一覧だけ
- 門の承認をチャット以外の外部（スマホ等）から返す経路
- おまかせ度の新設・名前の変更
- `publish` / `lab-submit` の実体（アップロード機能そのもの）。v0 は門の語彙と帯だけを用意する
