# 国土地理院タイルから地形の素材を作る

`akari geo terrain` は、国土地理院の標高タイル（`dem_png`）と写真タイル（`seamlessphoto`）を
取得して bbox の範囲に結合・切り出し、3D の地形宣言が読む 3 つのファイルを出力します。

地理院タイルは無料・認証不要ですが、**出典の表示**が条件です。コマンドは `terrain.json` と
CLI の出力に必ず出典を書きます。

## コマンド

```sh
akari geo terrain \
  --bbox 139.3445,35.5960,139.3555,35.6050 \
  --zoom 14 \
  --out assets/terrain/sagamihara
```

| オプション | 意味 |
|---|---|
| `--bbox <西,南,東,北>` | 世界測地系の度で範囲を指定（必須）。`西 < 東` かつ `南 < 北` |
| `--out <dir>` | 出力先（必須） |
| `--zoom <1-14>` | タイルのズーム（既定 `14`）。大きいほど精細でタイル数が増える |
| `--max-tiles <n>` | 1 層あたりのタイル数の上限（既定 `64`） |
| `--cache-dir <dir>` | タイルのキャッシュ先（既定 `~/.akari/cache/geo`） |
| `--json` | 結果を JSON で出力 |

bbox に必要なタイル数が上限を超えるときは、**取得を始める前に**止まり、収まる zoom を案内します。
勝手に zoom を下げることはありません。

## 出力

| ファイル | 内容 |
|---|---|
| `heightmap.png` | 標高タイルを `gsi-dem` の符号化のまま結合。`x = R*65536 + G*256 + B` として、`x < 2^23` は `x*0.01` m、`x = 2^23`（RGB `128,0,0`）は無効値、`x > 2^23` は `(x - 2^24)*0.01` m（負の標高）。無効値は最寄りの有効画素で埋める。404 の標高タイルは全体を無効値として扱い、同じように補間する |
| `texture.png` | 写真タイルを同じ矩形に結合・切り出し。404 の写真タイルは海の色（`#2a4d69`）の単色で埋める |
| `terrain.json` | 範囲・ズーム・実寸・標高の範囲・符号化・見つからなかったタイル数・出典 |

```json
{
  "bbox": [139.3445, 35.596, 139.3555, 35.605],
  "zoom": 14,
  "size_m": [1002.2, 1009.9],
  "elevation_m": [124.19, 170.33],
  "encoding": "gsi-dem",
  "declaration": {
    "heightmap": "heightmap.png",
    "texture": "texture.png",
    "encoding": "gsi-dem",
    "size": [10.02, 10.1],
    "meters": [1002.2, 1009.9],
    "baseline": "min"
  },
  "missing_tiles": { "dem": 0, "photo": 0 },
  "attribution": "出典: 国土地理院（地理院タイル）"
}
```

`size_m` は `[幅, 奥行]`（m）です。切り出した画素数と bbox 中心の緯度での地上解像度から出すため、
丸めていない bbox ではなく画像の実寸に一致します。`elevation_m` は切り出し内の**有効な**標高画素の
`[最小, 最大]` です（補間した画素は範囲を変えません）。

`declaration` は 3D の宣言にそのまま貼れる形です。`meters` は `size_m`、`size` は
`meters / 100`（1 m = 0.01 ワールド単位）なので、地図の実寸の比率を保ちます。`baseline` は
`"min"` で、有効な最低標高が `y = 0` になります。

## 出力を 3D シーンで使う

`declaration` をそのまま `terrain` に貼ります。ファイルは断片の隣に置くか、使っている
プロジェクト基準のパスに直してください。

```json
{
  "terrain": {
    "heightmap": "heightmap.png",
    "texture": "texture.png",
    "encoding": "gsi-dem",
    "size": [10.02, 10.1],
    "meters": [1002.2, 1009.9],
    "baseline": "min",
    "exaggeration": 1
  }
}
```

`meters` は高さマップの実寸 `[幅, 奥行]`（m）です。あるときランタイムは標高を
`size[0] / meters[0]` で縮めてから `exaggeration` を掛けるため、上方向と横方向が同じ縮尺に
なります。`baseline` は `y = 0` に置く基準で、`"min"`（既定）は最低標高、`"sea"` は標高 0 m
です。グレースケールの高さマップは従来どおりで、`meters` / `baseline` を使いません。

`akari geo point` は、その宣言が作る `[x, y, z]` へ経緯度を変換します。

```sh
akari geo point --terrain assets/terrain/sagamihara/terrain.json --lonlat 139.3500,35.6000
# [0, 13.42, -0.5]
```

3 つ目の数値で、高さマップから引く代わりに標高（m）を渡せます。

```sh
akari geo point --terrain assets/terrain/sagamihara/terrain.json --lonlat 139.3500,35.6000,120
```

結果は `lines[].points` と `data-akari-3d-anchor` にそのまま使えます。画像の 1 行目が北、
1 列目が西で、地形メッシュと同じ向きです。x・z は地図の範囲、y は `baseline` と縮尺を
適用したあとの標高です。

`gsi-dem` で `meters` が無く、高低差が `size` の 10 倍を超えるときは、標高と地図の距離が
別の縮尺になるため lint が警告します。描画時は、高さマップが読めない・標高がすべて無効値・
最初の描画で地形がカメラの視野に入らない、のいずれかでランタイムが警告を出します
（stderr に出るので `akari capture` と書き出しにも表示されます）。

`missing_tiles` は 404 が返ったタイルの枚数です。地理院タイルは海や範囲外のタイルが 404 になります。
海を含む bbox でも成功し、標高は補間、写真は海の色で埋めます。**bbox の標高タイルがすべて**
404 のときだけ、出力を書く前に止まり、陸地を含む bbox を案内します。404 だけをこのように扱い、
ほかの 4xx は即座に失敗、5xx は再試行します。

## 出典表示の決まり

- `terrain.json` の `attribution` は消さず、書き換えない。
- 地形を映像に使うときは、画面またはクレジット・説明欄に
  **「出典: 国土地理院（地理院タイル）」** を表示する。CLI も成功のたびに同じ行を出す。
- 標高の符号化と出典は地理院タイルの利用条件の一部です。出力を変換・再配布するときも
  出典を一緒に持たせてください。

## キャッシュと通信

取得したタイルは `~/.akari/cache/geo/` に保存し、再取得しません（`AKARI_GEO_CACHE_DIR` で変更可）。
同じ bbox と zoom の 2 回目はオフラインでも動きます。取得先は
`cyberjapandata.gsi.go.jp` で、送るのはタイル番号の GET だけです。タイルは 1 枚ずつ取得します。

テストはネットワークに出ません。fetch を差し替え、小さなタイル fixture で
タイル番号の計算・結合と切り出し・無効値の補間・404 の扱い（一部と全部）・terrain.json の値・
タイル数上限・キャッシュの再利用を検査します。リポジトリに置いた小さな JPEG fixture で
ffmpeg 経由の写真展開も検査し、ffmpeg が無い環境ではその旨を出してスキップします。

## 関連

- 写真タイルは JPEG です。AKARI が映像処理で使う ffmpeg の解決経路で展開するため、
  新しい画像ライブラリは足していません。
- `terrain` 宣言そのもの（高さマップ・写真・実寸・誇張を 3D がどう読むか）は 3D 側の担当で、
  このコマンドの範囲外です。
