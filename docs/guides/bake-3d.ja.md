# 3D シーンをベイクする

3D の既定の経路は、Three.js で描く**ライブ 3D**（動く部品。`author-scene3d/live.md`）です。
ベイクは、ライブ 3D では出せない絵のための**もう 1 つの経路**で、Blender で 3D シーンを
**映像素材として焼き込みます**。どちらもスキル `author-scene3d` の経路で、このページはベイクの経路
（`bake.md`）を扱います。焼いた映像は、通常のクリップとして edit.json に載せられます。

画面では、この「ベイクレシピ」を **3D の設定** と呼びます（素材の絞り込みの項目、接続の「3D の設定」）。
CLI・ファイル・スキルでは従来どおり recipe / `scene.py` です。
（`akari recipe` コマンドは別物で、外部の道具を使う手順を確かめるものです。）

## いつ使う

次のどれかに当てはまるときだけ、ベイクを選びます。

- 被写界深度・モーションブラー・レイトレースの反射・GI・パーティクルなど、Three.js の宣言型の描画では出せない絵が要る
- 3D のシーンが同時に 3 つ以上出て、書き出しの負荷が高すぎる（一部を焼いて 2 つ以下にする）
- 再利用できるクリップとして、素材ライブラリに納める

「タイムラインにクリップとして置きたいから」だけでは、ベイクを選ぶ理由になりません。
焼いた映像には不透明な背景が付き、焼き直しに 10 分ほどかかるためです。
開閉や回転の動きだけなら、Blender で動きを glb に焼いて Three.js の経路で再生します。

## 仕組み — レシピ方式

3D シーンは「レシピ」（`scene.py` + パラメータ宣言）として管理します。

- レシピは Blender をヘッドレス起動して mp4 に焼く再現可能なスクリプト
- 色・文字・速度などの調整点はパラメータとして宣言されており、
  Blender を触らずに値だけ変えて再ベイクできる
- 焼き上がりは `bakes/*.mp4` に出力され、**edit.json の通常クリップ**として使う
- 同じレシピ・同じパラメータ・同じ Blender の版なら、同じ映像になる（時刻や乱数に頼らない）

## 頼み方

- 「ロゴが回るオープニングを 3D で作って」
- 「この 3D の設定の文字を『第 2 回』に変えて再ベイク」
- 「draft で速く確認して、良ければ final で」（`--profile draft / final`）

## 流れ

1. レシピ選定または新規作成（カタログ・ライブラリから探索）
2. パラメータ確認 → ベイク実行（Blender ヘッドレス）
3. 出力を検証（尺・解像度・先頭 / 中ほど / 末尾のフレームの目視）
4. プロジェクトへ配置、または [ライブラリへ入庫](./asset-library.ja.md)

## Three.js との使い分け

| | ライブ 3D（author-scene3d/live.md。既定） | ベイク（author-scene3d/bake.md） |
|---|---|---|
| 実体 | Three.js で描く動く部品（`.glb` を読む） | Blender で焼いた mp4 クリップ |
| 触れる度 | ツマミ（CSS 変数）・インスペクターの 3D の節・キーフレームで即調整 | パラメータ変更 → 再ベイク |
| 向き | 軽量な演出・タイトル・デバイスのモック | 重い質感・ライティング・複雑なシーン |

ライブ 3D の `.glb` は、外部のバッファを持たない自己完結のファイルを使います。
**Draco 圧縮と KTX2 には対応していません**（圧縮せずに書き出した glb を使ってください）。

## 前提

- Blender がローカルにあること（未導入ならベイクの経路が確認・案内します。承認なしには入れません）。
  場所は環境変数 `AKARI_BLENDER_BIN` で指定できます
