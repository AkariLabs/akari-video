# 編集計画を立てて実行する

分析結果をもとに、エージェントが編集方針を提案し、承認を経て `edit.json`
（編集のセーブデータ）へ落とし込む中心工程です。スキルは `edit-plan`。

## いつ使う

- 素材の分析（[analyze-footage / analyze-project](./analyze-footage.ja.md)）が済んでいるとき
- カット構成・BGM・SFX・B ロール・テロップ計画をまとめて決めたいとき
- 素材ゼロから生成で組む場合（→ 先に [ゼロから企画する](./plan-from-scratch.ja.md) を参照）

## 頼み方

「編集方針を立てて」「この分析レポートをもとに 60 秒に縮めて」「テンポ重視でカットして」

## 3 段階の承認ゲート

edit-plan は一気に最後まで走らず、3 つの節目でチャット承認を挟みます
（`autonomy: full-auto` の場合は自動承認）:

1. **方針** — 全体の構成・トーン・尺配分。分析レポートを一次証拠として提示
2. **素材計画** — どの素材のどこを使うか、足りない素材をどう埋めるか（生成 / 撮り足し / 既存流用）
3. **実行** — edit.json への書き込みとオーバーレイ生成

決定はすべて `decision-log.md` に追記されます。「なぜこうなったか」は後から必ず追えます。

## 生成されるもの

| ファイル | 内容 |
|---|---|
| `edit.json` | 編集の SSOT。カット列・オーバーレイ参照・音声（BGM/SFX/ナレーション）・ビート・演出 |
| オーバーレイ HTML 断片 | テロップ・字幕・図形など（`edit.json` の `overlays[]` から参照） |
| `captions.json` | 字幕データ |
| `decision-log.md` | 判断の記録 |

## edit.json のここだけ知っておく

編集状態の正本はこのファイルです。スキーマの正確な定義は
[Reference](../README.ja.md#reference) の各契約にありますが、日常の操作で意識するのは:

- **新規プロジェクトは常に edit v1 で始まる** — 新しく作られる `edit.json` は必ず `sources[]`
  （素材 1 本でも配列に 1 件で書く）と、それを指す `cuts[].src` を使います。手元に
  `version: 0`（単一 `source`）のままの古いプロジェクトがあっても、そのまま v0 で編集して
  構いません — 既存ファイルを勝手に v1 へ移行することはありません。変換を頼まれたときは
  [マルチソース契約 §5](../contract-2026-07-18-edit-json-v1-sources.md) の機械的な手順
  （差分を提示 → 明示承認 → 変換。無断で書き換えない）に従います。
- **cuts[]** — どの素材（`src`）の何秒から何秒を使うか。時刻は常に**素材の原本秒**で
  永続化されるので、前後のカットを入れ替えても参照はズレない
- **overlays[]** — オーバーレイ HTML への参照とタイミング
- **audio** — 効果音も音楽も**クリップ**として書く（`audio.sfx[]`。`cuts[]` と同じ
  `t`/`in`/`out` の意味論で、タイムライン上のバー端ドラッグでトリムできる）。ナレーションは
  `audio.narration[]`。`audio.bgm` は全編ループの最短表現（ベッド）として残っており、
  トリムや途中配置が要らないときだけ使う。一部区間だけに敷く・曲を切り替える等は音楽でも
  クリップで書く

手で直接編集しても構いません（git diff で差分が追えます）。ただし変更後は
[edit-lint](./review-and-fix.ja.md) をかけるのが約束です。
