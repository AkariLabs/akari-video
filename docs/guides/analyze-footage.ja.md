# 素材を分析する

撮影素材をエージェントが「読める」状態にする工程です。編集計画の前提になります。

## 1 本ずつの分析 — `analyze-footage`

**いつ使う**: 新しい撮影素材を取り込んだとき。編集計画（edit-plan）の前処理として。

**頼み方**: 「この動画を分析して」「`assets/` に入れた素材を取り込んで」

**やること**: 必要な深さ（L0〜L3）まで、引っ張られた分だけ観察します。既定は L0 + L1 です。
L2・L3 は頼まれたとき、または後の工程がその観察を必要とするときだけ足します。

| 段 | 何をするか |
|---|---|
| **L0 メタデータ** | `akari media probe` で長さと映像・音声の有無を確かめる |
| **L1 音声** | 波形（`waveform`）で無音と「話していそうか」を見て、話していそうなときだけ文字起こし（`transcribe`）をする |
| **L2 映像** | フィルムストリップ（`filmstrip`）や静止画（`grab`）をエージェントが実際に見て、キーフレーム・イベント（フィラー・トラブル・章・見どころ・フック）を記録する |
| **L3 人物** | 効果に必要な素材・区間だけ、人物マットや顔・手・体の位置データを作る |

L2 で映像を見るときだけ 720p のプロキシを作ります（プレビューは常にプロキシ、書き出しは原本）。
L0・L1 は原本をそのまま読みます。

**生成されるもの**: `analysis.json`（素材ごとのサイドカー。
`.akari/sidecars/<素材相対パス>.analysis/` 配下）

`analysis.json` は「事実層」です。ここには観測できたことだけが書かれ、
解釈や編集判断は次の工程（interpretation.json / edit.json）に分離されます。
話していない素材に言葉を足すことはせず、文字起こしは空のまま理由を報告します。

### 文字起こしのエンジン

環境に応じて、次の 3 層から選びます。

- **SpeechAnalyzer**（macOS・ローカル・高速）— 既定。指定した言語に対応しているとき使われます
- **whisper.cpp**（ローカル・無償）— SpeechAnalyzer が使えない環境（Windows など）や、
  SpeechAnalyzer が対応しない言語、SpeechAnalyzer が失敗したときの代わり
- **クラウド STT**（要接続設定）— 精度が必要なとき。**既定では音声を外へ送りません。**
  接続が正常で、人が決定カードで明示的に承認したときだけ使います。ローカルが使えないだけでは切り替えません

whisper.cpp のモデルが無いときは、次のどれかで入れます。

```sh
akari tools install whisper
```

または、設定 → 道具 → Whisper からインストールします。ggml のモデルを `~/.akari/tools/models/` に置く方法もあります。

### 言語

文字起こしには、その動画の中身の言語（content-language）を渡します。画面や会話の言語とは別です。
文字起こしの言語は `--lang`（例: `akari media transcribe <素材> --lang en`）→ `.akari/intake.json` の `language` →
自動判定の順に決まります。判定した言語は `analysis.json` に残り、字幕やナレーションの言語の既定にも使われます（何も無ければ `ja`）。
英語の素材なら英語を指定します。

### 話者を分ける

既定では話者を分けません。会話やインタビューなど 2 人以上が話す素材のときだけ、人数（わからなければ `auto`）を決めて分けます。

```sh
akari media transcribe <素材> --diarize --speakers 2
```

声のエンジンは初回に用意します（`akari tools install voice`、またはアプリの「字幕を作る」から）。
チャンネルの人物のうち、本人または本人の同意を得た声のサンプルがある人となら、名前の候補も出ます（`--identify`）。
候補は提案で、名前を決めるのは人です。声の特徴量（`voices.json`）は本人確認に使えるデータなので、読み出しも外への送信もしません。

### 人物マットと vision tracks（L3）

「人物の後ろに文字を入れる」などの切り抜き効果を使うときだけ、その素材の**人物マット**を作ります。
映像の書き出しを伴うので時間がかかります（目安は素材の尺の数倍）。顔があるだけでは作りません。

目の位置・指先・体の関節を使う効果（アイバー・指フレーム・ポーズスケルトンなど）を選んだときだけ、
**vision tracks**（顔・手・3D の体の姿勢）を作ります。必要な種類だけを指定でき、
3D の体の姿勢はとくに時間がかかります。どちらも、道具が無い環境では作らずに理由を記録します。

## プロジェクト横断の分析 — `analyze-project`

**いつ使う**: 素材が複数あるとき。編集方針を決める前に全体像を掴みたいとき。

**頼み方**: 「プロジェクト全体を分析して」「素材を読み合わせてレポートにして」

**やること**:

1. 各素材の `analysis.json` と、プロジェクト文脈（`intake.json` / `edit.json` /
   `planning/` 配下）を読み合わせる（再視聴はしない・テキスト推論のみ）。足りない素材だけ analyze-footage を回す
2. 解釈層 `interpretation.json` を生成（1 プロジェクト 1 ファイル）
3. 読み取り専用の**分析レポート HTML** を描画

素材が届いた直後には、観察した尺・向き・話者・素材の種類に合う作り方（Playbook）を最大 3 つ、
理由つきで提案することがあります。選ぶまで適用はしません。

**取材質問（open_questions）**: 素材だけでは判断できないこと
（「この場面は残したい思い出か、失敗テイクか」など）は `open_questions` として
レポートに残ります。チャットで答えると解釈が更新されます。
一次情報が欠けたまま編集判断を捏造しない、という規律のためのものです。

## 分析レポートの見方

レポートは読み取り専用で、決める画面（選択肢やボタン）はありません。編集方針は、
このレポートを一次証拠にしてチャットで詰めます。「一緒に作る」では方針を明示的に承認してから
編集計画（edit-plan）が実行へ進みます。「提案つき」「そのまま」では、レポートを読まずに
`analysis.json` だけで進むこともできます。
