# QA・レビューして直す

「開いたらほぼ終わっている」を成立させるのは検査とレビューのループです。
3 つのスキルが連携します: `edit-lint`（機械検査）→ `compile-review-session`
（録音レビューのチケット化）→ `address-review`（チケット対応）。
プレビューに直接付けた印は、録音なしでそのまま注釈（チケット）になります。

## セルフチェック — `edit-lint`

**いつ使う**: `edit.json` を作成・変更した直後。書き出しの前。レビュー対応後の再確認。

**頼み方**: 「lint かけて」「書き出す前にチェックして」

**やること**:

1. 決定的 CLI が `edit.json`（v2）・`captions.json`・`analysis.json`・メディア実体を検査
   （参照切れ・時刻の矛盾・重なり・尺の不整合など。v2 では短すぎる項目や、素材の区間と
   置いた尺の食い違いも警告）
2. 書き出しの前に `--engine gpu` / `osr` / `auto` を付けて、書き出しエンジンが読まない項目が
   無いかを確認（対応表は `packages/schemas/engine-capabilities.json`）。読まれない項目は
   エラー、近似になる項目は警告として出る
3. PASS 後、エージェントがキーフレームを**実際に視認**して品質確認

**生成されるもの**:

- `.akari/lint.json` — 検査結果の正本（`verdict: pass / fail`）
- `.akari/reports/edit-lint-report.html` — 人間向けレポート

アプリでは、検査結果をポップアップで中身まで見られ、指摘はそのままパートナーに直してもらえます。
FAIL のときはレポートに件数と理由が出ます。「lint の FAIL を直して」で対応まで頼めます。
render-cut は lint PASS を前提条件にしているので、このゲートは飛ばせません。

## プレビューに印を付けて AI に渡す

録音しなくても、見ながら気になった所に直接印を付けられます。

1. 出力プレビューの再生バーの **2 行目**にある **ペン**・**ピン**・**範囲** から道具を選ぶ
   - ペン: 動画に線を描く
   - ピン: 動画の上をクリックして置く（置いたあともドラッグで動かせる）
   - 範囲: 開始位置と終了位置を選ぶ（確定すると範囲の道具から抜ける）
2. 印の横の小窓に「変更したい内容」をメモする。印のある所の字幕や映像も一緒に記録される
   （小窓は × で閉じるまで出たままで、そのあいだも再生・シークできる）
3. 確定した印は **右パネルの注釈**に並ぶ。再生バーの「添付 N 件」の一覧にも並び、
   アプリを開き直しても残る
4. 注釈ごとに **「<!-- F ui.annotation.handToAi -->AI に渡す<!-- /F -->」**、まとめては **「まとめて AI に渡す」**。いま使っている
   パートナー（最後に前に出していたもの）の入力欄に依頼文が入ったところで止まるので、
   読んでから送る。書き込めないパートナーには、文章のコピーと貼り付けを案内する

ペンの線は「どこからどこへ」が依頼文に書かれます。注釈のペンの線を押すと、描いた順に線を
なぞって見せ、描きはじめに丸が付くのでどちらから描いたかが分かります。注釈と録音は削除できます。

注釈は `review.json` に保存されます。契約は
[review.json v1 注釈モデル](../contract-2026-07-20-review-json-v1-annotation-model.md) と
[注釈ストローク永続表示](../contract-2026-08-23-stroke-persistence.md)。

## 喋りながらレビューする — `compile-review-session`

**いつ使う**: プレビューを見ながら口頭で気になった点を挙げていきたいとき。

右パネルの「話しながら注釈する」で録音を始め、再生しながら話して描きます（イヤホンで聞いて
ください）。録音は音声・操作イベント・描いた線・録音時点の `edit.json` のスナップショットとして
`review/sessions/` に残ります。録音を渡すと:

1. 文字起こし → 発話の区切り
2. 「ここ」「この字幕」などの指示語を、再生位置と操作イベントから**実際の対象に解決**
3. 命令形に正規化して `review.json` の open チケット（annotation）として着地。
   解決できなかった発話は黙って捨てず `[要確認]` の印と低い確信度で残す

**頼み方**: 「さっきのレビューセッションをチケットにして」

まだ AI に渡していない録音は右パネルに件数が出ます。「録音を見返す」では、音声・出力プレビュー・
線・文字起こしを同じ時計で見直せ、録音時点から `edit.json` がどう変わったかの差分も出ます
（[見返しビューア](../contract-2026-09-12-review-session-viewer.md)）。

## チケットに対応する — `address-review`

**いつ使う**: `review.json` に open チケットが溜まっているとき。

**頼み方**: 「a-0002 と a-0003 に対応して」「open チケット全部対応して」

チケットごとに `edit.json` へ実対応 → edit-lint で再検査 → チケットを
`open → addressed` に更新、まで型どおりに実行されます。対応しないチケットも黙って閉じず、
理由つきで見送りとして返します。`[要確認]` のチケットは、名指しされたときだけ扱います。
状態遷移は原子的に記録されるので、どこまで対応済みかが常に明確です。

`resolved`（確認済み）にできるのは人だけです。`addressed` は AI が対応した印で、確認が済むまでは
未解決として扱われます。レビューボード（`review.json` のかんばん）で、人が内容を見て確認済みにします。

## 自動化の門と「やったこと」

エージェントに任せて見ていないあいだも、**戻せる作業は止まらず進み、戻せないことだけ人の
返事を待ちます**。おまかせ度（そのまま / 提案つき / 一緒に作る）はどれでも、次の場面では必ず止まります。

| 止まる場面 | 例 |
|---|---|
| 公開・投稿 | YouTube などへのアップロード、共有リンクの発行 |
| Lab への提出 | Lab・ストアへの提出 |
| 有償 | 有償の生成・購入（見積つき） |
| 外部への送信 | 人物の写真を生成 API へ送る、など |
| 元素材の削除 | 取り込んだ素材の削除・上書き |
| ライセンスの確認 | 出どころ不明・商用不可の疑い |
| 作り方の確認点 | 作り方が「ここで止まって」と宣言した所 |
| 確認の依頼 | 人が「確認して」と頼んだ所 |

止まると、アプリに確認待ちの帯が出ます。**承認**すれば進み、**やめる**と見送ります。
止まらずに進んだ作業は、プロジェクトの節目として記録され、**「やったこと」**の一覧から
誰が（あなた / 相棒 / 外のエージェント / 無人）何をしたかを見て、**変更を見る**・**ここまで戻す**ができます。
戻した操作自体も新しい節目として残るので、戻したことも取り消せます。戻るのは編集データと文書で、
元素材の実体と書き出したファイルは履歴に入りません（だから素材の削除・上書きは門で止まります）。
契約は [automation-gates-v0](../contract-2026-10-16-automation-gates-v0.md)。

## レビューの永続化について

注釈は「タイムライン上の何秒」ではなく **(素材, 素材の原本秒)** で保存されます。
カットを並び替えてもチケットの指す場所はズレません。
