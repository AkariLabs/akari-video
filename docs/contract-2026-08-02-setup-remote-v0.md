## 0. 位置づけ — 一言で言い切る

承認は本質的に**机の前にいなくてもできる**。解析・レンダはマシンが回し、人間は「レポートを見て
OK / 差し戻しを言う」だけ — その閲覧と素材の受け渡しを、道具 1 つ（Tailscale）のセットアップで
スマホから可能にする。私設ネットワーク限定 = **デフォルト非公開**であり、「設定ミスで世界に公開
されていた」が構造的に起きない手段だけを既定とする。

## 1. 決定事項（v0 の骨格）

| 論点 | 決定 |
|---|---|
| 手段 | **Tailscale**（tailnet 限定）。閲覧 = `tailscale serve` でプレビューサーバーを tailnet 限定 HTTPS 化。素材 = **Taildrop**（共有シートからデバイス直送。クラウド不経由・実用上サイズ無制限・画質劣化なし） |
| 不採用 / 保留 | Cloudflare Tunnel + Access（tailnet 外の人への共有が要件になったときの**別契約**。「公開してからゲートで守る」構造は既定にしない）。Cloudflare Pages（レポートはローカル随時生成のため噛み合わない） |
| 素材搬送路の優先順位 | **Taildrop（v0 で実装）** → Dropbox カメラアップロード → iCloud 写真 → Google Drive（順次。v0 では選択肢として提示のみ）。Google フォトは対象外（Library API 制限により自動取得不可） |
| 対応 OS | macOS / Windows 両対応を前提に書く（Tailscale / Taildrop とも両対応。手順の分岐は SKILL.md 側） |

## 2. スキルの責務 — 5 フェーズ

1. **doctor**: Tailscale の導入状態を決定論で判定（未導入 / 導入済み・未ログイン / 構成済み）。
   プレビューサーバーの起動可否・serve 設定の現況もここで検出
2. **導入ガイド — 人間手番の受け渡し**: インストーラーの sudo・GUI ログイン・スマホ側アプリ導入は
   **自動化しない**（macOS の cask は .pkg で sudo 対話必須 — 実測済み）。スキルは
   「ここはあなたの番」を明確に指示 → 完了を doctor で確認 → 次へ進む、を繰り返す構造とする
3. **serve 設定**: `tailscale serve` でプレビューサーバー（4567）を tailnet 限定 HTTPS URL にする
4. **Taildrop 受信設定**: 受信先フォルダを固定し、作業場の `inbox/` へ接続する
   （直接指定できる場合は直接、できない場合は受信箱 → `inbox/` への移送手順を案内）
5. **疎通確認**: 別デバイスから (a) serve URL が開ける (b) テストファイルを Taildrop 送信して
   `inbox/` に現れる — の両方が通ったら、URL と受信経路を完了レポートに記録して終了

## 3. 安全規律（ハードルール）

- 既定は **tailnet 限定のみ**。公開インターネットへ出す `tailscale funnel` は**既定で使わない・
  提案もしない**。ユーザーが明示的に要求した場合のみ、リスク説明 + 明示承認を経て扱う
- serve の対象は**プレビューサーバーのみ**。ファイルシステムや他ポートを serve しない
- secrets を作業場・プロジェクトに書かない（creator-root v1 の原則。Tailscale の認証情報は
  Tailscale 側が管理し、スキルは一切保持しない）
- スキルが勝手にインストールを完遂しない（§2-2 の人間手番）。ネットワーク設定の変更は
  すべて事前提示 + 承認後に実行

## 4. intake との接続

- Taildrop の受信先 → 作業場 `inbox/`（creator-root v1 §3 の投げ込み口）が受け皿
- 「直近で撮ったやつで編集よろしく」の**自動選択規約（直近 N 件 / 直近 24h 等）は v0 では
  定めない** — 人間が `inbox/` 内のファイルを指す運用でよい。自動選択は intake 側の将来契約
- クラウド同期レーン（Dropbox 等）を使う場合も「同期フォルダ = 監視対象」に正規化される設計を
  崩さない（搬送手段が何であれ、最終形は「ローカルフォルダにファイルがある」）
