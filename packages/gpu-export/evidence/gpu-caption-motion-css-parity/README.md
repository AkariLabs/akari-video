実機: macOS・`render-cut --engine gpu` / `--engine osr` の実際の書き出し（1280×720・30fps・H.264）。
fixture = `scripts/fixture.mjs`（単色の映像 + 字幕 12 本。in / out に同じ語彙・loop は別の語彙、loop 無しの行は回転 / 拡縮の中心を素で見る）。

## 測り方（`scripts/compare.mjs`）

- ink = 背景からの色差の総和 / 画素数（不透明度 × 塗りの量の代理）
- cx, cy = 色差で重みづけた重心（フレーム比）
- w, h = 色差 > 60 の画素の外接矩形（上下左右 0.5% の外れ値を落とす・フレーム比）
- 差 = GPU − OSR、ink 比 = GPU / OSR。許容差は契約の手順 2（重心 ±0.002・矩形 ±0.007）

## BEFORE で見えていた食い違い（原因）

1. **スロットの合成**: GPU は in / loop / out の状態を掛け合わせ・足し合わせていた。CSS は同じプロパティを後の animation（loop → out）が上書きする
   （例: in=spin-in・loop=float の登場の途中は、CSS では transform は float だけ・opacity は spin-in）
2. **字幕テクスチャの焼き込み**: 字幕の HTML を焼くとき板の CSS animation（paused）が効いたままで、登場の途中の姿（傾き・拡大）がテクスチャに入っていた。
   in / out が終わっているはずの loop 時刻でも c-0003（spin-in）が傾き、c-0002 / c-0005 / c-0011（pop / zoom-pop）が拡大したままだった
3. **回転 / 拡縮の中心と回転の向き**: GPU は画面の中心（クリップ空間）を中心に回し、縦横比の補正も無く、回転の符号も CSS と逆だった。CSS は板の中心（`transform-origin: center`）
4. **イージング**: GPU は全体の進行にイージングを掛けてから区間を探していた。CSS はキーフレーム区間ごとに掛かる（reverse は区間を逆向きに選び、区間内は順方向）
5. **amp**: GPU は全値に amp を掛けていた。CSS はレシピで `calc(… * amp)` が付いた値にだけ効く

## 直したこと（実装は codex・所有範囲のみ）

- `packages/frame-engine/src/timeline/caption-motion.ts`: 上書きの合成（opacity と transform を別々に、後のスロットが勝つ・触らないプロパティは下が残る・out は delay 前は効かない）、
  プロパティごとのキーフレーム区間（途中のキーフレームがそのプロパティを持たなければ飛ばす・端点に無ければ下の層の値）、区間ごとのイージングと reverse、CSS レシピどおりの amp、
  `translateX(100%)` 等の割合を板の寸法で解決
- `packages/frame-engine/src/exits/sprite-compositor.ts`: 描画に `originX` / `originY`（画素）を渡したときだけ、その点を中心に回転・拡縮し、非正方形の縦横比を補正する（未指定の描画は従来と同じ行列）
- `packages/gpu-export/src/page-runtime.js`: 動きの宣言がある字幕だけ、焼き込みと採寸で板の animation を止める・板の中心を origin として渡す・板の font-size を em の基準にする・回転の符号を CSS にそろえる。
  宣言の無い字幕は CSS も origin も変えない（= 画素一致）
- 語彙の受け付け（typewriter / wipe / push / glitch / swing は OSR へ）は変えていない
