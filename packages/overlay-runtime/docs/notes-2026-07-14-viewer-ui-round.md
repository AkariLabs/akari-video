│                                        │ 字幕                              │

│                                        │ │        ことができるという…     │ │   アクセント背景

- **左右分割**: 左=プレビュー、右=字幕リスト。既定比率は概ね **60:40**。
  ドラッグで動かせる可変スプリッタとし、両ペインに下限を設ける
  （プレビュー最小 320px 程度・リスト最小 260px 程度）。「プレビューは小さくてもよい」
  という要望はこのスプリッタで実現する（既定値そのものを小さくするのではなく、
  可変にして好きな比率へ寄せられるようにする）
- **上部バー**: 高さ 44px 固定。左にタイトル（今回は表示のみで可、編集導線は対象外）、
  右に「全画面」トグルボタンと「書き出し」ボタン（アクセント塗り、いちばん目立つ位置）
- **下部トランスポート**: プレビューペインの内側下端に**常設**（フルスクリーン時も消えない。
  §2・§5 参照）。字幕パネルには重ねない
- **字幕リスト**: プレビューの右側にドッキング。字幕の見た目編集 UI
  （フォント/色/アニメーションなどのスタイル設定）は本ラウンドのスコープ外（§9 参照）

> 本パッケージが担うのは `#overlay-stage` 配下のオーバーレイ DOM とインタラクション、
> `#minimap` のミニマップのみ。上部バー・下部トランスポート・字幕リストパネル・
> スプリッタなどのアプリシェル DOM 骨格（`ui/index.html` 《legacy 参照》相当）は
> 本パッケージの対象外で、新シェル実装者が用意する（`README.md` のホストアダプタ契約参照）。

## 2. 常設トランスポートバー

自作のシーク/再生バーとする（OS 標準の動画コントロールは使わない。既に
`ui/index.html` の `#controls` がこの役割の土台としてある）。《legacy 参照 —
トランスポート DOM 自体は本パッケージの対象外》

- **常時表示**: ホバーで出す/消すではなく、プレビューペインの下に固定の帯として常に描画
  する（要望2）。既存の左下フロート `#controls` はこの帯に統合・置き換える
- **構成**（上→下、左→右）:
  1. シークバー（幅いっぱい）— クリックでシーク、ドラッグで scrub。
     ドラッグ中は `video_seek` を毎フレーム呼ばず、pointerup で確定シークする方式を推奨
     （ローカルの scrub 中フラグのみで十分。IPC 負荷を避ける）
  2. 現在時刻（左端）/ 総尺（右端）— `mm:ss`（1 時間以上は `h:mm:ss`）、等幅数字
     （`font-variant-numeric: tabular-nums` で桁を揃える）
  3. 再生/一時停止（中央）— 1 個のトグルボタン（▶⇄⏸）。既存の `#btn-play` /
     `#btn-pause` の 2 ボタンはこの 1 ボタンに統合する（`engine.toggle()` を叩く。
     Space キーショートカットは現状のまま維持）
- **字幕区間バー（推奨・必須ではない）**: シークバー上に、キャプション系オーバーレイの
  `start`〜`start+duration` を薄い帯で重ねて表示する。データ（overlays の
  start/duration）は `EditSummary` に既にあるため実装コストは低いが、必須要件では
  ないため後回し可
- **見た目**: トラック=`rgba(255,255,255,0.18)` の 5px capsule、進捗=アクセント色
  capsule、つまみ=白円 9px（ホバー/scrub 中は 13px）+ 影 `0 1px 2px rgba(0,0,0,0.4)`

## 3. 拡縮ハンドル（オーバーレイの selection scale）

要望1。現状 `interaction.css` に四隅ハンドル（`.akari-interaction-handle`,
nw/ne/se/sw）は**見た目だけ**存在し、ドラッグ操作は未実装（`pointer-events: none`）。
本ラウンドで「相対的に大きく/小さく」を正式な M3 機能にする。

> 本パッケージの `src/interaction.js` / `src/interaction.css` は、下記の仕様に
> 沿った実装済みの状態（ドラッグ可能な拡縮ハンドル込み）で移送されている。

- **操作**: 選択中オーバーレイの四隅ハンドルをドラッグ → **uniform scale**
  （縦横比固定、四隅どれでも同じ倍率計算）。回転・移動とは独立
- **計算方法**: コンテナ中心からドラッグ開始点までの距離 `startDistance` と、
  現在のポインタ位置までの距離 `currentDistance` の比で倍率を出す:
  `scale = dragStartScale * (currentDistance / startDistance)`
  コンテナの `transform-origin` は既定の中心のままでよい（M2 の合成 transform
  `translate(--x,--y) scale(--scale) rotate(--rotate)` は translate が先なので、
  拡縮してもアンカー位置は動かない — 移動ドラッグと干渉しない）
- **ライブ反映**: ドラッグ中はコンテナの `--scale` を書き換えるだけ
  （`--x`/`--y`/`--rotate` には触れない）
- **確定書き戻し**: 既存のドラッグ移動と同じ規約 —
  `pointerup` で `overlay_write(edit_path, overlay_id, { transform })` を呼ぶ。
  `interaction.js` の `readTransform()` は既に `--x`/`--y`/`--scale`/`--rotate` を
  まとめて読むため、移動用の `finishDrag()` と同じ書き戻し経路をそのまま再利用できる
  （並行するステート（例: `activeResize`）を 1 つ増やし、`onPointerDown` で
  イベントターゲットがハンドル要素かどうかを見て「移動ドラッグ」か「拡縮ドラッグ」かを
  分岐すればよい）
- **クランプ**: 最小 0.2 倍・最大 4.0 倍を提案する（字幕・ロワーサード等の小さい
  オーバーレイ要素が対象であることを踏まえ、1.0 倍付近での見た目破綻・可読性低下を
  避ける意図で狭めのレンジにする）
- **「等倍に戻す」スナップ（任意・推奨）**: 倍率が 1.0 の ±3.5% 以内に入ったら
  1.0 に吸着させる。触覚フィードバックは Web では扱えないため対象外
- **選択枠・ハンドルの見た目は変更しない**: 既存 `interaction.css` のスタイル
  （枠線 `2px solid`、アクセント色、ハンドル `10px` 白円+アクセント枠+影）をそのまま
  使う。変えるのは「ハンドルに `pointer-events: auto` を与えてドラッグ可能にする」ことと
  「ドラッグ時の挙動（移動 or 拡縮）」の追加のみ
- **合成 PointerEvent 対応必須**: 契約 §M3 と同じ制約（`isTrusted` チェック禁止）。
  既存の `selftest()` は移動ドラッグのみを検証しているため、拡縮ドラッグの selftest
  追加は実装ラウンドの任意タスクとして申し送る

## 4. 字幕リスト（右パネル）

要望3。テキスト編集・タイミング調整・有効/無効チェックボックスは実装しない、
表示専用の簡易版に絞る。

> 字幕リストパネル自体（DOM・データ源の列挙・自動スクロール）は本パッケージの
> 対象外（アプリシェル側の責務）。本節は legacy 参照として残すのみ。

- **データ源**: `state.summary.overlays` のうちキャプション系オーバーレイを
  `start` 昇順で列挙する。edit.json の overlay id は現状スキーマ例で
  `cap-a` / `cap-b` のような接頭辞を使う慣例がある（`contract-2026-07-13-m1-m4.md`
  《legacy 参照》のスキーマ例参照）ため、本ラウンドではこの接頭辞規約でフィルタする案を採る。
  スキーマ自体に overlay の種別（字幕/ロワーサード等）を区別するフィールドは
  ないため、将来的には `overlays[].kind` のような明示フィールドを edit.json v1 で
  検討してもよい（`notes-2026-07-13-edit-json-v1.md` 《legacy 参照》側の話題）
- **行の表示**: 開始タイムコード（`mm:ss`、§2 と同じフォーマット）+ 本文テキスト。
  本文はオーバーレイの `html` 断片からテキストコンテンツを抽出して表示する
  （リストは読み取り専用の表示であり、断片 HTML 自体は書き換えない）
- **クリックでシーク**: 行クリックで `engine.seek(overlay.start)` を呼ぶ
- **再生中ハイライト + 自動スクロール**:
  - 現在行 = `overlay.start <= t && t < overlay.start + overlay.duration` を満たす
    最後の要素（`tick(t, playing)` のたびに再計算）
  - 現在行の背景をアクセント色の薄い塗り（`rgba(255,139,44,0.15)`）にする
  - **再生中のみ**自動スクロール（`scrollIntoView({ block: "center", behavior:
    "smooth" })` など）。手動シーク直後や一時停止中は追従スクロールしない
- **空状態**: 対象オーバーレイが 0 件（動画単体ロード時、または edit.json に字幕が
  ない場合）は「字幕がありません」のプレースホルダを表示する
- **本ラウンド対象外と明記する項目**:
  - リスト内でのテキスト直接編集（ダブルクリック編集 → `overlay_write({ html })`)
  - タイミングの微調整（開始/終了の秒単位ナッジ）・分割/結合
  - 字幕の有効/無効チェックボックス、AI による一括整形（フィラー除去等）の UI
  - 上記はいずれも今回の要望には含まれないため後続ラウンドに送る

## 5. 全画面トグル

要望5。ウィンドウのクロム（信号機ボタン等）は残したまま、**プレビューペインだけを
拡大**する挙動とする。

> 全画面トグル自体（レイアウト切替クラス）はアプリシェル側の責務で本パッケージの
> 対象外。ただし全画面化・スプリッタ操作のたびに `#overlay-stage` の実表示矩形が
> 変わるため、`window.akari.stageScale()`（本パッケージが呼び出すホスト提供 API。
> `README.md` 参照）の再計算契約として関係する。

- **実装対象は OS のフルスクリーン API ではない**。`requestFullscreen()` や
  Tauri のネイティブウィンドウ全画面化ではなく、**アプリ内レイアウトの切替**
  （プレビューペインの幅を字幕パネル分まで広げる CSS クラストグル）
- **ボタン 1 個**: 上部バー右側、「⤢」アイコンのトグルボタン。enter/exit で
  別ボタンにしない（押すたびに拡大⇄復帰を切り替える）
- **切替内容**: 字幕リストパネルを非表示にし、プレビューペインが横幅いっぱいに広がる。
  **下部トランスポートバーは全画面プレビュー中も消さない**（要望2の「常設」と
  矛盾しないよう、この状態遷移でも生き残らせる）
- **状態非破壊**: トグルは純粋な CSS レイアウト変更。再生状態・選択中オーバーレイ・
  overlay-runtime のマウント状態には触れない（`unmount`/`mount` を呼び直さない）
- **永続化しない**: セッション内のみの表示状態。次回起動時は既定比率（§1）に戻る
  （必要なら後続ラウンドで localStorage 記憶を検討）

## 6. 書き出しボタン

要望4。本節は本パッケージの対象外（`src-tauri/src/export/` 《legacy 参照》・
IPC の話題）。legacy 参照として全文残す。

- **配置・見た目**: 上部バー右端、アクセント色で塗った目立つボタン。
  ラベルは「書き出し」
- **活性条件**: `state.editPath` が null（edit.json 未ロード）の間は無効化する
- **配線**: 既存 IPC・イベントをそのまま使う（今回新設しない）:
  - 実行: `engine.exportStart(editPath, outPath)` →
    `invoke("export_start", { editPath, outPath })`
  - 進捗: `export:progress` (`{ stage, pct }`) を購読
  - 完了: `export:done` (`{ out_path }`)、失敗: `export:error` (`{ message }`)
    （すべて `main.js` 《legacy 参照》に配線済み。現状は `#status` へテキスト表示するのみ）
- **進捗表示の格上げ**: 現状の `#status` 一行テキストから、半透明の暗幕 + 中央カードに
  進捗バー（`pct` を反映）+ 「書き出し中… {stage} {pct}%」という表示に格上げする。
  書き出し中は書き出しボタンを無効化し、二重起動を防ぐ。完了時はカードを閉じて
  ボタンを再度有効化、失敗時はエラーメッセージを表示して同様に再有効化する
- **出力先パス（`outPath`）— 現状実装から判断した結論**:
  現行コードには保存ダイアログの仕組みがない（`package.json` に
  `@tauri-apps/plugin-dialog` なし、`Cargo.toml` に `tauri-plugin-dialog` なし、
  `main.js` にもダイアログ呼び出しなし）。このラウンドで新規に Tauri プラグイン依存を
  足すのは影響範囲が読みにくいため見送り、**既定パス方式**にする:
  `edit.json と同じディレクトリ` に `<タイトルまたは元ファイル名>-export.mp4` を
  既定の出力先とする（拡張子は現状 M4 契約に形式選択 UI がないため `mp4` 固定でよい）。
  保存ダイアログ導入は今回のスコープ外とし、必要になった時点で
  `tauri-plugin-dialog`（Rust）+ `@tauri-apps/plugin-dialog`（JS）の追加を
  次ラウンドの申し送り事項とする
- **書き出し設定シート（解像度/形式/コーデック選択・書き出しプレビュー静止画・
  推定ファイルサイズ）は今回作らない**。ボタン 1 個 + 進捗表示のみに絞る
  （要望も「ちゃんと付ける」＝機能させる、が主眼）

## 7. 視覚語彙・トークン

新規に色や値を増やすのではなく、**現行実装が既に採用している値に統一**することを
基本方針にする。本パッケージが同梱する `src/interaction.css` / `src/minimap.css` は
このトークンに準拠済み。

- **アクセント色（最重要）**: `#ff8b2c` 系のオレンジ/アンバー。現行実装は既に
  2 箇所でほぼ同じ値を使っている:
  - `ui/style.css` `#demo-badge { background: rgba(255, 122, 26, 0.92); }`
    《legacy 参照 — `#demo-badge` 自体は本パッケージ対象外》
  - `ui/interaction.css` 選択枠 `rgba(255, 157, 66, 0.98)` / ハンドル `#ff8b2c`
    《legacy 参照 — 本パッケージでは `src/interaction.css` に同一の値で同梱》
  → この既存トークンに統一する（書き出しボタン背景、再生中の字幕リスト行ハイライト、
  シークバー進捗 capsule、全画面トグルの active 状態、拡縮ハンドルは全て同じ
  アクセントを参照）
- **背景（ダークテーマ）**: プレビュー側は黒基調。字幕リスト・上部バー・
  トランスポートの地色は暖色寄りの暗いグレー（`#18161a`〜`#1e1c1f` 目安）とし、
  純黒とは差をつける
- **パネル/浮遊要素の背景**: 本アプリの WebView は透明合成でネイティブ映像の上に
  乗るサンドイッチ構造（`ui/index.html` 《legacy 参照》冒頭コメント参照）。常時描画される UI 側は
  4K 表示時の GPU コストを避けるため `backdrop-filter: blur()` は使わず、**不透明に
  近い単色 rgba**（例: `rgba(24,22,26,0.92)`）で半透明パネルの見た目を作る。
  影は `box-shadow: 0 2px 8px rgba(0,0,0,0.18)` 程度の控えめな値にする
- **角丸スケール**: 用途別に整理する。リスト行・小ボタン=8px、中間ボタン類=9px、
  サムネイル/プレビュー角=10px、トランスポート/フローティングパネル=12〜14px、
  ドロップゾーン等の大きい面=16px
- **タイポグラフィ**: フォントスタックは現行 `style.css` 《legacy 参照》のまま
  （`"Hiragino Sans", "Noto Sans JP", system-ui, sans-serif`）。タイムコード等の
  数字は `font-variant-numeric: tabular-nums` で桁を揃える
- **選択枠・ハンドルの意匠**: 既存 `interaction.css`（本パッケージでは
  `src/interaction.css`）の値をそのまま維持
  （枠線 2px アクセント色、ハンドル直径 10px 白円+アクセント枠 1.5px+影
  `0 1px 4px rgba(0,0,0,0.7)`）

## 8. 実装への申し送り事項（本ラウンド外だが要注意）

- **プレビュー領域とネイティブ映像レイヤーの整合**: 本アプリは WebView 全体が
  透明でネイティブ映像レイヤーの上に乗る構造。プレビューを「可変・既定60%」の
  ペインに収めるには、ネイティブ映像の描画矩形（レイヤーのフレーム）を
  ウィンドウ全体ではなく**プレビューペインの矩形に追従**させる必要がある
  （左右スプリッタ・全画面トグルのたびに Rust 側へ矩形を伝える IPC が要る見込み）。
  M1/M4 のファイル所有権（`src-tauri/src/video_plane/`《legacy 参照》）に関わるため、
  この設計の詳細化は実装ラウンドの担当エージェントに委ねる
  （本パッケージの観点では、この矩形追従の結果が `window.akari.stageScale()` /
  `#overlay-stage` の scale() 貼り付けとして現れる — `README.md` 参照）
- **既存の左下フロートコントロール（`#controls`: 再生/一時停止/パス入力/読み込み/
  ステータス）の扱い**: 今回のレイアウトでは上部バー・下部トランスポートに機能が
  分散するため、素材の読み込み導線（パス入力・ドロップ）の置き場所は本書では
  確定していない。動画/edit.json の読み込みフロー自体の再設計は今回のスコープに
  含まれていないため対象外とし、実装時は「空状態のプレビューペインにドロップ受け+
  パス入力を残す」程度の最小変更で良い

## 追記（2026-07-14）— 映像ビューポート追従の実装後メモ

`video_set_viewport` IPC を実装済み（JS: #preview-pane の ResizeObserver + rAF デバウンス →
Rust: Y 反転のみの座標変換で AVPlayerLayer の view frame を設定。CSS 論理 px と AppKit
ポイントは 1:1 のため backing scale factor は掛けない — 回帰テストで固定）。

**残課題**: `AVLayerVideoGravityResizeAspect` により、ペインと素材のアスペクト比が
異なるときは映像がペイン内でレターボックス/ピラーボックスされる。オーバーレイ座標は
ペイン全体基準のため、映像の実表示矩形とピクセル一致を前提にした素材は比率が合わない
ウィンドウでずれる。対策候補: 映像の実表示矩形を JS へ通知して #overlay-stage を
その矩形に一致させる（M1 の薄いインターフェースに「表示矩形通知」を足す）。次ラウンド判断。

**解消**（2026-07-14 追記）: 上記の残課題は後続 2 ラウンドで解消済み。オーバーレイ座標系は
output 基準に統一され（コミット 544476f「実機バグ4件 — 映像遮蔽・透過スプリッタ・
オーバーレイ座標系・書き出し不能」）、プレビューの `#overlay-stage` は output 解像度の
