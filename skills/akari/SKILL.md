# Start or resume AKARI Video

> **Language**: Respond in the user's language — conversation, questions, approval prompts, and the reports and records you write (including decision-log rows) follow the language the user writes in.

The library defaults to the workspace's `library/`. Without a workspace, use the legacy `~/.akari/assets/`.
Check the first line of `akari-assets list` (or `akari assets list`) for the actual location.
Below, `<ライブラリの置き場>` is the existing library-location placeholder; audio belongs in its `audio/` subdirectory.

This entry point handles only the following 3 branches. Do not duplicate the main skills' procedures here.
Use the `akari` CLI on PATH. If unavailable, use
`node "${AKARI_HOME:-$HOME/.akari}/app/packages/akari-launcher/bin/akari.mjs"`;
if that is also unavailable, run `packages/akari-launcher/bin/akari.mjs` from an actual repository checkout with
`node`. If none exists, explain what is missing and stop; do not invent paths.

## Recommend a playbook

Recommend at most twice: when starting a project and immediately after the user places new source material.
Read `.akari/intake.json` and available `analysis.json` records for target duration, format, speakers, and media kinds.
Run `akari playbook list --json` (add `--channel <name>` for the current channel). Compare each entry's
`category`, `tags` (especially `form`, `length`, and `materials`), and `requires` with that evidence.
Rank up to three matches and explain the concrete evidence for each in chat. For example, portrait source
material and a target of 60 seconds or less favor vertical explainers or short dramas; a talking head plus
screen capture favors an explainer; music-led footage favors an MV. A missing required tool lowers the rank
and must be mentioned. Link to the playbook's review sheet path when one exists, or state that
`.akari/reports/playbook-apply.html` will be generated by applying it. Never apply a recommendation
automatically. After the user chooses, run `akari playbook apply <id> --into <project>`.

## Resume

1. Search for `.akari/` from cwd up through its ancestors. Call the discovered project `<project>`.
   A `.akari/root.json` with `schema: "creator-root/v1"` marks a workspace, not a video project.
   If only a workspace is found, proceed to Create or Open according to the request.
2. Run `akari status "$PWD" --json`. Use `next_skill` / `waiting_on` to explain
   the next action in 1–2 sentences. Report failure or `state_health: inconclusive` as unavailable state;
   do not infer the workflow stage from fragments of files.
3. If `next_skill` is present, **read directly by path**:
   `<project>/.claude/skills/<next_skill>/SKILL.md`. If absent, report the missing file rather than inventing a procedure.
   If `waiting_on` is present, explain that action without skipping the main skill's wait conditions.

## Create

Use when `.akari/` is absent or a new project is explicitly requested. The legacy matcher
`新規作成を明示された場合` denotes an explicit request for a new project.

Even if no workspace exists, **do not create one without the user's consent** (propose → consent → create).
The machine-matched cue `利用者の同意なしに作成しない` means that creation requires the user's consent.

1. Detect a workspace through these 2 routes (either is sufficient).
   - Check whether `lastRoot` in `<AKARI_HOME>/creator-root.json`
     (default: `~/.akari/creator-root.json`) exists.
   - Search from cwd through its ancestors for `.akari/root.json`,
     and verify that `schema` is `"creator-root/v1"`.
   Read the discovered workspace's marker too. Report damaged JSON or unknown schemas without overwriting them.
   Before asking where to create the project, infer the content language from the user's conversation and source
   audio, independently of the UI language. If they appear to disagree, include a content-language choice in the
   question in step 2 so the user can settle both the destination and language in one reply.
2. Ask **only 1 question**: “Create this in the workspace `~/Akari/`, or in this folder?
   If there is no workspace, I will create it with `akari init`.”
   If an existing workspace was found, replace `~/Akari/` with its actual path.
   Include the specific destination for the workspace option in the same question:
   `<作業場>/channels/<channel>/videos/<日付-スラッグ>/` (the existing workspace/date-slug placeholders).
   Use the first entry in `root.json`'s `channels` as `<channel>`, or `my-channel` if absent.
   Suggest a short slug from the date and request; propose a different name if a project already has that name.
   If this folder is selected, `<target>` is cwd.
3. After consent, run `akari init` only if the workspace was selected and does not yet exist.
   Its no-argument ensure operation is idempotent: if a workspace exists, stdout's first line returns its path.
   If that differs from the approved location, do not create somewhere else on your own.
4. Before creation, use the selected content language; an explicit choice takes precedence over the inference.
   Run `akari new "<target>"`, adding the --lang option with the BCP 47 code if available.
   Otherwise write the code to intake.json's language field after creation. Let the CLI add only missing files
   without overwriting existing ones and enforce the F18 guard against git init inside an existing repository.
   Main skills remain physical copies; `AKARI-SKILLS-VERSION` records their version at creation.
   Resolve in order: explicit --lang → intake.json language → analysis.json transcript.language → ja.
   Use the primary language subtag for pack selection (en-US → en); preserve ja and use en for a missing pack.
5. Explain the creation report path printed to stdout and that `edit-plan` is next,
   then **read directly by path**: `<target>/.claude/skills/edit-plan/SKILL.md`.
   Skills created during a session may not appear in discovery. They will appear when the agent is started
   in that project next time, so read them directly in this session.

The 1 question above also obtains consent. Do not ask again if the destination has already been explicitly approved.
If the CLI cannot run, manual workspace-only creation is limited to the approved location. Create
`akari.md`, `channels/<channel>/videos/`, `library/`, `inbox/`,
`.akari/memory/`, and `.akari/cache/`.
Use this stub for `akari.md`:

```markdown
# akari.md

この作業場（CreatorRoot）の規約・好みを書く場所です。
AKARI Video のエージェントは動画を作る前に、まずこのファイルを読みます。

## 好み

（まだ何も書かれていません）
```

Always follow these 2 rules for manual creation.

1. **Never overwrite any existing file**. If `root.json` or `akari.md` exists, do not write it; return to detection.
   The machine-matched cue `既存ファイルを一切上書きしない` states this same no-overwrite rule.
2. **Write `root.json` last**. Place the workspace marker only after all directories and `akari.md` are complete.
   The machine-matched cue `` `root.json` は最後に書く`` states the ordering rule.

Set `.akari/root.json` to
`{"schema":"creator-root/v1","createdAt":<ISO8601>,"channels":[<channel>]}`.
Do not write `<AKARI_HOME>/creator-root.json` in the fallback.
Do not claim project creation is complete without the CLI; report the missing `akari new`.

## Open

Use only the detection procedure from Create to find the workspace. List existing project directories under
`<作業場>/channels/*/videos/*` (the existing workspace placeholder) and let the user choose.
If none exists, explain that and point to Create.
Set cwd to the selected project and proceed to Resume. Do not create a workspace during a read-only action.
