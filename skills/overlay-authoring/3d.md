# Three.js + glTF authoring

## 経路の振り分け（まずここを判定）

本スキルの対象は**映像の上に重なるオーバーレイ 3D**（経路 A）だけ。3D シーンを動かして
**映像素材（クリップ）そのもの**を作る用途（経路 B）はオーバーレイでやらない —
Blender ヘッドレスで焼き込む。契約: `docs/contract-2026-07-14-3d-bake-recipe.md`。
判定基準: タイムラインにクリップとして置くなら B、映像の上に重ねるなら A。

## 現在の実装ゲート

live preview v0 は、fragment 内の非実行 JSON 宣言を信頼済みランタイムが読み、
ローカル `.glb` の静的シーンと内蔵 animation clip を描画できる。fragment の任意
JavaScript は実行しない。モデルは edit.json 相対パスから preview 専用 localhost
asset URL へ変換され、Three.js core と GLTFLoader は pinned IIFE として同梱される。

export（render-cut）は同じ Three.js runtime を puppeteer-core 経路で動かし、ローカル
`.glb` を自己完結 data URI として埋め込んで 3D overlay を焼き込む。

根拠: `packages/overlay-runtime/src/overlay-runtime.js`、
`packages/overlay-runtime/src/three-runtime.js`、[WHATWG HTML — scripting](https://html.spec.whatwg.org/dev/scripting.html)

## 宣言型 fragment スキーマ（preview v0）

fragment は単一ルートとし、透明 canvas、任意の静的 fallback、非実行の
`<script type="application/json" data-akari-3d-scene>` を 1 個だけ置く。

```html
<div class="product-spin">
  <canvas class="product-spin__canvas"></canvas>
  <div data-akari-3d-fallback>3D を読み込み中</div>
  <script type="application/json" data-akari-3d-scene>
  {
    "model": "assets/models/product.glb",
    "camera": {
      "position": [0, 1.2, 3],
      "fov": 45,
      "near": 0.1,
      "far": 100,
      "lookAt": [0, 0.5, 0]
    },
    "lights": [
      { "type": "ambient", "color": "#ffffff", "intensity": 0.35 },
      {
        "type": "directional",
        "color": "#ffffff",
        "position": [2, 3, 2],
        "lookAt": [0, 0.5, 0],
        "intensity": 1.2
      }
    ],
    "animationClip": "Idle"
  }
  </script>
</div>
```

- top-level key は `model` / `camera` / `lights` / `animationClip` だけ。
- `model` は edit.json のあるディレクトリからの相対 `.glb` パス。URL や CDN を書かない。
- camera は perspective camera。`position` / `lookAt` は `[x, y, z]`、`fov` / `near` / `far` は数値。
- light type は `ambient` または `directional`。directional は `position` と `lookAt` を宣言できる。
- `animationClip` は glTF 内蔵 clip の正確な名前。省略時は静的シーンを描画する。
- canvas は CSS で表示寸法を必ず与える。fallback に `data-akari-3d-fallback` を付けると load 完了時だけ隠れる。fallback は自由にスタイルしてよく、`display` を宣言しても load 完了時にランタイムが確実に隠す。

## 原則

- 3D は Three.js、交換形式は glTF 系に限定する。preview v0 は外部 buffer/texture と Draco/KTX2 を持たない自己完結 `.glb` だけを受け付ける。
- Three.js 本体、addon、decoder、model、texture はローカルへ固定し、CDN import を使わない。export Chrome は background network を無効化する。
- fragment は上記の宣言型スキーマに限定する。任意 script、event handler、`new Function()` 等を使わない。
- 単一ルート内へ透明 canvas と静的 fallback を置く。canvas は透明合成を有効にし、背景を不透明に塗りつぶさない。
- asset は visible な期間だけ load / render / decode され、区間外と unmount で geometry、material、texture、renderer が解放される。
- camera、light、model pose、material、screen source を CSS 変数または素材 metadata の knob として宣言する。固定すべき model topology まで knob にしない。

## ライセンス済み glb

1. 配布元、asset ID / version、author、取得日、license、商用可否、改変可否、帰属表示を確認する。
2. glTF 形式であることを利用許諾と取り違えない。license 不明の model は使わない。
3. library からリンクせず、採用する project へ `.glb` と必要 texture / decoder をコピーする。
4. project 側 provenance に元 library、version、license、attribution を残す。
5. 相対 URL で読み込み、load error 時に空 canvas のまま成功扱いしない。

素材ライブラリ利用時のコピー規律は `docs/contract-2026-07-13-asset-library.md` に従う。

## 決定的な 3D アニメーション

- preview v0 は overlay の local timeline 秒を `AnimationMixer.setTime(localSeconds)` に渡し、その状態だけを render する。
- `THREE.Clock` や `mixer.update(delta)` で時間を積算しない。カメラ、shader time、particle も同じ local timeline から求める。
- rAF は算出済みの時刻を描画するためだけに使い、rAF delta を状態へ足さない。
- glTF clip がない動きも、local time の関数として pose を求める。再生・停止・逆シークで同じ結果になることを確認する。

公式: [Three.js AnimationMixer.setTime](https://threejs.org/docs/pages/AnimationMixer.html#setTime)

## VideoTexture

- `VideoTexture` の source は HTMLVideoElement とし、**編集用 720p プロキシ**を与える。原本を preview 用 texture へ接続しない。
- `source.proxy` の自動生成は現時点で未実装である。proxy がなければ先に生成し、ないまま原本へ黙って fallback しない。
- `<video>.currentTime` を overlay local timeline へ同期してから texture を更新する。autoplay / loop の wall-clock 再生へ任せない。
- 現行 preview / export は `<video>.currentTime` を同期しないため、動画 texture は **未対応** とする。
- source の寸法・format を変える場合は既存 texture を dispose し、作り直す。

公式: [Three.js VideoTexture](https://threejs.org/docs/pages/VideoTexture.html)

## パフォーマンス

- 4K 上の post-process blur、`filter: blur()`、`backdrop-filter`、過剰な shadow を使わない。
- 毎フレームの object / material / texture 生成、shader compile、model reload を避ける。
- preview v0 と export の renderer pixel ratio は `1` 固定。同一 scene の見え方を対象出力 profile で実測する。
- `renderer.info` で draw calls、triangles、textures を計測する。固定の polygon / draw-call 上限は一次根拠がないため発明せず、対象 Mac と出力 profile で **要検証** とする。

公式:

- [Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)
- [Three.js — How to dispose of objects](https://threejs.org/manual/en/how-to-dispose-of-objects.html)

## よくある間違い

- CDN の Three.js、decoder、texture に依存する。
- Draco / KTX2 圧縮モデルを v0 へ渡す（decoder と worker は未対応）。
- license 不明の `.glb` を「ネットで見つけた素材」として同梱する。
- JSON 宣言の代わりに fragment 内の `<script>` を実行させようとする。
- export だけを見て WYSIWYG 対応済みと報告する。
- proxy がないため原本を `VideoTexture` へ流す。
- `Clock.getDelta()` / `mixer.update(delta)` でアニメーションする。
- 非表示後も render loop と video decode を動かす。
- dispose せず、素材切替のたびに GPU resource を残す。
