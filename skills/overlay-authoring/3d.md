# Three.js + glTF authoring

## 経路の振り分け（まずここを判定）

**既定は経路 A（Three.js オーバーレイ）**。経路 B（Blender ベイク、`docs/contract-2026-07-14-3d-bake-recipe.md`）は
A で出せない絵が要るときだけ選ぶ。「タイムラインにクリップとして置きたいから B」は**誤り** —
置き場所ではなく**必要な能力**で選ぶ。

A を既定にする理由（2026-08-04 の実制作で確認）:

- **透過で合成される**。B の出力は不透明な背景を必ず連れてくるので、背景色を合わせ続ける仕事が発生する
  （実際に「なぜ背景が灰色なのか」という手戻りを生んだ）
- **反復が速い**。断片を直して再レンダーで済む（数分）。B は焼き直しに 10 分級かかる
- **画面に映像を流せる**。`materialOverrides` に mp4 を差せば端末画面が動く
- **自作モーションも動く**。Blender で作ったアニメクリップを glb に焼いておけば `animationClip` で再生できる
  （開閉・一周スピン等はこれで足りる。B に逃げる理由にならない）

B を選ぶのは次のいずれかに当てはまるときだけ:

1. **宣言型ランタイムで表現できない絵**が要る — 被写界深度、モーションブラー、レイトレース反射、
   GI、パーティクル、複雑なシェーダ
2. **同時に出す 3D シーンが 3 枚以上**になり、書き出しの性能予算（後述「書き出しが timeout で落ちるとき」）を
   超える。一部を焼いてクリップ化し、同時枚数を 2 枚以下へ落とす
3. 素材ライブラリへ**再利用可能なクリップとして納品**する（レシピ = SSOT の資産にする）

判断に迷ったら A で試す。行き詰まってから B へ落とす方が、B で作り直すより速い。

## 現在の実装ゲート

live preview v0 は、fragment 内の非実行 JSON 宣言を信頼済みランタイムが読み、
ローカル `.glb` の静的シーンと内蔵 animation clip を描画できる。fragment の任意
JavaScript は実行しない。モデルは edit.json 相対パスから preview 専用 localhost
asset URL へ変換され、Three.js core と GLTFLoader は pinned IIFE として同梱される。

export（render-cut）は同じ Three.js runtime を GPU / OSR 経路で動かし、ローカル
`.glb` を自己完結 data URI として埋め込んで 3D overlay を焼き込む。動画 texture・環境マップ画像も
同じく data URI として埋め込む。

export は **動画をフレーム精度でシークし、提示フレームが確定してから 3D を描く**。この順序が
逆だと `<video>` が 1 フレーム前の絵のまま texture へ上がる（実測: 旧順序は全フレームが
ちょうど 1 コマ遅れる）。

根拠: `packages/overlay-runtime/src/overlay-runtime.js`、
`packages/overlay-runtime/src/three-runtime.js`、[WHATWG HTML — scripting](https://html.spec.whatwg.org/dev/scripting.html)

## 宣言型 fragment スキーマ（preview v0）

fragment は単一ルートとし、透明 canvas、任意の静的 fallback、非実行の
`<script type="application/json" data-akari-3d-scene>` を 1 個だけ置く。

```html
<div class="product-spin">
  <canvas class="product-spin__canvas"></canvas>
  <div data-akari-3d-fallback>3D を読み込み中</div>
  <script type="application/json" data-akari-3d-scene>
  {
    "model": "assets/models/product.glb",
    "camera": {
      "position": [0, 1.2, 3],
      "fov": 45,
      "near": 0.1,
      "far": 100,
      "lookAt": [0, 0.5, 0]
    },
    "environment": {
      "intensity": 1.0,
      "exposure": 1.0,
      "map": "assets/env/studio.png"
    },
    "shadows": true,
    "lights": [
      { "type": "ambient", "color": "#ffffff", "intensity": 0.35 },
      {
        "type": "directional",
        "color": "#ffffff",
        "position": [2, 3, 2],
        "lookAt": [0, 0.5, 0],
        "intensity": 1.2
      }
    ],
    "materialOverrides": {
      "ScreenMaterial": { "texture": "assets/screens/app-01.png" }
    },
    "animationClip": "Idle"
  }
  </script>
</div>
```

- top-level key は `model` / `camera` / `environment` / `lights` / `animationClip` / `materialOverrides` / `shadows` / `texts` / `physics` だけ。`texts[]` があれば `model` は任意（詳細は後述「texts[] — 3D テキスト」節）。`physics` は `texts[]` の物理落下（後述「physics — 3D テキストの物理落下」節）。
- `model` は edit.json のあるディレクトリからの相対 `.glb` パス。URL や CDN を書かない。
- camera は perspective camera。`position` / `lookAt` は `[x, y, z]`、`fov` / `near` / `far` は数値。
  または `{ "fromModel": "<glb 内カメラノード名>" }` で glb 内カメラを描画に使う（§カメラを動かす）。
- `environment` は IBL の knob。`intensity` は金属など PBR マテリアルへの環境光強度、
  `exposure` は ACES Filmic tone mapping の露出で、どちらも 0 以上の数値を指定する。省略時は
  `intensity` は `0.5`、`exposure` は `1.0`。まず既定値で
  確認し、白飛びを抑えるなら `exposure`、映り込み自体の強弱を変えるなら `intensity` を小幅に調整する。
  IBL 自体（既定値での環境マップ・トーンマッピング）は preview / export とも常に有効 — `environment`
  キーは既定値からの微調整用の任意 knob。
- **金属マテリアルは environment の映り込みでしか色が出ない。** 暗い場合は
  `environment: { "intensity": ..., "exposure": ... }` を明示する。既定 intensity 0.5 + ACES では宣言色より大きく沈む。
- `environment.map` は**正距円筒（equirectangular）画像の相対パス**。宣言すると既定の手続き生成
  `RoomEnvironment` を差し替える。金属は環境の映り込みでしか見えないので、光源に「形」が要る
  ヒーローカットではこれが効く（既定の部屋は強度スカラーしか触れず、側面レールが黒く沈む）。
  画像形式のみで動画は受け付けない。読み込みは load 完了まで待ってから ready になるので、
  「既定の部屋のまま焼ける」ことはない。**環境光の強度を上げて材質の不足を埋め合わせないこと** —
  副作用（画面の白濁・彩度飛び・白飛び）が離れた場所に出る。
- `shadows` は真偽値、または `{ "enabled": true, "mapSize": 2048, "bias": …, "normalBias": … }`。
  **既定は無効**（既存素材の見え方を変えないため、素材側で明示的に宣言する）。有効にすると
  shadow map を立て、メッシュへ cast / receive を、`directional` ライトへ影の投射を配線する。
  shadow camera はモデルの実寸（bounding sphere）へ自動で畳むので、数 cm の被写体でも影が出る。
  `bias` / `normalBias` の既定も実寸から決まるため、通常は宣言しなくてよい。
  **自発光マテリアルのメッシュは cast / receive の対象から外れる**（光源側の扱い。発光体が
  自分の影で汚れるのを避ける）。
- light type は `ambient` または `directional`。directional は `position` と `lookAt` を宣言できる。
- `animationClip` は glTF 内蔵 clip の正確な名前。**clip 名の配列**、または全 clip を同時再生する
  `"*"` も指定できる。省略時は静的シーンを描画する。Blender の glTF 書き出しはオブジェクトごとに
  clip を分けるので、1 個のモデルに複数の動きがあるときは `"*"` で束ねる（1 本しか再生しないと
  片方しか動かない）。存在しない clip 名を書いた場合はエラーになる。
- `materialOverrides` は `{ "<material 名>": { "texture": "<画像または動画の相対パス>" } }` の形で、名前が一致するマテリアルの `emissiveMap` を差し替える。**差し替え先が `emissiveMap` である以上、貼り先の材質が発光しない（glTF の `emissiveFactor` が未設定 = 黒）と「0 × テクスチャ」で何も出ない**（2026-08-14 実害。詳細は後述「発光しない材質には貼れない」）。edit.json のあるディレクトリからの相対 PNG / JPEG / WebP 等、または MP4 / MOV / WebM を指定し、URL や CDN を書かない。該当するマテリアル名がモデル内にない場合は警告して無視される。
  - **パスは「edit.json のあるディレクトリ」から。断片の場所からの相対ではない。** `model` も同様。
    断片を `overlays/3d-phone/fragment.html` へ置いたなら `"overlays/3d-phone/model.glb"` と書く
    （`"model.glb"` はプロジェクト直下を探して ENOENT になる）。
  - **貼っても真っ黒 / 何も変わらないときの 2 大原因**（2026-08-04 実測）:
    (1) 対象メッシュに **UV が無い**。glTF の `TEXCOORD_0` が無いメッシュにはテクスチャが乗らない。
    Blender で uv_layers を新規作成して平面投影してから再エクスポートする。
    (2) 差し替え先は `emissiveMap` なので、**マテリアルの emissive が黒（既定）だと結果も黒**。
    glb 側で emissiveFactor を白・Emission Strength を 1.0 にしておく。
- canvas は CSS で表示寸法を必ず与える。fallback に `data-akari-3d-fallback` を付けると load 完了時だけ隠れる。fallback は自由にスタイルしてよく、`display` を宣言しても load 完了時にランタイムが確実に隠す。
- canvas またはその容器へ CSS `rotate()` を掛けてもよい。カメラの aspect は回転後の外接矩形ではなく
  `offsetWidth` / `offsetHeight`（fallback は `clientWidth` / `clientHeight`）から決まるため、
  回転で投影が縦横に歪むことはなく、回転用の回避策は不要。

## texts[] — 3D テキスト（flat / extrude。2026-08-12 導入。contract-2026-08-12-3d-text-rail.md）

`data-akari-3d-scene` に `texts[]` を足すと、troika-three-text（SDF 平面文字）で per-char に
分解した 3D テロップを宣言だけで出せる。**`texts[]` があれば `model` は任意**（glb 小物と
3D テキストは同一シーンに併存できる。1 断片 = 1 宣言の原則は変えない）。

```jsonc
<script type="application/json" data-akari-3d-scene>
{
  "texts": [{
    "id": "title",
    "text": "立体テロップ",
    "window": { "start": 2.0, "duration": 5.0 },
    "mode": "flat",
    "size": 0.8,
    "color": "#ffd166",
    "material": { "doubleSide": true },
    "layout": {
      "type": "line",
      "spacing": 0.78,
      "position": [0, 0, 0],
      "rotation": [0, 0.9, 0]
    },
    "anim": {
      "preset": "char-chaos",
      "speed": 1.0,
      "stagger": 0.055,
      "amplitude": 1.0,
      "seed": 42
    }
  }]
}
</script>
```

- `texts[].id` は宣言内で一意な文字列。`text` は表示文字列（1 文字ずつ独立した troika `Text`
  に分解される。空白も含め全 char が展開対象で、レイアウトの並び順は `text` の文字順そのまま）。
- `window` は任意の `{ "start": 0 以上, "duration": 正数 }`（クリップ先頭を 0 とするローカル秒）。
  可視区間は半開区間 `[start, start + duration)` で、窓外では文字ブロックを描画しない。
  省略時はクリップ全尺に表示される。`anim.preset` の時刻は窓の先頭を 0 秒として進み、`physics`
  対象も窓の先頭から落下を開始する。
- `font` は任意。明示する場合は `model` と同じ相対パス解決規則（edit.json のあるディレクトリからの
  相対 `.ttf`/`.otf`。URL・CDN は書かない）。省略時はホストが
  `window.akari.threeRuntime.configure({ defaultFontUrl })` で注入した Zen Kaku Gothic New Black
  （`packages/overlay-runtime/test-harness/fonts/`、OFL）を使う。preview-server は
  `/__akari/fonts/zen-kaku-gothic-new-black.ttf` から静的配信し、render-cut は同じ実体を data URI
  としてシートへ埋め込む。未設定のホストで `font` を省略すると日本語の明示エラーになる。
- `mode` は `"flat"`（troika SDF 平面。既定）または `"extrude"`（opentype.js 輪郭 →
  `ExtrudeGeometry` の押し出し文字。次々節「extrude モード」）。
- `size` は troika `fontSize` 相当・extrude では opentype の em サイズ相当（共に既定 `0.5`）。
  `color` は CSS 色文字列（既定 `#ffffff`）。
- `material` は `metalness` / `roughness` / `doubleSide` を宣言できる。**flat の既定は unlit
  `MeshBasicMaterial` + `DoubleSide`**（光源なしでも常に読める）。`metalness` か `roughness` の
  どちらかを明示すると `MeshStandardMaterial` に切り替わり、シーンの `lights[]` を受けて陰影が付く。
  `doubleSide: false` にすると裏面カリングが有効になり、筒配置の奥側の文字が消える。
  （extrude は常に `MeshStandardMaterial` で `doubleSide` は読まない。次々節）
- `layout.type` は `"line"`（既定。`spacing` で中央寄せに 1 列並べる）または `"cylinder"`
  （`radius` の円周上へ文字数で等分配置、外向きに回転）。`position` / `rotation` はテキスト
  ブロック全体（全 char の親グループ）の配置で、`rotation.y` を振ると「台形パース」
  （右奥へ消える遠近）になる — corner-pin と違い文字単位で正しい遠近が出る。**flat / extrude
  共通の同一コードパス**（`charBasePosition`）で解決するので、モードを切り替えても
  `layout` の意味は変わらない。
- `anim.preset` は 5 種（**flat / extrude 共通の同一コードパス**。`char-chaos` の減光は
  extrude では char ごとに複製したマテリアルの `opacity` へブリッジして効かせている）:
  | preset | 見え方 |
  |---|---|
  | `none` | 静止（既定） |
  | `carousel` | テキストブロック全体が Y 軸回転（`layout.type: "cylinder"` と組むと筒テロップ） |
  | `char-chaos` | 1 文字ずつ独立した回転・上下ウォブル・奥行き揺れ・ちらつき減光 |
  | `flip-wave` | 左から右へ 1 文字ずつ 360° 回転が伝播するフリップ波 |
  | `tumble` | 1 文字ずつ別々の軸・速度でタンブリング |

  `speed`（時間スケール）・`stagger`（char index ごとの位相オフセット）・`amplitude`
  （振幅スケール）で調整する。**`preset` が `"none"` 以外のとき `seed` は必須**（次節）。

### extrude モード（本物の厚みの押し出し文字。2026-08-12 導入。T3）

`mode: "extrude"` にすると、opentype.js（`window.AkariThree.opentype`）でグリフの輪郭を抽出し、
`THREE.ShapePath` → `toShapes(false)` → `ExtrudeGeometry`（押し出し + ベベル）で「本物の厚みの
ある 3D 文字」を描く。ヒーロータイトル向け — 量産テロップは軽い flat を使う（下表）。

```jsonc
"texts": [{
  "id": "title",
  "text": "立体テロップ",
  "font": "fonts/zen-kaku-gothic-new-black.ttf",
  "mode": "extrude",
  "size": 0.85,
  "color": "#ffd166",
  "material": { "metalness": 0.9, "roughness": 0.25 },
  "extrude": { "depth": 0.3, "bevelSize": 0.028, "bevelThickness": 0.04 },
  "layout": { "type": "line", "spacing": 0.92 },
  "anim": { "preset": "carousel", "speed": 0.5, "seed": 7 }
}]
```

- `extrude.depth` / `bevelSize` / `bevelThickness` の既定はそれぞれ `0.3` / `0.028` / `0.04`
  （上記例と同じ値。省略可）。`bevelSegments`（2）・`curveSegments`（6）は固定でツマミ化していない。
- **`toShapes(false)` 固定** — `true` にすると「プ」のような半濁点付きグリフの穴が 2 つに化ける
  （PoC 実測）。これは実装の内部固定値でツマミではない。
- **マテリアルは常に `MeshStandardMaterial`**（`metalness` 既定 `0`・`roughness` 既定 `1`）。
  flat と違い unlit フォールバックが無い（厚み・ベベルは陰影が無いと見えないため）。
  `material.doubleSide` は宣言できても無視する（ソリッドな閉じたメッシュに裏面カリングは無意味）。
- **無灯の事故防止**: シーンに `lights[]` も `environment` も**どちらも未宣言**のときだけ、
  extrude テキストがあればランタイムが弱いデフォルトライト（ambient 0.25 + directional 2.0,
  `position: [3, 5, 4]`）を自動で足す。`lights[]` か `environment` のどちらかでも宣言すると
  デフォルトは足さない（宣言を尊重する）。狙った陰影が欲しいときは `lights[]` を明示すること。
- **グリフ形状・ジオメトリはキャッシュする**（`font+char+size+depth+bevelSize+bevelThickness`
  キー）。同じ文字が同じシーン内で複数回出てきても再三角形分割しない。キャッシュは mount された
  インスタンスの寿命に閉じる（unmount で解放。他インスタンスとは共有しない）。
- 生成は mount 時のみの同期処理（opentype のフォント解析だけが非同期）。`draw(localSeconds)`
  は flat と同じく純関数のまま — 決定論・シーク安全の不変条件は変わらない。

**flat と extrude の使い分け**:

| | flat | extrude |
|---|---|---|
| 実体 | troika SDF（薄い平面） | opentype 輪郭の押し出しメッシュ |
| 厚み・ベベル | 無し | 有り |
| 既定マテリアル | unlit（光源不要） | lit（`MeshStandardMaterial` 固定） |
| 向き | 量産テロップ・筒配置・多文字 | ヒーロータイトル・少文字・金属/陰影表現 |
| 相対コスト | 軽い | per-char に triangle mesh を持つぶん重い（8 文字目安が快適の目安。§検証） |

### 決定論（texts[] 固有の注意）

`texts[].anim` は既存の「render は localSeconds の純関数」原則（後述「決定的な 3D
アニメーション」節）をそのまま継承する。実装上の要点:

- per-char の「ばらつき」は mount 時に `anim.seed` から生成する決定論的な定数表（sin ハッシュ、
  `Math.random` ではない）のみに由来する。`draw(localSeconds)` は毎回この定数表 + 三角関数の
  合成だけを計算し、フレーム間の状態を一切持たない — 同じ `localSeconds` を何度呼んでも、
  どの順で呼んでも同じ姿勢になる（シーク安全・書き出しの SHA-256 一致の根拠）
- `window` を宣言した文字は `localSeconds - window.start` をアニメーションと physics lookup の
  時刻に使う。窓前の逆シークは 0 秒へクランプされ、窓外の可視性も同じ半開区間判定だけで決まる
- `sync()`（troika のグリフ確定）の完了は 3D シーンの ready 条件に含まれる。読み込み中の
  空 SDF フレームが書き出しへ混入することはない
- **グリフ欠落（絵文字等、フォントに無い文字）でも外部ネットワークへは出ない**。troika-three-text
  はグリフ欠落時に `cdn.jsdelivr.net`（unicode-font-resolver）へフォールバックフォントを
  動的取得しにいく経路を持つが、ランタイムはこの CDN 宛の `fetch()` だけを狙い撃ちで遮断する
  （`unicodeFontsURL` 設定では「取得先」しか変えられず「取得するかどうか」自体は変えられない
  ため、fetch レベルで塞いでいる — `three-runtime.js` の `disableTroikaUnicodeFontFallback`）。
  欠落グリフは豆腐（不描画）になるだけで、書き出しは黙って続行する
- extrude は opentype.js が `texts[].font` を自前で `fetch()` して解析する（troika の XHR 読み込みとは
  別経路）。書き出し時は `rasterize.mjs` の `embedThreeModels` が `font` を data URI へ埋め込む
  （flat と共通のロジック）ため、この `fetch()` は data: へ解決され外部到達は発生しない

## physics — 3D テキストの物理落下（2026-08-12 導入。contract-2026-08-12-3d-text-rail.md）

`data-akari-3d-scene` に `physics` を足すと、`texts[]` の対象文字が重力で落ちて collider
（床・壁・円・多角形）に当たって跳ねる演出が宣言だけで出せる。方式は
**`createInstance()` 時に matter-js を `seed`・固定 `dt` で `duration` 分だけ事前シミュレーション
し、per-char の (x, y, angle) を Float32Array キーフレームバッファへ焼く**。
`draw(localSeconds)` はこのバッファのクランプ付き線形補間 lookup だけを行う — 前節の
texts[] anim と同じ「render は localSeconds の純関数」原則をそのまま満たす。

```jsonc
<script type="application/json" data-akari-3d-scene>
{
  "texts": [{
    "id": "fall",
    "text": "物理落下テスト",
    "font": "fonts/zen-kaku-gothic-new-black.ttf",
    "mode": "flat",
    "size": 0.5
  }],
  "physics": {
    "enabled": true,
    "seed": 7,
    "duration": 6.0,
    "dt": 0.008333,
    "gravity": [0, -1],
    "restitution": 0.35,
    "targets": ["fall"],
    "colliders": [
      { "type": "floor", "y": -2.6 },
      { "type": "wall", "x": 5.6 }, { "type": "wall", "x": -5.6 },
      { "type": "circle", "center": [1.7, -0.05], "r": 0.62 },
      { "type": "polygon", "points": [[-1.3,-2.6],[1.3,-2.6],[0.85,-0.9],[-0.85,-0.9]] }
    ]
  }
}
</script>
```

- `enabled`: 省略時 `true`（`physics` を書いた時点で有効。`false` で一時的に無効化できる —
  宣言は残したまま演出だけ切りたいときに使う）。
- `seed`（**必須**）: presim の初期配置（位置・角度・角速度）を決める疑似乱数の種。
  `Math.random`・壁時計は一切使わない。**seed ガチャ**（同じシーンで `seed` だけ変えて
  何パターンか presim し、見た目が気に入ったものを選ぶ）が実質的な調整手段になる —
  文字ごとの落下軌道を直接指定する API は無いため、狙った絵に近づけるには seed を振って
  試すのが早い。
- `duration`（**必須**）: presim を回す秒数。**オーバーレイの `duration`（timeline 上の尺）
  以上を推奨**。presim 秒数がオーバーレイの尺より短いと、尺の終盤は `duration` 時点の
  姿勢でクランプされたまま静止する（バッファの最終フレームを保持し続ける — エラーにはならない
  が、意図せず「途中で固まる」ように見えることがある）。
- `dt`: 固定タイムステップ（既定 `1/120`）。値を大きくすると presim は速くなるが精度が落ちる。
- `gravity`: `[x, y]`（既定 `[0, -1]`）。`camera`/`lights` と同じ scene 空間・y-up。
- `restitution`: 反発係数（既定 `0.45`）。0 に近いほど跳ねずに沈む、1 に近いほどよく弾む。
- `targets`: 物理対象にする `texts[].id` の配列（**必須・非空**）。対象文字は
  `layout.position`/`layout.rotation` を無視し、`colliders`/`gravity` と同じ絶対 scene 座標を
  そのまま使う（テキストブロックの見た目上の配置は物理シミュレーションが決める。
  **`start="layout"` のときだけ例外** — 下記参照）。
- `colliders`: 静的な衝突体の配列。`floor`（`y`）/ `wall`（`x`）/ `circle`（`center`, `r`）/
  `polygon`（`points`: `[[x,y], ...]` の scene 座標頂点列。**凹多角形可**）。`polygon` の頂点数は
  25〜60 程度が実務上の目安（人物シルエット等の簡略化輪郭。T5 spike 実測）、上限 200 を超えると
  validation エラーになる。
- `spawn`（任意。2026-08-14 導入）: 各文字の初期位置を狙って宣言する矩形
  `{ "x": [min, max], "y": [min, max] }`。**未宣言時は従来の 5 レーン固定グリッドのまま**
  （`x=(col-2)*1.1` 等、`laneCount=5`）で、狭い被写体（人物の頭・肩幅など）を直接狙うことはできない
  — 実測で頭幅 ±0.9 の帯に seed を 242 通り全数探索しても 1 文字も乗らなかった
  （社内実測。狙って spawn を宣言できないことがボトルネックだった）。`spawn` を宣言すると、
  各文字の初期位置は 5 レーングリッドの代わりに `spawn.x`/`spawn.y` の矩形から
  **seed 由来の決定論的一様分布**（`Math.random` は使わない。同じ `seed` + 文字 index は常に
  同じ初期位置になる）で引かれる。狙った被写体の直上に狭い `spawn` を宣言すれば、`seed` を
  振らなくても着地位置を大きく外さなくなる。

```jsonc
"physics": {
  "seed": 5, "duration": 3.0, "targets": ["fall"],
  "spawn": { "x": [-0.5, 0.5], "y": [1.0, 1.6] },
  "colliders": [
    { "type": "floor", "y": -5.0 },
    { "type": "circle", "center": [0, -1.0], "r": 0.5 }
  ]
}
```

  - `x`/`y` とも `min < max` が必須（違反はエラー）。
  - `spawn` の矩形は `colliders` の `floor`/`wall` の内側に収まっている必要がある
    （`floor.y` 以下、または `wall.x` の外側を指定すると**警告ではなくエラー**になる —
    最初から壁・床の外に spawn する宣言はほぼ確実に意図しないミスのため）。
- `start`（任意・既定 `"spawn"`。2026-08-14 導入）: presim の初期配置の決め方。
  - `"spawn"`（既定）: 上記の `spawn`（または未宣言なら 5 レーン固定グリッド）から seed 由来の
    疑似乱数で初期位置を引く。従来どおり。
  - `"layout"`: 初期位置・初期回転を **`texts[].layout` どおり**にする。`layout.position` の
    x/y と `layout.rotation` の z 成分（画面内の 2D 回転。matter-js は x/y と z 軸回転しか
    表現できないため）をそのまま使い、`layout.type: "line"` の並び順（`spacing` で等間隔）を
    崩さない。**乱数を一切使わないため決定論は自明**（`seed` を振っても絵は変わらない）。
    `spawn` と同時に宣言するとエラー（どちらが効くかの曖昧さを残さないため）。
- `holdSeconds`（任意・既定 `0`。**`0` 以上 `duration` 未満**。2026-08-14 導入）: presim 開始
  （`localSeconds=0`）からこの秒数のあいだ、対象文字を静的（重力・衝突の影響を受けない）に
  保つ。経過後に動的化し、そこから落下が始まる。ホールド中もバッファには毎フレーム同じ位置が
  焼かれる（lookup だけの draw はそのまま — シーク安全は変わらない）。`start="layout"` と
  組み合わせると「レイアウトどおりの読めるテロップが `holdSeconds` 秒静止したあと崩れ落ちる」
  演出になる。

**レシピ: 横並び（or 斜め）テロップが崩れ落ちる**（`start="layout"` + `holdSeconds`）:

```jsonc
{
  "texts": [{
    "id": "fall",
    "text": "落ちるテスト",
    "font": "fonts/zen-kaku-gothic-new-black.ttf",
    "mode": "flat",
    "size": 0.4,
    "layout": {
      "type": "line", "spacing": 0.55,
      "position": [0, 1.6, 0],
      "rotation": [0, 0, 0.22]
    }
  }],
  "physics": {
    "enabled": true,
    "seed": 13,
    "duration": 2.5,
    "start": "layout",
    "holdSeconds": 1.0,
    "restitution": 0.35,
    "targets": ["fall"],
    "colliders": [
      { "type": "floor", "y": -2.6 },
      { "type": "wall", "x": 5.6 }, { "type": "wall", "x": -5.6 }
    ]
  }
}
```

`localSeconds` 0〜1.0s は `layout` どおりの並び（`rotation.z` を振ってあるので斜め読み）で静止し、
1.0s を過ぎると重力で崩れ落ちて床（`floor.y`）に積もる。`seed` はホールド後の落下・跳ね返りにだけ
効く（初期配置には無関係）ので、崩れ方だけを seed ガチャで振りたいときに使う。

**physics と anim は排他**: `targets` に含めた `texts[].id` は `anim.preset` を `"none"` 以外に
できない（宣言するとエラー）。physics が per-char の position/rotation を毎フレーム書き込むため、
両方が同時に効く曖昧な優先順位を残さない設計判断。

**人物シルエットへ当てたいとき**: v1 の `polygon` collider は頂点列を手書きする必要がある
（人物セグメンテーション → 輪郭抽出 → 簡略化の自動生成は将来スキル化予定。現時点では手動）。
被写体の直上を狙うだけなら `spawn` の矩形を人物の頭・肩幅に合わせて宣言すればよい。

## 標準ツマミ（camera 投影 — pan / zoom。2026-08-06 導入）

ランタイムは `--akari-3d-pan-x` / `--akari-3d-pan-y` / `--akari-3d-zoom` という 3 つの
**標準カスタムプロパティ**を解釈する。断片ルート（または祖先）へ CSS で宣言すると、
ランタイムが毎 draw 読み取り、**カメラの投影**（`setViewOffset` によるオフセット、
`fov` の詰め直し）へ反映する。カメラ位置・モデル姿勢・ライトには一切触れない
（焼き込み済みアニメーションクリップとの干渉を避けるため）。

| プロパティ | 意味 | 単位 |
|---|---|---|
| `--akari-3d-pan-x` | 被写体の横位置。フレーム幅に対する割合 | `%` 付き、または無単位の小数（`50%` = `0.5`） |
| `--akari-3d-pan-y` | 被写体の縦位置。フレーム高さに対する割合。正 = 下へ（既存 CSS `translate` と同じ向き） | 同上 |
| `--akari-3d-zoom` | 見かけの大きさ倍率。`1` = 既定 | 無単位 |

**単位は割合に統一する（px にしない）。** プレビューは表示倍率で縮小されることがあり、
px 単位だと表示倍率に依存してプレビュー / 書き出しの絵が食い違う（パリティが壊れる）。
割合なら表示倍率と無関係に一致する。

### 経路A の canvas 移動 CSS を置き換える

旧来、素材のツマミ（`--<asset>-x` / `--<asset>-y` / `--<asset>-scale` 等）は断片ルートの
`transform: translate(...) scale(...)` を通じて **canvas そのものを CSS で動かして**いた。
これは canvas がフレーム外へ出て見切れる・拡大が描画済みビットマップの引き伸ばしになる
（解像度が落ちる）という欠陥がある。標準ツマミへブリッジすることでどちらも解消する:

```css
.laptop-live {
  position: absolute; inset: 0;
  --akari-3d-pan-x: var(--laptop-live-x, 0);
  --akari-3d-pan-y: var(--laptop-live-y, 0);
  --akari-3d-zoom:  var(--laptop-live-scale, 1);
}
```

素材ごとのツマミ名（`--laptop-live-x` 等）はそのまま維持し、標準プロパティへ**マップするだけ**。
`transform` は撤去する。canvas は常に `inset:0` でフレーム全面を覆い続け、被写体が消えるのは
本当にフレーム外へ出たときだけになる（自動見切れ補正は無い — 意図したはみ出し演出をそのまま描く）。

### 後方互換

**3 プロパティが未宣言なら現行と完全に同一挙動。** ランタイムは `getComputedStyle` で 3 つとも
空文字（＝どの祖先も宣言していない）と分かった時点で `camera.view` に一切触れない
（`setViewOffset` を呼ばない・`fov` も書き換えない）。旧来の CSS `transform` 方式の断片は
無改修のまま動き続ける。

### パリティ（プレビューと書き出しが同じ絵になる理由）

書き出し（`packages/render-cut/src/rasterize.mjs` の `embedThreeModels`）とライブプレビュー
（shell / `packages/overlay-runtime/src/overlay-runtime.js`）は**同じ `three-runtime.js` を
同じ断片 DOM 構造へ注入する**。標準プロパティは断片ルートで宣言され、CSS の継承で
`<canvas>` まで届く — 呼び出し元がどんな入れ子（`.scene-content` で包む／包まない等）で
container を渡しても、断片の外側からは同じ値が同じ式で読まれる。store の簡易レンダラー
（`asset-live.js` の `mountThreeScene`）は `three-runtime.js` を使わない独立実装のため、
**同じ式・同じ符号を手動で移植する**必要がある（移植を怠ると、それだけがプレビューと
書き出しからズレる）。

## カメラを動かす（camera.fromModel — glb 内カメラ + ベイク済みクリップ。2026-08-11 導入）

従来、経路 A のカメラは宣言のリテラル値で固定だった（動きはモデル側を動かして等価に出す）。
床 + 接地影のステージ演出ではモデル移動が等価にならない（モデルやステージを回すと影が床を
掃くように動き、照明の当たり方も変わる）ため、カメラ自体を glTF クリップ = **データ**として
動かせるようにした。宣言型（実行コードを配信物に入れない）の約束はそのまま。

```json
"camera": { "fromModel": "ShotCam" },
"animationClip": "CamOrbitDollyIn"
```

- `fromModel` は glb 内カメラノード名の文字列（`true` = 最初の 1 台）。宣言時は glb の
  yfov / znear / zfar を使い、`position` / `lookAt` / `fov` 等のリテラル併記は**警告して無視**する。
  aspect だけは canvas 実寸が正（リテラルカメラと同じ扱い）
- カメラの動きは `animationClip` の既存文法にそのまま乗る（クリップ名 / 配列 / `"*"`。
  モデル移動クリップと配列で共存できる）。`mixer.setTime` がカメラノードの TRS も評価する =
  時刻の純関数のままで、決定的レンダリングの原則は不変
- 標準ツマミ（pan / zoom）は**ベイク済みパスの上に合成**される。zoom の基準 fov は glb の yfov
- 対象は perspective カメラのみ。**シーンツリー外のカメラ**（`gltf.cameras` にだけいる）は
  使えない（クリップが node を辿れないため）— Blender 側でコレクションに入れて出力し直す
- `inspect()` の `cameraSource`（`"model"` = 配線済み）と `cameraWorldPosition`（クリップ評価後の
  実位置）で、絵を比較せずに配線とカメラ駆動を検証できる

### カメラリグとベイクの罠（2026-08-11 スパイク実測）

- **glTF コア仕様はカメラの yfov（画角）をアニメできない**（アニメは node の TRS + weights のみ）。
  寄りはドリー（translation）で出す。ドリーズームが要るときは宣言キーフレーム側の将来拡張
- Blender の `TRACK_TO` 等コンストレイントは glTF に出ない。**注視を保つのはリグの構造で**:
  yaw（pivot に置く・Y 回転）→ pitch（X 回転）→ カメラ（+Z オフセット = ドリー、Z 回転 = ロール）。
  glTF カメラは自ノードの -Z を向くので、子カメラを親の +Z に置けば回転が単位のまま pivot を
  向き続け、TRS キーだけで注視が保たれる
- 軸ごとにノードを分けるのは **1 ノードの同一 path へ複数チャンネルを張れない**制約のため。
  ヨー・ピッチ・ロールを同時に焼くなら 3 ノード
- ピッチの符号のような「角度の意味」はリグ構成に依存する。**必ず実レンダー + `cameraWorldPosition`
  の両方で確定させる**（§モデルの「既定ポーズ = 中立」と決めつけない、と同じ規律）
- クリップ長 = 窓尺の規約はカメラクリップにも同じに効く（LoopRepeat）。可視判定が半開区間なので
  実運用では踏まないが、QA レンダラへ **t = 尺ちょうど**を渡すと先頭へ巻き戻った絵が写る
  （`setTime(6.0)` で 6 秒クリップは 0 秒の絵）

## 書き出しが `seeking frame N timeout` で落ちるとき

書き出しは GPU / OSR の WebGL 実行体で走る。
1920×1080 のシーンを毎フレーム CPU で描くので、**同時に出す 3D シーンが増えるほど 1 フレームが重くなり**、
60 秒のウォッチドッグに触れて書き出し全体が失敗する。実測（2026-08-04・M 系 Mac）:

| 同時 3D シーン | 1 フレームのシーク | 結果 |
|---|---|---|
| 1 枚 | 数十 ms | 安定（8/8 成功） |
| 2 枚 | 数百 ms | ほぼ安定（稀に失敗） |
| 3 枚 | 300 → 1500ms と漸増 | 連続失敗（ページごと固着する瞬間もある） |

- **同時に出すシーンは 2 枚までを目安に**。3 枚以上ならショットを時間でずらす（同時刻に重ねない）
- 失敗時は警告に直近フレームの所要時間・3D シーン数・ページの声が出る。
  **時間が伸びていれば「重すぎる」、伸びずに固まっていれば別要因**という読み方をする
- タイムアウトは相関で犯人を決めない。**1 変数だけ変えて複数回**回して初めて因果が言える
  （2026-08-04 の実例: 「自作アニメ glb が原因」→ 棄却、「environment ツマミが原因」→ 棄却、
  実態は上表の性能限界。誤診 2 回のコストを診断出力で減らすのがこの節の目的）

## 原則

- 3D は Three.js、交換形式は glTF 系に限定する。preview v0 は外部 buffer を持たない自己完結 `.glb` と、`materialOverrides` で指定したローカル画像を受け付ける。Draco/KTX2 は未対応。
- Three.js 本体、addon、decoder、model、texture はローカルへ固定し、CDN import を使わない。書き出し実行体は background network を無効化する。
- fragment は上記の宣言型スキーマに限定する。任意 script、event handler、`new Function()` 等を使わない。
- 単一ルート内へ透明 canvas と静的 fallback を置く。canvas は透明合成を有効にし、背景を不透明に塗りつぶさない。
- asset は visible な期間だけ load / render / decode され、区間外と unmount で geometry、material、texture、renderer が解放される。
- camera、light、model pose、material、screen source を CSS 変数または素材 metadata の knob として宣言する。固定すべき model topology まで knob にしない。

## ライセンス済み glb

1. 配布元、asset ID / version、author、取得日、license、商用可否、改変可否、帰属表示を確認する。
2. glTF 形式であることを利用許諾と取り違えない。license 不明の model は使わない。
3. library からリンクせず、採用する project へ `.glb` と必要 texture / decoder をコピーする。
4. project 側 provenance に元 library、version、license、attribution を残す。
5. 相対 URL で読み込み、load error 時に空 canvas のまま成功扱いしない。

素材ライブラリ利用時のコピー規律は `docs/contract-2026-07-13-asset-library.md` に従う。

## 決定的な 3D アニメーション

- preview v0 は overlay の local timeline 秒を `AnimationMixer.setTime(localSeconds)` に渡し、その状態だけを render する。
- `THREE.Clock` や `mixer.update(delta)` で時間を積算しない。カメラ、shader time、particle も同じ local timeline から求める。
- rAF は算出済みの時刻を描画するためだけに使い、rAF delta を状態へ足さない。
- glTF clip がない動きも、local time の関数として pose を求める。再生・停止・逆シークで同じ結果になることを確認する。

公式: [Three.js AnimationMixer.setTime](https://threejs.org/docs/pages/AnimationMixer.html#setTime)

### クリップ長は overlay の窓尺に一致させる（実測 2026-08-04）

`setTime(localSeconds)` の駆動で、**clipAction は既定 LoopRepeat**。窓（`duration`）がクリップ長を
超えると、超えた瞬間にクリップ先頭へ巻き戻り、**モデルが破綻したように見える**（開いた蓋が
一瞬で閉じる等）。

- 対処は 2 択: (a) 窓をクリップ長以内に収める (b) **クリップを窓尺ぴったりに作り直す**
- 同梱クリップの尺・向きが用途に合わないことは珍しくない。合わないなら**作り直す方が速い**
  （§glb を直接編集する）

### 発光しない材質には貼れない（materialOverrides の実測 2026-08-14）

`materialOverrides` の差し替え先は `emissiveMap` 固定である。three は `emissive`（glTF の
`emissiveFactor`）を掛けてから合成するので、**`emissiveFactor` が未設定＝黒の材質へ貼っても
「0 × テクスチャ」で完全に消える**。しかもエラーにならないため、原因に辿り着きにくい。

実害: アプリアイコンの glb は前面（`IconFaceMaterial`）が非発光で、`materialOverrides` を
宣言しても**白い樹脂の面のまま**だった。同じ宣言でスマホの画面（`ScreenMaterial` =
`emissiveFactor: [1,1,1]`）は正しく映るので、「宣言は合っているのに出ない」状態になる。

- 判定: 貼る前に glb の材質を確認する。`emissiveFactor` が無ければ貼れない
  ```sh
  python3 -c "import json,struct;d=open('model.glb','rb').read();n=struct.unpack('<I',d[12:16])[0];j=json.loads(d[20:20+n]);print([(m['name'],m.get('emissiveFactor')) for m in j['materials']])"
  ```
- 対処 1（推奨）: モデル側の当該材質に `emissiveFactor: [1,1,1]` を与える。あわせて
  `baseColorFactor` を暗く落とすと、貼った絵の発色を下地が濁さない
- 対処 2: 発光する材質（画面用など）を対象にする
- ランタイムは非発光の材質を対象にすると**警告を出す**（2026-08-14 追加）。ログを見ること

### 動きプリセットは「正面を向く時間」を実測してから使う（2026-08-14）

`animationClip` の回転系プリセットは、**表示区間の大半で裏面や側面を向いていることがある**。
1〜2 秒しか出さないオーバーレイでは、貼ったテクスチャが一度も映らないまま終わる。

実害: アプリアイコンの 3 本（`Turntable` / `PopInDrop` / `TumbleReveal`）はいずれも序盤
約 1.5 秒がアイコン面の裏側で、1.8 秒の表示では白い面しか映らなかった。
**`animationClip` を外した初期姿勢が正面**だったため、短い露出では回さないのが正解だった。

- 短時間の露出では、まず `animationClip` 無し（初期姿勢）で焼いて向きを確かめる
- 回したい場合は、クリップの位相を実測して「正面が映る区間」に表示窓を合わせる

### 実写に重ねる小物は `--akari-3d-zoom` を 0.3〜0.5 まで落とす（2026-08-14）

`--akari-3d-zoom` の既定 1.0 は**フレームいっぱいに 3D が映る**設定。実写の上へアイコンや
端末をワンポイントで置く用途では大きすぎ、画面外へはみ出す。実測の目安はアイコン 0.30〜0.34、
スマホ実機 0.46。位置は `--akari-3d-pan-y`（正 = 下）で送る。

### 3D の確認は「最小プロジェクトを焼く」（2026-08-14）

`harness/render-fragment.mjs` の単体レンダーでは 3D シーンが `status=error` になる
（`model` / `texts[].font` がプロジェクトルート相対で解決されるため、プロジェクト文脈が要る）。
**確認は最小の `edit.json` を作って `render-cut` で焼き、フレームを抜いて目視する**。
断片だけを見て「貼れたはず」と判断しない。

### モデルの「既定ポーズ = 中立」と決めつけない（実測 2026-08-04）

ノート PC の `lid_root` で、回転 0°（単位クォータニオン）が **「閉じ」ではなく「180° フラット
（開ききって平ら）」** だった実例がある。実際の開き角は `180° − A`（A = 適用した X 回転角）。

| 適用角 A | 実際の見え方 |
|---|---|
| 0° | 180° フラット |
| 100° | 通常の開き 80° |
| 180° | 完全に閉じ |
| −100° | 逆折れ 280°（ヒンジが反対側へ） |

**角度の意味は必ず実レンダーで 3 点以上（両端 + 中間）を撮って確定させる。**
モデル名・軸名・既定値からの推測で決めない。

### glb を直接編集する（Blender より確実な場面がある）

- **Blender の `frame_set()` はポーズ凍結に使えない**: glTF 読み込み直後はアニメが評価されず、
  どの時刻を指定しても既定ポーズのまま出力される（複数時刻で同じ絵が出たら疑う）
- ノード回転の差し替え・アニメの新規生成は **glb の JSON チャンクを直接書く方が確実**
- 実装メモ:
  - BIN チャンク末尾へ **4 バイト境界を守って append** し、`bufferViews` / `accessors` を追加 →
    sampler から参照する
  - `buffers[0].byteLength` と **GLB ヘッダの総長**を更新し忘れない
  - 時刻（input）accessor には **`min` / `max` が必須**
  - 回転の `LINEAR` 補間は SLERP なので、30fps 相当のキーを並べれば任意のイージングを再現できる
  - 静止 `node.rotation` も t=0 の値に揃える（初回描画のちらつき防止）

### テクスチャが載らないモデルへ焼き込む

`materialOverrides` は既存の `emissiveMap` にしか効かず、**UV も emissive も持たないマテリアルには
構造的に効かない**（画面が黒いまま）。その場合は Blender で平面 UV を張り、画像を
`emissiveTexture` として焼き込む（`emissiveStrength` 1.2〜1.5 目安）。

**UV の向きは 4 通りを実レンダーで総当たりするのが速い**（bbox 軸から機械的に決めても向きは出ない）:
`(u,v)` / `(1-u,v)` / `(u,1-v)` / `(1-u,1-v)`。判定基準は「文字が正しく読めるか」。

## VideoTexture

`materialOverrides` の texture に動画（`.mp4` / `.m4v` / `.mov` / `.webm`）を指定すると、ランタイムが
`<video>` を DOM へ置いて `VideoTexture` を作る。**DOM へ置くのが要点** — 決定的シークは
`document.querySelectorAll('video')` を対象にするので、DOM にいるだけで既存の機構に乗る。

- 時刻を決めるのは常に**外側**。ランタイムは `autoplay` しない。wall-clock 再生へ任せない。
  - **export**: rasterize がフレーム精度シーク（提示フレームの確定まで待つ）を済ませてから
    3D を描く。ランタイムは `currentTime` を書かない
  - **preview**: tick が `render(container, seconds, { syncVideos: true })` を渡し、ランタイムが
    overlay のローカル時刻へ `currentTime` を合わせる。壁時計で進むので提示フレームの確定は
    待たず、1 フレーム前後ずれることがある（絵は必ずその時刻の近傍になる）
  - `syncVideos` は **preview 専用の opt-in**。export で渡すと確定済みの提示フレームを崩して
    決定性が壊れる
- ランタイムは `<video loop>` を立てて作る。export のシークは loop 宣言のある素材の時刻を尺で
  畳むので、素材より合成が長くても末尾で静止せず巻き戻って回る。
- **編集用 720p プロキシ**を与える。原本を texture へ接続しない。export は動画を data URI として
  シートへ埋め込む（base64 で約 1.37 倍）ので、原本を差すとシートが肥大し、preview は
  それを毎 tick シークすることになる。
  - **24MiB を超える動画 texture は export が拒否する**（黙って原本へ fallback しない）。
    エラーには 720p プロキシを作る ffmpeg コマンドが出る:
    `ffmpeg -i <master> -vf scale=-2:720 -c:v libx264 -crf 23 -preset medium -pix_fmt yuv420p -an <proxy>.mp4`
  - 解像度ではなくバイト数で見ているのは、シート生成が同期・純関数で ffprobe を呼ばないため。
    「720p かどうか」の代理指標であり、上限そのものは運用で調整してよい
  - タイムライン素材側の `source.proxy`（edit.json）の自動生成は別件で、現時点では未実装
- ミップマップはランタイムが有効化する（`LinearMipmapLinearFilter` + 異方性 16）。
  `VideoTexture` の既定は無効で、大きな画面素材を 3D 上の小さな面へ潰すと細部が割れ、
  モデルが回ると割れ方が毎フレーム変わるため「カクついている」ように見える。
- 差し込み先の面は **baseColor を黒**にする。明るいままだと環境光で照らされた面が
  自発光の絵を飲み込む。UV の無いメッシュには差せない（(0,0) を拾って真っ黒になる）。
- 素材の縦横比を差し込み先に合わせる。縦動画を横画面に差すと引き伸ばされる。
- source の寸法・format を変える場合は既存 texture を dispose し、作り直す。
- preview は毎 tick シークするため、**編集用 720p プロキシでないと詰まる**。原本を差さない。
  既に十分近い時刻（20ms 以内）なら書かないので、再生中にシークが走り続けることはない。

公式: [Three.js VideoTexture](https://threejs.org/docs/pages/VideoTexture.html)

## パフォーマンス

- 4K 上の post-process blur、`filter: blur()`、`backdrop-filter`、過剰な shadow を使わない。
- `shadows` を有効にすると shadow map の深度パスが増える（実測: 単純なシーンで draw call 2 → 4）。
  必要なカットだけで宣言する。
- 動画 texture は毎フレーム GPU へ上げ直す。ミップマップの再生成もそのたびに走る。
- 毎フレームの object / material / texture 生成、shader compile、model reload を避ける。
- preview v0 と export の renderer pixel ratio は `1` 固定。同一 scene の見え方を対象出力 profile で実測する。
- `renderer.info` で draw calls、triangles、textures を計測する。固定の polygon / draw-call 上限は一次根拠がないため発明せず、対象 Mac と出力 profile で **要検証** とする。

公式:

- [Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)
- [Three.js — How to dispose of objects](https://threejs.org/manual/en/how-to-dispose-of-objects.html)

## よくある間違い

- CDN の Three.js、decoder、texture に依存する。
- Draco / KTX2 圧縮モデルを v0 へ渡す（decoder と worker は未対応）。
- license 不明の `.glb` を「ネットで見つけた素材」として同梱する。
- JSON 宣言の代わりに fragment 内の `<script>` を実行させようとする。
- export だけを見て WYSIWYG 対応済みと報告する。
- proxy がないため原本を `VideoTexture` へ流す。
- 材質にテクスチャが無いまま `environment.intensity` を上げて金属をごまかす（副作用が離れた場所に出る）。
- 複数の動きを持つモデルで `animationClip` を 1 本だけ指定し、片方しか動かないまま出す。
- overlay の窓尺がクリップ長を超え、途中でループして破綻する。
- モデルの既定ポーズを「中立（閉じ・正面）」と決めつけ、実レンダーで角度の意味を確かめない。
- Blender の `frame_set()` でポーズを凍結したつもりになる（アニメが評価されず既定ポーズのまま）。
- `Clock.getDelta()` / `mixer.update(delta)` でアニメーションする。
- 非表示後も render loop と video decode を動かす。
- dispose せず、素材切替のたびに GPU resource を残す。
