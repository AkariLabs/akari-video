# トレンド取得

[SKILL.md](SKILL.md) の実行順 3. からだけ読む。**専用の `trends` フィールドは持たない。** ここで得た知見は [ideate.md](ideate.md) の `topic.candidates[].rationale` や [competitor.md](competitor.md) の `target.competitors[].gap` に溶け込ませ、出典だけを `sources[]` に残す。トレンドそのものを別セクションとしてレポートに独立掲載しない（候補ネタランキング表・競合分析サマリーの根拠として吸収される）。

## 1. 無償手段を既定にする（ハードルール）

既定のトレンド取得は無償枠のみで完結させる。

- 一般公開されているトレンドページ・急上昇一覧の閲覧
- 検索エンジンの一般公開結果
- 既に持っている一般知識（学習時点の傾向。取得日時が不明な場合はその旨を `sources[]` の `note` に明記し、`url` は `null` にする）

無償手段だけでも一周は成立させる。有償のトレンド API（有償枠のソーシャルリスニング・キーワードボリュームツール等)が使えない、または承認が得られない環境でも、ここで停止せず「無償手段のみで確認した」範囲を明記して次工程へ進む。

## 2. 有償手段はオプトイン

有償のトレンド取得手段を使う場合は、[manage-connections](../manage-connections/SKILL.md) の承認ゲート（対象・使う手・理由・代替案・見積費用・待ち時間・外部送信の宣言 → 明示承認）を先に通す。承認が無いまま有償呼び出しをしない。承認後に使った場合は `sources[]` の `cost` に `paid` を記録する。

## 3. 出典を残す

トレンド調査で参照した情報は必ず `sources[]` に 1 件として記録する。

- `url`: 参照ページの URL。URL の無い一般知識由来なら `null`
- `retrieved_at`: 取得日時（ISO 8601）。不明なら `null`
- `cost`: `free` / `paid`
- `note`: 何を確認したか、どの候補・競合の根拠に使ったか

## よくある間違い

- トレンド調査結果を独立したレポート面として作り、固定 5 面から逸脱する。
- 有償トレンド API を承認前に呼ぶ、または承認ゲートを経ずに「無償枠だから」と誤認して有償枠を使う。
- 取得日時不明の知見を、あたかも今調べたかのように `retrieved_at` を捏造する。
- 無償手段で何も見つからなかった場合に、そのまま `sources[]` へ何も残さず知見だけ書く（出典なしの主張を作らない）。
