パッケージ実機での同期経路の実測（重要・地雷を 1 個潰した）:
  ELECTRON_RUN_AS_NODE=1 で出荷 Electron を node として起動し app.asar 内 /lib/skills を検証:
  - fs.stat(/lib/skills/analyze-footage/SKILL.md) => true（asar 対応 fs で読める）
  - しかし fs.cp(dir, dest, {recursive}) は ENOENT で失敗。Electron の asar フックは
    cp/cpSync を「単一ファイルの copyFileOut」に差し替えるため、asar 内ディレクトリの
    再帰コピーが成立しない（＝ 初回起動同期が packaged で死ぬ地雷）。
  - 対策: syncSharedStore の copyTree を fs.cp から readdir+readFile+writeFile の
    手動再帰に変更（readdir/readFile は asar 対応）。出荷 asar 相手に再実測:
      手動 copyTree(/lib/skills → 実 fs) => SKILL.md 6 本コピー・references 同梱・
      SKILL.md 内容 intact（先頭 '---'）  => PASS
  - 再ビルド・再パッケージで修正版を同梱（final app 430MB・6 SKILL.md・fs.cp 残存 0 を確認）。
