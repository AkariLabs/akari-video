# システムを変える前の確認画面 — 実機での観測手順

AKARI Video が利用者のシステム（レジストリ・他社ソフトの導入・アプリの外のフォルダ）を変える前に、
何を・どこから・どこへ変えるかを画面に出して同意を取る。その 3 つの画面を、隔離した実機
Electron で開いて撮るための再現スクリプト。

| 画面 | 出る場面 |
|---|---|
| 道具の導入 | 初回セットアップの「道具チェック」と、設定の「道具」 |
| AI パートナーの導入 | 未導入の CLI のカードで「始める」を押したとき |
| 書き出し時の GPU 設定 | Windows で、書き出しがはじめて高性能 GPU の一時割り当てを必要としたとき |

## 走らせ方

```sh
cd apps/shell && npm run build      # 先に一度
cd ../.. && node apps/shell/extensions/akari-partner/evidence/signpath-consent/capture.mjs
# 一部だけ: … capture.mjs tools-partner | gpu-decline | gpu-allow
```

- `HOME`・`AKARI_HOME`・`THEIA_CONFIG_DIR`・`--user-data-dir` はすべて OS の一時フォルダ配下に作る。
  手元の設定やプロジェクトには触れない。終了時は自分が起動したプロセスだけを止める
- **［導入する］［インストール］は押さない**。確認ダイアログを撮って［やめる］を押し、そのあと隔離した
  `HOME` に何も入っていないことを記録する（提供元のインストーラーは実際には走らない）
- GPU の確認は Windows でだけ出る。macOS で画面を出すために、表示の判定だけを切り替える
  `AKARI_TEST_WINDOWS_GPU_CONSENT=1` を付けて起動する。macOS ではレジストリの操作は起きない
- 道具は実機の導入状況がそのまま出る（導入済みの道具にはチェック欄が無い）

## 出てくるもの

スクリプトと同じフォルダに、スクリーンショット（`01-…png`〜`10-…png`）と `observations.json`
（ダイアログの文言・ボタン・リンク先、書き出しへ渡った引数、保存された許可、［やめる］後の `HOME` の中身）を書く。
**これらは検証の記録なのでコミットしない**（`.gitignore` 済み）。

## 見るところ

- 道具: 説明に「Windows では winget、Mac では Homebrew で導入します。導入すると各ソフトの利用規約に
  同意したことになります。」と管理者の確認の一言があり、未導入の道具が**どれも選ばれていない**
  （`installButton` が「…（0）」で押せない）。各行に提供元と規約へのリンクがある
- AI パートナー: ソフト名・提供元・取得元・入れる場所・環境変更・利用条件のリンクと
  「AKARI Video の配布物ではなく、提供元のソフトです。」が出る。［やめる］でカードが「始める」に戻る
- GPU: ［許可しない］なら書き出しへ `--gpu-preference off`、［許可する］なら `auto` が渡り、
  どちらでも書き出しは最後まで進む。2 回目の書き出しではもう聞かない
