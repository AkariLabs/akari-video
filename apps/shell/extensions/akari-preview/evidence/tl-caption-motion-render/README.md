# 字幕の動き: 原因、修正、実機判定

## 通常再生の原因（CDP 実測）

`display_policy` の無い 14 字幕・28 秒の fixture（11 字幕に `in: glitch` / `typewriter`、全字幕に `words[]`）を、表示中の出力プレビューで先頭から連続再生した。rAF 1,800 回の採取で全 14 字幕を確認し、動き付き 11 字幕すべてにアニメーションが付いた。連続する同一 id の glitch / typewriter も字幕ごとに別の DOM 板になり、各回の animation `currentTime` は 0 ms から始まった。karaoke の styled 経路に入った動き付き 5 字幕も描画された。UI のタブ名は「出力プレビュー」で、観測した webview の id も output-preview だった。

したがって可視状態のオーナー相当 fixture では「通常再生で描かれない」は再現しなかった。CSS/WAAPI の字幕板は存在し、再生時刻も更新される。旧タイプライターは板全体の clip-path ワイプで、1 文字ずつの表示ではなかった。最初の CDP 実行で webview が `hidden` だったときは rAF が 0 回で補助 tick が粗かったが、これは可視ウィンドウでのオーナー現象の原因とは断定しない。hidden 時の補助 tick 判定を 400 ms から 120 ms へ短縮したのは、背景の webview での粗さの改善である。

修正後の短い fixture でも、通常再生中の glitch 字幕を `currentTime = 300 ms` で撮影した。動き無し対照の animation は `none` で、同時刻のシーク判定では 2,346 画素が異なった。

CSS 経路を維持した理由: glitch / typewriter は GPU 字幕スプライトの非対応語彙で、auto は OSR に降格する。文字単位の表現を frame-engine に重複実装するとプレビューと OSR の描き方が割れる。

## 修正と判定

47 レシピの正本と書記素ごとの span 生成関数を、配布の `render-cut/src/**` に入る場所へ置いた。配布対象だけをコピーした一時ディレクトリで `captions.mjs` と GPU eligibility を import し、47 レシピ・typewriter 4 span の生成を確認した。span は `display:inline` とし、プレビューと OSR の適用順を runs → typewriter → rich layers にそろえた。リッチ層は影・縁取り・塗りの文字を複製するため、旧順序では層の数だけ書記素を余分に数え、50% 時刻に塗りがまだ現れなかった。新順序では 13 書記素に対して 13 個の文字 span ができ、各 span の内側に影 1・縁取り 2・塗り 1 層が入る。animation だけの `text_style` が `display_policy` の見た目変数を変えていたため、プレビューと OSR の両方でその余計な変数を除いた。

判定では、動きが出る時刻の差分に加え、動きの終わった中立時刻に動き無し対照と一致するかを測る。loop など区間全体を動かす行と、入口の終端が中立姿勢ではない行は中立チェックから明示的に除外する。これにより影などの見た目差だけで「合」とする偽陽性を防ぐ。文字 span の縁では微小なラスタ差が出るため、320×180 画面の下半分で、平均 RGB 差と差分画素数を併用する。文字送りと未来の退場動作を組み合わせた行の中立フレームは、全 13 書記素が不透明で animation `currentTime = 1500 ms`、対照との差は平均 1.012/255・699 画素だった。影欠落時の差 2013 画素・平均 2.5/255 を通さない閾値を使う。

最終コードで全 81 行を引き継ぎ無しで再実測し、プレビュー従来・プレビュー `display_policy`・書き出し OSR・書き出し auto は各 81 合 / 0 否。中立チェックは 414 件が合 / 0 否、区間全体の動きなど 72 件は理由付きで除外した。auto の両 fixture 版では GPU 適格 130 件が実際に GPU を選び、非適格 32 件が OSR を選んで日本語の降格理由を出した。

追加したリッチ文字送り行は入口 50% で、プレビュー両経路とも 13 書記素中 6 書記素が影・縁取り・塗りまで表示された。プレビューの文字インク量は対照の 48.3% / 47.7%、OSR は 48.6% だった。終了後の中立時刻と動き無し対照の差はプレビュー 26 / 25 画素（平均 0.060 / 0.062）、OSR 167 画素（平均 0.912）で、字形の範囲とインク量が一致した。

PNG、JSON、results.md などの記録物はリポ外に置いた。記録スクリプトは `--records` または `TL_CAPTION_MOTION_RECORDS` で専用のリポ外ディレクトリを受け取り、evidence 内には再現スクリプトとこの README だけを置く。
