# 出力プレビューの字幕の動き（textanim）— 実機 L1 の証跡

タスク: `task/2026-09-24-preview-caption-textanim`。

実機: 専用の CDP ポート 9493・一時ディレクトリの `--user-data-dir` / `THEIA_CONFIG_DIR` / `AKARI_HOME`（名前に `preview-caption-textanim` を含む）。
ウィンドウ 1440×900・倍率 2 で撮影。出力 1280×720・30fps。
BEFORE は変更前（基点 `c0008b0a`）のビルド、書き出しは基点を別ディレクトリへ展開した render-cut で行った（本タスクは `packages/` を変えていないので書き出しは before / after で同一）。

## 許容差の根拠

プレビューは webview の撮影（倍率 2 → 映像枠を切り出し 1280×720 へ拡縮）、書き出しは H.264 の復号フレームなので、同じ絵でも色と縁が少し違う。
**動きの無い字幕 c-0012** のプレビュー ⇄ OSR の差をこの経路の雑音とみなした: 重心 dcx +0.0001 / dcy −0.0005・外接矩形 dw +0.0015 / dh +0.0028・ink 比 0.939。
動きのある字幕の loop の途中（ほぼ静止）でも ink 比は 0.943〜0.997 に収まる。
そこで許容差を **重心 ±0.002・外接矩形 ±0.007（フレーム比。1280×720 で約 9 px / 5 px）・ink 比 0.93〜1.05** とした（ink 比は不透明度 × 塗りの量の代理。登場の途中の fade-up は不透明度 0.68 なので、動きを描かない BEFORE は ink 比 1.43 になる）。
AFTER の 36 時刻はすべてこの範囲。最大は c-0010 out（drop-in の退場 + 強調 one-char-bang）の dw −0.0062。

## 再生・一時停止・コマ送り（`results-after-playback.json`）

- c-0001（fade-up / float / fade-up）を 0 秒から `akari.preview.play` → 1.8 秒後に `akari.preview.pause`。rAF ごとに板を採取（156 回）
  - 板の animation の currentTime は 0 → 66.7 → 166.7 → … → 1766.7 ms とフレーム単位で進み、opacity は 0 → 0.18 → 0.42 → … → 1、transform は translateY 0 → −8.0 → −0.35 px（float の往復）と変わる
- 一時停止後の姿 `{opacity 1, translateY −1.74167, currentTime 1766.7}` = 2.9 秒へ寄り道してから 1.7667 秒へシークし直した姿（完全一致）
- プレビューの「1コマ進む」（`#frame-forward`）3 回: 0.2 秒 → 233.3 / 266.7 / 300 ms。各回の姿はその時刻へ直接シークした姿と完全一致

`results-before.json` の playback は、再生コマンドに editUri を渡していなかった版の記録（再生が始まっていない）。BEFORE は板に animation 自体が無い（captures 36 時刻すべて）ので、再生の比較は AFTER だけで行った。

## 同時に見える字幕へ宣言が漏れない（`results-after-overlap.json`・`after-overlap-t0.3.png`）

`gen-fixture.mjs --overlap`: 0〜3 秒に o-top（spin-in）/ o-mid（動き無し）/ o-bottom（fade-up）の 3 本。
0.3 / 1.5 / 2.7 秒のどれでも、o-mid は animation なし・opacity 1・transform none。o-top / o-bottom はそれぞれ自分の語彙だけ（`akari-anim-spin-in` / `akari-anim-fade-up`）。

## 書き出しで見つかった既存の差（本タスクでは直さない・報告のみ）

1. **OSR は複数の字幕の動きを 1 本分しか描かない**: OSR は全字幕のオーバーレイを 1 枚の文書に並べ、各字幕の `<style>` の
   `.akari-caption__plate{…animation:…}` が文書全体に効く。後に並ぶ字幕の規則が前の字幕の板を上書きするため、
   本 fixture（最後の c-0012 が動き無し）を 1 本の書き出しにすると、全字幕の動きが消える（`export-before-osr-sheet.json`・
   画素の比較で in / loop / out の ink が同じ）。比較の基準には、字幕 1 本だけのプロジェクトで書き出した
   `export-osr-per-caption.mjs` の結果を使った（`export-before-osr-per-caption.json`）
2. **GPU の字幕の動き（frame-engine の captionMotionAt）は CSS の宣言と合成の規則が違う**: CSS は同じ要素の複数の animation のうち
   後のもの（loop / out）が transform を上書きするが、GPU はスロットを掛け合わせる。回転の中心も違う。
   spin-in / pop / zoom-pop / rotate-in の in / out の途中で GPU とプレビュー（= CSS 宣言）は重心で最大 0.28 ずれる（表の右列）。
   `--engine auto` は GPU が受け付けるプロジェクトでは GPU を選ぶので、既定の書き出しとプレビューは語彙によって見た目が違う。
   typewriter / wipe-left は GPU が受け付けない（OSR へ落ちる）ため、GPU 版の fixture（`--gpu`）では c-0003 / c-0009 の動きを外した
