## 注: 「Shift クリックで 2 本を選ぶ」について

派遣票の手順は「Shift クリックで話した言葉の字幕と置いた文字の 2 本を選ぶ」だが、今の UI では、話した言葉の字幕と置いた文字の 2 本をプレビュー上で同時に選ぶ実操作が見つからなかった。スクリプトは次の順に試し、すべて記録している（`attempts`）。

1. プレビューで置いた文字をクリック → 話した言葉を Shift クリック: 字幕の `pointerdown` は Shift を見ないので、選択が置き換わる（1 本）。Shift の加算選択（他席 `5d6176ff`）はオーバーレイのパーツ向け
2. タイムラインで Shift クリック: 2 本とも 0 秒から始まって同じ行で重なっており、話した言葉の項目に当たる点が無い。タイムラインの複数選択は primary だけをプレビューへ送る
3. 台本で行を ⌘クリック → 置いた文字のバーを Shift / ⌘クリック: 台本の置いた文字の選択は 1 本だけ（行の選択とは別）で、加算されない

そのため 2 本の選択は、他席 P0 の L1（`preview-caption-handles-v1`）と同じく、ホストのイベント `akari.daihon.selectionChanged`（`[c-0001, c-0101]`）+ `akari.timeline.primarySelected`（置いた文字）で作った（**計装**）。判定の対象である「何もない所を 1 回クリック」は実マウス。計装で作った選択は台本自身が持っていないので、タイムラインへ写った分（`c-0001`）は解除後も残る。この項目ではプレビューと台本だけを判定し、タイムラインに残った分は `timelineResidueFromSyntheticEvent` に記録した。

## 注: ホスト発の選択が台本・タイムラインに残る件

台本の行を選ぶと、プレビューへは `selectedCaptionIds` だけが届き、primary（`selectedCaptionId`）は空のまま。プレビューの空クリックで解除の通知（`null`）は出ているが、台本の行選択とタイムラインの字幕選択はそれでは外れない。プレビュー側は r2 で直っており（main 側の `selectCaption` が集合も空にする）、残りはホスト側の受け方の問題。本票（衝突の解消と再検証だけ）の範囲外なので直していない。
