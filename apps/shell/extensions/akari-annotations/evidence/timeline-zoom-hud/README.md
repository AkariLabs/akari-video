# evidence: timeline-zoom-hud（タイムラインのズーム修正 + ズーム率 HUD + フレーム単位ズーム）

L1 検証（production ビルド + 生 CDP 実操作）の証跡。フィクスチャはオーナー実プロジェクトの複製
（実素材 26.3 秒・実文字起こし付き）を土台に、`edit.json` の `cuts` を 3 個に加筆したもの。
`captions.json`/`review.json` は `edit.json` と同じ階層へ配置（既存の `akari-preview` 側の
規約に合わせるため）。`output.fps` は 30。

検証環境: production ビルド（`npm run build`、0 errors）の Electron を隔離
user-data-dir + `--remote-debugging-port` で起動し、`playwright-core` の
`chromium.connectOverCDP` で実際の pointerdown/pointermove/pointerup・wheel（ctrlKey 付き）
イベントをディスパッチして操作した（座標はレンダリング後の DOM `getBoundingClientRect()` の
実測値）。

## ズーム率の定義

`totalDuration() / visibleDuration() * 100`。全体表示 = 100%、拡大すると 100% を超える。
フィクスチャの `totalDuration()` は約 26.52 秒（cuts/captions/overlays/annotations の最大値 ×
1.02）。

## 実測 diff・実測値

### F35: ルーラー追従（nice-number 方式）

| ズーム段 | 可視長（概算） | 目盛り間隔 | ラベル形式 | 実測ラベル |
|---|---|---|---|---|
| 全体表示（100%） | 26.5秒 | 5秒 | mm:ss | 00:00, 00:05, 00:10, 00:15, 00:20, 00:25 |
| 中間（wheel 6段, 1139%） | 2.3秒 | 0.5秒 | mm:ss.d | 00:08.5, 00:09.0, 00:09.5, 00:10.0, 00:10.5 |
| スライダー 300（489%） | 5.4秒 | 1秒 | mm:ss | 00:07, 00:08, 00:09, 00:10, 00:11, 00:12 |
| 最大（スライダー 1000, 19890%） | 0.133秒(4フレーム分) | 1フレーム | mm:ss:ff | 00:09:17, 00:09:18, 00:09:19, 00:09:20 |

どの段でも隣接ラベルが必ず異なる時刻を表示し、目盛り位置（`left: n%`）は該当時刻を
`percent()` で正確に変換した値と一致することを DOM 実測で確認（ソースは絶対時刻グリッド上の
nice-number 刻みで tick を生成するため、目盛り位置と実時刻は常に一致する設計）。

### F36: ズーム率 HUD

- 虫眼鏡アイコン（`codicon-search`）+ パーセント表示 + スライダーが「元に戻す」ボタンの直前に
  常設されていることを確認（01〜04 のスクショ）
- パーセント定義どおり、全体表示 = `100%`、ズームインするほど増加（`489%` → `1139%` →
  `19890%`）することを実測
- **wheel → スライダー同期**: ctrl+wheel でズームすると、スライダーのつまみ位置が
  `0`（全体表示）から右へ自動的に移動することを確認（01→02）
- **スライダー → 表示同期**: スライダーを直接操作すると、ルーラー・クリップ幅・パーセント
  表示が即座に再計算されることを確認（02→03→04、いずれも `input` イベント経由）

### F37: フレーム単位ズーム

- スライダー最大値（1000）で可視長が約 0.133 秒（fps=30 で 4 フレーム相当）まで縮小し、
  ルーラーが 1 フレーム刻みの `mm:ss:ff` 表記になることを確認（04-slider-max-frame-level.png）
- 同一秒内で隣接フレーム番号（17→18→19→20）が明確に区別できることを確認

### 非退行（6種・契約の最低5種を上回る実測）

| 操作 | 実測 diff |
|---|---|
| トリム | `cuts[0].out: 7.5 → 8.85`（`in` および他クリップは不変）→ undo で `8.85 → 7.5` に復元 |
| 並べ替え | `cuts` 配列順 `[{0,7.5},{9,17},{19,26}] → [{9,17},{0,7.5},{19,26}]`（C1/C2 ラベルが新順序に再割当て、各クリップの source 秒位置は不変）→ undo で元の順序に復元 |
| 字幕ずらし | `c-0002` の `start: 5.22→4.49` / `end: 8.28→7.55`（他の字幕は不変）→ undo で `5.22`/`8.28` に復元 |
| Esc キャンセル | ドラッグ中（ゴースト表示済み）に Esc → `edit.json` の内容がバイト単位で無変化（ドラッグ前後で完全一致を確認） |
| undo | 上記トリム・並べ替え・字幕ずらしそれぞれで、「元に戻す」ボタン押下により直前の変更が正しく復元されることを確認（ボタンは操作直後に有効化・undo 後に再度無効化） |
| クリックシーク | タイムライン背景クリックでフッターに選択時刻（例: `00:00:13.260 を選択しました。`）が表示されることを確認 |

段積み（Wave 17 機能）は本タスクで変更していないため今回は対象外（フィクスチャの字幕・
オーバーレイは重複させていない）。
