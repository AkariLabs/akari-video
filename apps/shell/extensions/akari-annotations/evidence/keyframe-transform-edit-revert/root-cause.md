# Confirmed cause and repair

## BEFORE evidence

The external Electron/CDP run recorded 96 cases: 17 `ok`, 79 `ng` in `run-log-before.json`. The committed log is a compact summary of each case's saved transform/keyframe changes, relevant on-screen values, and error message; the runner's full log also captured item snapshots, preview geometry, and write journals. The run established two separate failure modes.

- `still-item` is a v2 media **cut** in this fixture (`cut:0` in the inspector). Before `a-toggle-x`, the saved transform after preparation was approximately `{x:-38.4,y:39.6,scale:1.12,rotate:24.73}`. Toggling X inserted points at frames 0 and 30 with only `transform.x`; the preview media dataset changed from the visible transform to `y:0, scale:1, rotate:0`. Subsequent Y, scale, and rotation toggles restored one missing coordinate at a time. The paired `before-062-toggle-before.png` and `before-062-toggle-after.png` show the jump.
- `html-item` had approximately `scaleX:1.305`, `scaleY:1.08`, `scale:1.12`. `a-toggle-scale` wrote only `scale:1.18735319` at frame 30, the inspector's geometric mean. The preview changed both effective axes to `1.18735319`, losing the width/height ratio.
- `b-inspector-x` changed the saved HTML base X from about `-108.83` to `-27`, but changed no keyframe point and left preview `--x` around `-121.21px`. The media case likewise changed base X from about `-38.4` to `-27` while preview X stayed about `-38.4`. The write happened; keyframe evaluation overrode the edited base. Handle commits exhibited the same base-write path. This distinguishes evaluation override from a missing write.
- Several BEFORE case errors came from the r1 runner racing iframe replacement or losing preview selection. These are measurement errors, not evidence that the product edit succeeded.

## Code path

1. `akari-inspector-widget.ts` `keyframeSeatOptions()` passed the displayed scalar into `handleKeyframeControl()`. `akari-annotations-widget.ts` then wrote only that scalar using `setV2Keyframe()`. The output cut evaluator (`packages/frame-engine/src/timeline/layer-visual.ts` `computeLayerKeyframesVisual()`, called from `timeline/plan.ts` for cuts and layers) treats any transform point as a whole transform category: absent X/Y/scale/rotation leaves use 0/0/1/0. The shell's cut path calls `apps/shell/extensions/akari-preview/src/common/layer-keyframes-visual.ts` with the same whole-category fallback. The HTML overlay runtime (`packages/overlay-runtime/src/keyframes.mjs`) instead evaluates each property against its static value and supports scaleX/scaleY. Both render rules were read, and no export evaluator was edited.
2. `akari-inspector-widget.ts` `appendRow()` sent transform numeric commits through the ordinary `item-field` writer. `akari-annotations-widget.ts` `handleInspectorWriteV2()` built `{transform}` from `raw.transform`, so keyframe points remained unchanged. The inspector also displayed base snapshots at a different value from the preview's evaluated frame.
3. HTML move/resize/rotate in `packages/overlay-runtime/src/interaction.js`, and media handle completion in `akari-preview-open-handler.ts`, emitted transform patches. Preview host `handleOverlayWrite()`, `handleLayerWrite()`, and `handleCutWrite()` passed these to `resolvePreviewItemWrite()`, whose v2 branch merged into the base transform without a playhead. Preview writes also bypassed the annotations edit history.
4. The scale controls display percentages but the stored transform/keyframe values are unitless factors. X/Y are output pixels, rotation is degrees. The HTML CSS and render-cut sheet both apply translation, then rotation, then local scale about the center. Width/height are independent axis factors; the overall scale control is the geometric mean and must adjust both axes by a common ratio.

## Repair in this turn

- `packages/edit-store/src/transform-keyframe-edit.ts` evaluates the appropriate HTML or media rule, seeds a visible transform, and updates an existing or inserted playhead point. For media it fills complete transform points, preserving the cut evaluator's whole-category behavior. For HTML it seeds both axes when enabling overall scale so the ratio remains unchanged. `edit-v2-item-write.ts` uses the same update when preview writes include playhead time.
- `akari-annotations-widget.ts` routes transform toggle/write requests through one v2 mutation each, shows the evaluated transform in the inspector snapshot, and refreshes it on a paused playback tick. `akari-inspector-widget.ts` converts percentages once and commits active transform fields to the point. `timeline-keyframe-rows.ts` exposes width and height rows.
- Preview write requests carry their current output time. The host uses the shared item writer, then calls an annotations command for one history entry when that command owns the same edit URI. Its fallback direct write remains for a preview without an active annotations widget.
- The AFTER runner now waits for inspector persistence and iframe refresh, reselects missing preview targets, uses the actual corner handle classes, stores journal deltas, and checks values after seeking away and back. Electron execution and AFTER screenshots are delegated to the external wrapper.

## Boundary note

The cut/export evaluator's whole-transform rule means a media item's first X point must contain Y/scale/rotation too. Those values are preservation coordinates, but the current schema has no separate enabled-property mask. A strict distinction between a media field that was explicitly enabled and one copied into a complete point cannot be represented without changing the evaluator or schema. Changing `packages/frame-engine/src/timeline/layer-visual.ts` to per-property static fallbacks would also change export behavior and lies outside this task's ownership. The implementation keeps the export rule and records this as a contract boundary candidate rather than editing that evaluator.

The shell's separate `akari-preview/src/common/layer-keyframes-visual.ts` evaluator currently returns only uniform `scale`, whereas the frame-engine evaluator can return `scaleX`/`scaleY`. This fixture's still cut has no width/height inspector controls. If an anisotropic media cut must keep its axis ratio after a keyframe, the smallest shell-only follow-up is to add axis interpolation and static axis fallbacks to that pure evaluator and pass the saved static transform into its cut/layer call sites. Those functions are outside the preview write-path ownership in this task, so they were not modified here.

## r3 AFTER findings and correction

The external AFTER run showed that inspector numeric edits and seek return cases were `ok`, while every preview handle case was `ng`, including the no-keyframe baseline. A direct webview call to `window.akari.engine.overlayWrite()` rejected with `ReferenceError: outputTime is not defined`; `edit.json` did not change. The four write bridge methods in `akari-preview-open-handler.ts` had captured `outputTime` from another embedded script's lexical scope. The bridge no longer sends that undeclared identifier. The host uses `widget.akariPreviewLastKnownTime` for the playhead value. A source-level test checks the embedded bridge and this host fallback.

The preview history command used to compare `JSON.stringify(doc)` against the pre-write document inside `commitEditMutation()`. `performEditMutation()` passes a document through `pinAutomaticBgmDuration()` before invoking that mutation, so a project with automatic BGM duration could fail the comparison despite no competing edit. r3 moved that comparison before BGM pinning. r4 replaced the whole-document candidate check with a latest-document patch mutation, as described below.

The inspector seat formerly set `aria-pressed` from `selectionModel.keyframeSelection`, which represents the selected timeline row rather than whether a point exists under the playhead. Thus an X point could be saved while its button still reported false. Each seat now checks for an explicit value at the item's local frame. The snapshot carries the current output playhead for cut, layer, overlay, and tree items. Selection of another row no longer changes a button's pressed state.

The scale rule is: activating overall scale writes its geometric-mean `scale` and both effective axes at the current point; width and height each have their own explicit point and timeline row. A width or height button reports pressed only when its own axis is explicitly present at the current frame. Pressing a pressed button deletes only that property from the point. The other axes, X/Y, and rotation remain intact. Deleting a point may change the visible result because interpolation or scale fallback is then re-evaluated; this is the normal delete-keyframe rule. A scale-only older point may still make numeric width/height edits keyframed through inherited scale, while their buttons remain unpressed until an explicit axis point is added.

The AFTER runner skips a toggle when that exact property already has a point at the tested frame, while still checking the displayed and saved values. It now journals synchronous and asynchronous webview write rejections and includes those messages, host responses, and the visible error banner when a drag does not persist. The r1 BEFORE run remains unchanged.

## r4 AFTER findings

The wrapper measured 71 `ok` and 25 `ng` cases. Inspector numeric edits passed for both items. The remaining failures separated into a cut gesture overwrite, overlapping pointer capture, a drawing-basis change, and runner observations.

- **A — cut gesture:** `beginMediaTransformDrag()` in `akari-preview-open-handler.ts` applied the drag pose, but `applyCutKeyframesToMedia()` could write the interpolated pose back to the media dataset during the gesture. `finish()` also called `cleanup()` before reading `target.transformNow()`, so the saved patch could contain the original values. The handle path now retains the last computed pose and sends it directly. Cut keyframe evaluation yields while that cut gesture owns the preview; the selection proxy is not re-evaluated until the write response ends the gesture. The frame-engine live summary receives a temporary complete point at the playhead, so its canvas renders the drag pose instead of evaluating the old point over a changed base transform. Keyframe-free cuts retain the existing static live-preview path.
- **B — overlapping writes:** the overlay runtime's `interaction.js` listens for `pointerdown` in document capture and can resolve an HTML overlay at the coordinates of a selected cut. The cut's handler then begins too, producing an unrelated `overlayWrite` and `cutWrite` in one gesture. A window capture handler in the preview temporarily disables overlay interaction for a selected cut hit before document capture, then reenables it after dispatch. The preview host now serializes overlay, batch, layer, and cut item writes through one queue. The annotations command resolves each write command against the latest document *inside* its one history mutation; it no longer compares an earlier whole-document candidate and replaces the document with it. A separate external change is preserved by the latest-document mutation and the guarded snapshot writer, while each successful handle write remains one undo entry.
- **C — still-image size:** the observed `after-062-toggle-before.png` and `after-062-toggle-after.png` differ in size although transform numbers agree: the selection's NW/NE corners move from approximately `(88,6)/(911,385)` to `(320,317)/(524,411)`. The switch begins when `keyframes[]` gains two points. `packages/frame-engine/src/timeline/plan.ts` `hasCutLayerStyleVisual()` then selects `layerStyleVisualAt()` for v2 cuts; `packages/frame-engine/src/compositor/webgl2.ts` `cutLayerStyleBox()` renders the still at its logical source size × crop × scale, whereas a cut without layer-style uses the output fit factor. This is the render/export rule. The shell's `cutHasLayerStyleVisual()` and `applyCutLayerStyleLayout()` make the same source-size switch. The source aspect ratio and output aspect ratio can differ, so a uniform write-side scale cannot preserve both width and height. The owned write path also has no source dimensions at keyframe creation. Keeping the old fit size requires a change outside the owned write path: the smallest shell change is a fit-basis multiplier or independent axis scale in `applyCutLayerStyleLayout()`, `cutSelectBoxGeometry()`, and the cut keyframe evaluator, with a matching decision about export parity. These evaluation/layout functions were not edited.
- **D — HTML move selection:** a paused playback tick called `pushSelectionSnapshot()`, refreshing the whole selection model during pointer interaction. That call is replaced by an inspector snapshot value update, which does not republish the preview selection. The runner also starts HTML moves on a hit-tested content point rather than the center of the selection rectangle, which could land on another visual item.
- **E — measurement:** X/Y toggle expectations use precise preview values instead of rounded inspector text. The still resize already uses the `se` corner handle; its missing write in the prior run is consistent with A/B and remains for external remeasurement. The cut's legacy `#preview-video` data attributes can be stale while the frame-engine selection rectangle and inspector show the current interpolated pose. The runner records this mismatch and judges media seek return by inspector values and the four selection corners. The prior still undo case had identical items before and after its drag, so it measured a missing edit rather than a failed undo; the runner now records that distinction explicitly.
