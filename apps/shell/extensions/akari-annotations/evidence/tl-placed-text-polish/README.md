# 置いた文字の磨き — 実機記録

専用の CDP ポート 9476 で、1280×720、文字「こんにちは」、64px の太字、8px の縁取り、折り返し幅 70% を使った。同じ初期条件の案件を修正前後で用意した。`scripts/observe.mjs <phase> <project>` は実行中のプレビュー、インスペクター、`captions.json` を `results-<phase>.json` と画面 PNG に記録する。

| 項目 | BEFORE | AFTER |
|---|---|---|
| 縁取り | 字の CSS stroke は 16px、外側は 8px。丸い字形の角が尖る | 32 方向の円周シャドウ、半径 8px。プレビューの stroke は 0px。OSR フレームの黒縁は白字から左右と上へ 8px、下へ 7px |
| 位置ボタン | 中央を押すと既定スタイルの `zone` だけが bottom→center。個別 cue は bottom のまま、文字の y=163.175px は不変 | 中央で cue の `position` が (0.15, 0.4298)、下中央で (0.15, 0.7896)。既定スタイルは bottom のまま。下中央から Cmd+Z 1 回で (0.15, 0.4298) |
| 位置の数値 | X/Y の欄なし | X を 15→20% にすると文字の x が 116.935→130.802px。後のドラッグで X 欄も 20→56.06% に追従 |
| 文字のドラッグ | 20px 操作は 19.994px、続く 100px 操作は 100.005px 移動。開始時の飛びはこの条件で未再現 | 100px 操作で 100.003px 移動。開始時の飛びなし |
| 大きさ | 角ハンドルは倍率 1→1.139 へ拡大できた。サイズの + は 64→66→68px と動くが、160px で止まり − は 158px になる | 角ハンドルは 1→1.161→0.921。+ で 320px に到達し、− で 318px |
| 位置セル | 150.336×34px | 22×22px。X/Y 欄はセルの下。下中央のホバーでプレビューにガイドを表示 |
| 幅のダブルクリック | 折り返し幅 70% のまま、文字幅と位置は不変 | 第 1 走は 70→29.22%、枠幅 178.793→74.633px。文字の左端 x=577.261px は不変だが、文字実寸との差が残った。追加修正の最終値は下記 |

位置、サイズ、幅のスクリーンショットと保存値は各 `results-*.json` にある。第 1 走の幅の前後の文字実寸は `after-final-fit-before` と `after-final-fit` の `metrics.ink`。最長行の文字幅 63.855px に既定の左右余白 10.779px が加わり、受け入れ条件の ±2px には届いていなかった。

話した言葉の字幕も確認した。ドラッグ後は対象 cue の位置が (0.4388, 0.93) になり、サイズ + で 50px。置いた文字の保存値は不変。Cmd+Z を 2 回押すと、まずサイズ、次に位置が戻った。
最終ビルドでは話した言葉の Y ツマミを 93→94% に動かし、既定スタイルを `text_anchor: bc`、`position: {x: 0.2946, y: 0.94}` に書いた。置いた文字は不変で、Cmd+Z 1 回で既定の bottom に戻った。

OSR は `results-after-osr.json` で lint と書き出しがともに exit 0。フレームは `after-osr-frame.png`。書き出しの縁取りは、影の値が `none` のとき円周シャドウへ `none` を連結しないことで有効な CSS を保つ。

判断した細部: X は出力幅に対する文字枠の左端%、Y は現在のアンカーに対する高さ%。置いた文字のゾーン操作は cue の位置を書き、話した言葉の既存ゾーン操作はグループの既定位置に書く。背景の無い幅フィットは余白を 0 にする。サイズ上限は 160→320px とした。第 1 走の値は `after-final-*`、OSR は `results-after-osr.json` を参照する。

履歴調査: `6968a0a84` で字幕の 9 ゾーンはインスペクターのグリッドへ移り、自由位置はプレビューのドラッグへ移された。その直前もインスペクターはゾーンの選択欄で、置いた文字の X/Y 数値欄は確認できなかった。別のテロップ用ツマミを加えた `d2f3eb6c6` はこの字幕インスペクターとは別経路だった。

## 追加検証

160px の太字「こんにちは」、黒い縁 12px、折り返し幅 90%、中央配置の同じ案件を、旧コードと修正コードで OSR 書き出しした。旧版の字幕生成器と OSR ページ生成器は一時コピーへ隔離した。`outline-osr-side-by-side.png` は左が BEFORE、右が AFTER。`before-outline-osr.png` / `after-outline-osr.png` は 4 秒の元フレーム、`after-outline-preview-crop.png` は実機プレビューの文字だけを拡大したもの。旧プレビューのビルドは残っていなかったため、プレビューの BEFORE は OSR の旧コードの画像を使う。再現スクリプトは `scripts/render-outline-pair.mjs` と `scripts/outline-compare.mjs`。

同じ字の同じ走査線で、白字の外側へ出た黒を測った（`results-outline-osr.json`）。水平 y=396: 左 11→12px、右 19→20px。垂直 x=285: 上 11→12px、下 12→13px。各差は 1px。右側は字形の斜めの輪郭を横切るため 12px より長い。旧版の黒輪郭は x=1048 まで尖り、新版は x=1045 で収まった。

`results-gesture-matrix.json` は置いた文字の最初の pointermove（右へ 8px）を記録した。各行で `elementFromPoint` の対象は置いた文字 `c-0005` だった。

| 条件 | pointerdown の飛び | 1 回目の pointermove | 期待値との差 |
|---|---:|---:|---:|
| 位置未設定・zone のみで初回に掴む | 0px | 8px | 0px |
| サイズ +（158→160px）の後 | 0px | 8px | 0px |
| 角ハンドルで倍率 1→1.129 の後 | 0px | 8px | 0px |
| 25° 回転の後 | 0px | 8px | 0px |
| 折り返し幅 90%・中央揃え・文字の左寄り | 0px | 8px | 0px |
| 同条件・文字の右寄り | 0px | 8px | 0px |
| サイズ 160px・黒縁 12px | 0px | 8px | 0px |
| プレビューのズーム 150% | 0px | 8px | 0px |
| プレビューのウィンドウ幅を狭める | 0px | 8px | 0px |
| 黒縁あり・話した言葉と重なる位置 | 0px | 8px | 0px |

これらの条件では「左へずれる」は未再現だったため、ドラッグ計算は変更しない。

角ハンドルの 6 条件も次の通り。160px までの全角は `elementFromPoint` で各角自身に当たった。

| 条件 | 角の hit | 倍率 |
|---|---|---:|
| 初期倍率 | 4/4 | 1→1.129 |
| サイズ 160px | 4/4 | 1→1.049 |
| 既存倍率 1.4 | 4/4 | 1.4→1.452 |
| 25° 回転 | 4/4 | 1→1.055 |
| サイズ 160px・黒縁 12px | 4/4 | 1→1.049 |

角の拡縮不能は未再現。幅ハンドルだけは狭い枠で回転ハンドルに覆われることを再現し、操作ボタンを離して幅と角の当たりを優先した。

背景なしの幅フィットは `r2-fit-before-final` / `r2-fit-after-final` に記録した。実マウス相当の東側ハンドル中心は `elementFromPoint` で `e` を指し、ダブルクリックで折り返し幅 70→25%、枠幅 185.418→66.221px、最長行の字形幅 66.221px と一致（差 0px）。字形左端 x=469.890px は不変、縦位置差 0.002px、字形の高さ 19.142px は不変で 1 行のまま。`captions.json` の `background.padding_px: 0`・幅・位置を 1 回で書き、Cmd+Z 1 回で幅 70%・zone bottom・背景フィールドなしへ戻った。背景付きの文字では元の余白を保つ。

## 背景との共存と差分の縮小

`generateResolvedCaptionOverlays` は元の式本体 arrow と object literal のインデントへ戻し、縁取り用の小さなヘルパと `vars` への差し込みだけを残した。`git diff` で、この関数の削除行は縁取り変数を追加する `vars` の 1 行のみ。

背景なしで幅フィットした実機の結果は `results-r3-background.json` と `r3-background-off-workbench.png`。`background.padding_px: 0` があってもインスペクタの「表示」は **off**、プレビューの `backgroundColor` は `rgba(0, 0, 0, 0)`、`--plate-bg` は未設定、左右と上下の pad は 0px。OSR の `r3-background-off-osr.png` も背景色の矩形は無く、背景画素 (39,48,64) と旧枠内の画素 (39,48,64) が一致した。

同じ幅ハンドルをもう一度ダブルクリックしても、幅・字形 x・一行の高さ・背景の off 状態はすべて不変。続いてインスペクタで「表示」を on にすると checkbox は **on**、プレビューの背景色は `rgba(0, 0, 0, 0.6)`、字形の高さは 20.041px のまま。余白欄は 0px のため座布団は字形にぴったり重なり、外側へは張り出さない。`r3-background-toggle-side-by-side.png` は左が off、右が on。非ゼロの余白 8px を直接試した場合は字形の高さが 20.041→39.730px になって二行へ折れたので、幅を固定したまま余白を自動で足す変更は採用しなかった。背景色・余白はインスペクタで引き続き調整できる。

## detached 字幕の一致と最終検証

一致テストの旧入力は、detached 側が `time_domain: output` に射影する一方、共有生成器側は元の cue を source 域のまま渡していた。テストの共有側も output 域で呼び、HTML と vars のバイト一致を維持したうえで、丸い縁取り CSS と半径 2px の影変数を追加検査した。生成器の挙動は変えていない。

置いた文字「こんにちは」を 160px の太字・黒縁 12px で、字幕バッグから除外して detached 行へ配置し、OSR で 1280×720・360 フレームを書き出した（exit 0）。最初の案件外への `--out` 指定は出力先の保護チェックで exit 2 になったため、案件内の `exports/` へ直して通した。4 秒の `r4-detached-osr-frame.png` から文字を切り抜いた `r4-detached-osr-crop.png` は、同条件の通常経路 `after-outline-osr.png` の同じ 900×330 領域と **画素差 0**。縁取りの外半径は 12px、丸い角を維持した。数値は `results-r4-detached-osr.json` に記録した。

render-cut 全件は 752 件中 747 件通過・5 件失敗（exit 1）。この 5 件は変更前コードを隔離した一時コピーで対象テストを実行した結果と同じだった（変更前は 18 件中 13 件通過・5 件失敗）。失敗は `audio-sfx-in-out` の GPU stderr、`layer-audio` の同梱 ffmpeg 不在、`glass-runtime`・`rotate-scale-order`・`vgpu-sheet` の既存ハッシュ基準。detached のバイト一致テストを含む、その他 747 件は通過した。preview は 1,984 件中 1,983 件通過・1 件スキップ、annotations は 3,044 件すべて通過。`npm run build`、`npm run lint`、frame-engine と preview の bundle drift 検査はいずれも exit 0（lint は既存警告 6 件）。
