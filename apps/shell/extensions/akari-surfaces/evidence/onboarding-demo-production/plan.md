## コンセプト

話し手が「いまからやって見せます」のつもりで言った語の、**その語頭のフレームで機能が本当に起きる** 37.6 秒。

- 語の時刻を声の波形（10 ms 包絡）と口の開閉で取り直した。**元のトークンは最大 1.46 秒早かった**（「今日は」0.89 → 2.35）。字幕 22 行のうち 13 行が 0.3 秒以上早く出ていた（最大 1.46 秒）。これが「字幕に全然合っていない」の根本原因
- 右 45% の舞台に見せ場を **1 つずつ**出す。タイトル → AI との対話 → 編集完了の判子 → **「パッ」** → 「こういう」図解 → スマホの中にこの動画 → 「BGM も」で音楽が持ち上がる → カラオケ字幕 → 「編集 AI」のクレジットに「チーン」
- 派手さは 19.70 秒の「パッ」の一点に集める（閃光・1.06 倍のズーム・擬音「パッ！」・放射線・whoosh の山が同じフレームに着地し、BGM の拍もそこに来る）。ほかは品よく

## 組み込み（codex 担当）

- 頼む文: 「この動画を編集したいです。話している内容に合わせて、テロップ・図解・効果音・BGM を入れてください。」
- 作業ログ: 約 17 秒。本編 → 字幕 → タイトル → テロップ → 効果音 → 図解 → スマホ → BGM → カラオケ → オチ → edit-lint の順に増える（`plan.json` の `wiring.log`）。各段でプレビューをその見せ場の秒へ（4.2 / 13.5 / 20.25 / 24.9 / 28.6 / 30.1 / 31.9 / 36.9）
- 段階: `writeExample(..., progress?: { stage: 0〜8 })`。ツアーの 5 引数呼び出し = stage 8
- model.ts は変えない。字幕タイトル行を捨てる・runs・カラオケの 2 行は onboarding-service.ts の後加工
- 旧 overlays（automatic / dialogue / effects / diagram / finishing）は消し、新しい名前は `demo-*`（旧版の写しが残ったプロジェクトで古い図解が出続けないように）
- 既存ユーザーの library の transcript.json は旧版（sha256 `b384cae6…`）のときだけ上書き

## 並走レーン（字幕・台本の段）への連絡

## 危うい所

- スマホの画面（2 本目の映像段の crop / transform）がプレビューで書き出しと同じ位置に来ない → 28.5 秒で両経路を比べ、合わなければ静止画の代替
