AKARI Video の状態を確認し、利用者に次の一手を案内する。内部の仕組み（JSON・git・
スキーマ名）ではなく、利用者の言葉（素材・企画・書き出し・やること・尺・おまかせ度）で話す。
応答はユーザーの使用言語に合わせる（英語で話しかけられたら英語で案内する）。

手順:

1. カレントディレクトリに `.akari/` があるか確認する（`ls -la .akari` または同等の方法）。
   - **無ければ**: このフォルダーはまだ AKARI Video プロジェクトとしてセットアップされて
     いないと伝える。新しいプロジェクトを作る前に、後述「作業場（CreatorRoot）の検出・
     作成・案内」節の手順で作業場の有無を確認し、その節の「導線」に従って案内する。
   - **あれば**: 次のステップへ進む。

2. `.akari/connections.json` があれば、`manage-connections` スキルの実行順リーフに従って
   doctor（`node <スキルのディレクトリ>/bin/doctor.mjs` をプロジェクトルートで実行）を
   実行し、接続状態を要約する。**キーの値・HTTP 応答本文は絶対に表示しない**
   （`manage-connections` の FORBIDDEN 級ハードルールを継承する）。

3. `.akari/intake.json` を読み、`status` を確認する。
   - `draft` なら: 進め方（やること・尺・おまかせ度）がまだ未確定だと伝え、intake フォーム
     を開くか、対話でヒアリングして確定させることを提案する。
   - `submitted` なら: `tasks`（スキルカタログ対応の安定 ID。表示は日本語ラベルに変換して
     伝える — 例 `transcribe-captions` → 「文字起こし・テロップ」）・`target`・`autonomy`
     を要約し、その内容で作業を続けてよいか確認する。`autonomy` が `checkpoint`（既定）なら
     企画承認・書き出し前などの要所で必ず人に確認することも伝える。

4. `.akari/events/` に記録があれば、直近のイベント種別に応じた次の一手を一言添える
   （例: `report-generated` ならレポートの承認を促す、`report-approved` なら編集を進める、
   `edit-completed` なら仕上がり確認と telop 調整を促す、`export-completed` なら書き出し
   結果の確認を促す、`video-added` なら分析開始を促す）。記録が無ければ「まだ節目の記録は
   ありません」と伝える。

5. 最後に、次に何をすればよいかを 1〜2 文で明確に伝える。長い説明は避け、次の一手を
   はっきり示すことを優先する。

## 作業場（CreatorRoot）の検出・作成・案内

「新しいプロジェクトを作りたい」「作業場を作って」と言われたとき、または上記手順 1 で
プロジェクト未セットアップと判定したときにこの節を使う。**作業場**は利用者 1 人の
プロジェクト・素材・設定をまとめる置き場（既定 `~/AkariVideo/`）。用語・構造の正本は
公開契約 `docs/contract-2026-08-02-creator-root-v1.md`（以下「公開契約」）§3。

### 検出

次の 2 経路のどちらかで既存の作業場を探す（どちらか一方でも見つかれば作業場ありと判定）。

1. `<AKARI_HOME>/creator-root.json`（`AKARI_HOME` 環境変数、無ければ既定 `~/.akari`）を
   読み、`lastRoot` が指すパスが実在するか確認する
2. カレントディレクトリから祖先方向へ `.akari/root.json` を探し、見つかれば読んで
   `schema` が `"creator-root/v1"` であることを確認する

見つかった場合は「見つかった場合」へ、見つからなかった場合は「見つからない場合」へ進む。
どちらのファイルも**壊れている**（JSON が壊れている・`schema` が未知）場合は、上書き
せず利用者にそのまま報告する（読み取り拒否が正しい挙動 — 公開契約 §3 の前方互換方針）。

### 見つかった場合

新しいプロジェクトの作成先は `<作業場>/channels/<channel>/videos/<日付-スラッグ>/`
とする（`<channel>` は `root.json` の `channels` の先頭。無ければ既定チャンネル
`my-channel`。`<日付-スラッグ>` は例 `2026-08-02-my-video` のような日付始まりの
短い識別子）。作業場の場所を利用者へ 1 行で伝えたうえで、下記「導線」に進む。

### 見つからない場合 — 勝手に作らない

作業場が無いことを検出しても、**利用者の同意なしに作成しない**（提案 → 同意 → 作成の順。
承認ゲートの流儀。他のスキルの「黙って作らない」規律と同じ）。「作業場（既定
`~/AkariVideo/`。変更したい場合は場所を聞く）を作ってよいか」を尋ね、同意が得られてから
次を実行する。

- **作成（第一手段）**: `akari init` を実行する（引数なし。既存の作業場があれば何も
  作らずそのパスを stdout 1 行目に返す ensure 動作・冪等）。`akari` が PATH に無ければ
  リポ内 `packages/akari-launcher/bin/akari.mjs init` を直接実行する
  （例: `node <リポの絶対パス>/packages/akari-launcher/bin/akari.mjs init`）。
  この経路はマシンポインタ（`<AKARI_HOME>/creator-root.json`）の更新も内部で行うため、
  以後は検出の経路 1 でも見つかるようになる。

- **作成（フォールバック）**: `akari` コマンドも上記スクリプトの直接実行もできない環境
  でのみ、公開契約 §3 の正準構造を手で生成してよい。生成先は利用者に確認した作業場の
  パス（既定 `~/AkariVideo/`）。

  ```
  <作業場>/                          # 例: ~/AkariVideo/
  ├── akari.md                       # 憲法スタブ（下記の文面。新規作成のみ）
  ├── channels/<channel>/videos/     # <channel> は既定 my-channel
  ├── library/
  ├── inbox/
  └── .akari/
      ├── root.json                  # {"schema":"creator-root/v1","createdAt":<ISO8601>,"channels":[<channel>]}
      ├── memory/
      └── cache/
  ```

  `akari.md` スタブの文面（新規作成時のみ・既存があれば触らない）:

  ```markdown
  # akari.md

  この作業場（CreatorRoot）の規約・好みを書く場所です。
  AKARI Video のエージェントは動画を作る前に、まずこのファイルを読みます。

  ## 好み

  （まだ何も書かれていません）
  ```

  手動生成では次の 2 規律を必ず守る:
  1. **既存ファイルを一切上書きしない**（ディレクトリ作成は既存でも安全だが、ファイルは
     既に存在すれば書かない。`root.json` や `akari.md` が既にあるなら、それは既存の
     作業場なので上書きせず「検出」に戻ってそのまま使う）
  2. **`root.json` は最後に書く**（`channels/…/videos/`・`library/`・`inbox/`・
     `.akari/memory/`・`.akari/cache/`・`akari.md` を先に作り終えてから、「このフォルダは
     有効な作業場である」ことを示す `root.json` を最後に書く。`root.json` の存在そのものが
     作業場判定のマーカーなので、途中状態で先に作ると壊れた作業場を「完成」と誤認させる）

  フォールバックはマシンポインタを更新しない（`<AKARI_HOME>/creator-root.json` は
  書かない）。以後の検出は検出の経路 2（cwd 祖先探索）に頼ることになる — 作業場の
  外から始めるセッションでは経路 1 が使えないため、可能な限り `akari init` を優先する。

作成後は「見つかった場合」と同じ手順（`<作業場>/channels/<channel>/videos/<日付-スラッグ>/`
を作成先にする）に進む。

### 導線（見つかった場合・見つからない場合 共通）

- ターミナルで `akari` コマンド（ランチャー）を実行すれば、作業場の確認・作成 →
  プロジェクト作成 → このセッションと同じ入口に到達できる
- このセッションのままなら `create-project` スキルの作成先（`<target-dir>`）に
  `<作業場>/channels/<channel>/videos/<日付-スラッグ>/` を渡して雛形を作成できる
  （リポ checkout なら `skills/create-project/SKILL.md`、プロジェクト内なら
  `.claude/skills/create-project/SKILL.md` を参照。**アプリ単体ユーザー**でこのプラグインを
  `claude plugin install` 経由で導入した場合、シンボリックリンク越しのスキル正本参照は
  届かないことがある — その場合は上記いずれのパスも見つからない旨を伝え、`akari` CLI 経路
  （ターミナル実行）を優先して案内する）
- どちらを選ぶか、または何を作りたいか（素材から / テンプレから / 過去プロジェクトを
  参考に / 相談しながら）を尋ねる
